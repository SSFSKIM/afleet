# 15–17 · File tools, Bash tool, Sandbox — TUI-vs-headless gap inventory

Scope: SPEC [15 file-tools], [16 bash-tool], [17 sandbox], read completely. Cross-refs used:
SPEC 45.9.1/45.9.2/45.12.2/45.14.8/45.15.2 (wire frames), 41.16.5–41.16.8 (per-tool render
forms), 12 §"Additional messages appended after the tool_result", 11.8.2 (attachment
catalogue), 14.4.7 (`stripForStorage`/`stripForCreation` timing). Live evidence:
`/tmp/afleet-gap/init-dump.json` (2.1.259 initialize handshake).

**The single most important finding for this area** is stated once here and then referenced.
The headless `user` frame carries `tool_use_result`, and SPEC 45.12.2 says it "carries the
tool's **full Output object**, not the string sent to the model"
[`chunk-1kg58a1a.js:92982`, `chunk-sct99ax9.js:673390`]. The stripping hooks that blank
`Read.file.content`, `Edit.originalFile` and `Write.originalFile` are `stripForStorage`, and
`stripForStorage` only runs at message-creation time when the tool also sets
`stripToolUseResultAtCreation` (SPEC 14.4.7, `chunk-1kg58a1a.js:114917-114921`). Only the
`Artifact` family sets that flag (`chunk-j5tremg8.js:558937`); no file tool does. `Read` sets
`stripForCreation`, which removes **only** the `pages` key from a `"parts"` (PDF page) result
(SPEC 15.4.3, `chunk-1kg58a1a.js:125755-125760`). Therefore the full structured render data
for `Read`, `Edit`, `Write`, `NotebookEdit`, `Glob` and `Grep` — `structuredPatch`,
`oldString`/`newString`, `originalFile`, file content with `startLine`/`numLines`/
`totalLines`, image/PDF base64, notebook `cells`, `filenames`, Grep `mode`/`content`/
`numMatches` — is on the wire. A GUI has strictly more data than the TUI collapsed view; it
only has to write the renderers.

## Top gaps in this area

Ranked by how much they cost afleet's "equal to or better than the TUI" goal.

1. **Live Bash output streaming is not on the wire at all** (16.2). The TUI shows the last five lines refreshing every second with an elapsed timer; headless gets nothing, because `tool_progress` is dropped by filter `Cu` and, even when unlocked by `CLAUDE_CODE_REMOTE`, its published schema has no output field (SPEC 45.14.8). Class **D**. Partial workarounds: `CLAUDE_CODE_REMOTE=1` for elapsed time and `task_id`; tail the deterministic `<tmp>/claude-<uid>/<slug>/<session>/tasks/<taskId>.output` path once the task id is known. This is the strongest candidate for a protocol addition (add `output`/`total_lines` to `tool_progress`, or emit it for local sessions).
2. **No way to move a running foreground command to the background** (16.2). The TUI's `ctrl+b` has no control-request equivalent among the 66 requests; the wire *reports* the outcome (`backgroundedByUser`) but offers no cause. Class **D**. Second protocol-addition candidate.
3. **File checkpointing is off by default in headless** (15.4). `pT()` requires `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING` when `Oe()` (non-interactive) is true. Unless afleet sets it at spawn, `/rewind`-equivalent restore is dead and `rewind_files` answers `File rewinding is not enabled.` Class **R** — a one-line fix, but silent if missed.
4. **The effective sandbox policy is invisible** (17.1, 17.3). The `/sandbox` Config tab and the model-facing `sandbox_instructions` attachment both render the post-derivation filesystem/network lists; the attachment is dropped by `Cu` and nothing else carries them. Class **D**. `claude sandbox status` gives posture (`enabled`, `strictMode`, `filesystemPolicy`, `reasons[]`) but not the path or domain lists.
5. **Sandbox settings the user most wants to change are unwritable through the protocol** (17.5). `update_settings` writes `localSettings` only, and the eleven `ao` keys plus the `/sandbox` Mode/Overrides tabs' natural destination (user settings) are ignored from that tier. Class **D**; workaround is to edit `~/.claude/settings.json` on disk, which means afleet's settings UI bypasses the CLI it is hosting.
6. **`/sandbox`, `/diff` and `/rewind` are all unreachable as commands** (15.4, 17.1). Confirmed live: none of the three appears in the 2.1.259 `initialize.commands` list of 102. Class **X** for the panels, **R** for their data (`get_workspace_diff`, `rewind_files`, `get_settings`, `claude sandbox status`).
7. **The externally-changed-file reminder is dropped** (15.2). When a formatter or another process rewrites a file Claude had read, the model is told with a diff snippet; the host is not. Class **D** — the GUI's file view can silently disagree with what Claude believes. Workaround: watch the filesystem, or diff via `read_file`.
8. **"Which command ran sandboxed" is not on the wire** (17.6). Reproducing the `SandboxedBash` indicator requires reimplementing `rb()` and `excludedCommands` matching. Class **D**, cosmetic but visible.
9. **Persisted-output is a clear GUI win, not a gap** (16.3). `persistedOutputPath` + `persistedOutputSize` are structured wire fields and the file is a plain readable `.txt`. afleet should offer "open full output" — the TUI cannot. Class **P**; listed here because it should be built deliberately.
10. **Image, PDF-page and notebook-cell bytes are all on the wire** (15.3). The TUI shows `Read image (240KB)`; afleet can show the image, the rendered PDF pages and a real notebook view. Class **P**; the second deliberate win.
11. **`<sandbox_violations>` is stripped by the TUI but present on the wire** (17.3). afleet can render "blocked: network → api.example.com (host is not on the allow list)" with a one-click "allow this domain" that writes the `WebFetch(domain:…)` rule. Class **P**; the third deliberate win.
12. **The network-access prompt is `can_use_tool`, not a dialog kind** (17.4), with `permission_suggestions` already carrying the exact persist rule. Class **P** — no work beyond special-casing the pseudo-tool name `SandboxNetworkAccess`, which is never in `system/init.tools`.
13. **`bash_command` loses persistent shell state and transcript integration** (16.6). The schema says so in its own `.describe()`. A terminal pane built on `bash_command` cannot do `cd`/`export` across calls, and its output never reaches the model. Class **D** for persistence; afleet needs its own PTY if it wants a real terminal.
14. **The "needs a TTY" surface is narrower than expected** (16.5). The only one is the background stall watchdog's task notification (45 s without growth + one of seven prompt regexes), which *is* on the wire as `system/task_notification`. Foreground interactive commands just get `< /dev/null` and fail. Class **P** for what exists; noting the absence so afleet does not look for more.
15. **Startup sandbox warnings arrive on stderr, not as frames** (17.2), except the `failIfUnavailable` hard stop, which is a `result` message. Class **R** — afleet must capture stderr, which it may not currently do.
