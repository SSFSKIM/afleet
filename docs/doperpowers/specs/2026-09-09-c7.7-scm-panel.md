## Purpose

The Source Control tab is where the user reads the repository the channel is pointed at without
leaving the channel: the history as a graph, what a commit changed, what the working tree has that
`HEAD` does not, and — one tab over — what GitHub says about the branch. It is a **reader**. Root
spec §9.2 puts staging, committing and branch operations out of scope by the parent's decision,
and that is not a v1 cut to be revisited here: everything this panel offers is a read of the
user's own `git` and the user's own `gh`, run through the environment X11 captured.

It is also the leaf that closes C7. Three merged leaves left work pointed here and no other:
`SourceControlCore` has had no consumer since it landed — every one of its rendering-facing
subtleties (a `truncated` edge that continues, several edges arriving in one lane, a windowed
history with no paging above it) is documented on the type and unexercised by any drawing;
C7.5's `.diff` target has been driven only by C7.5's own tests; C7.6's `.pullRequest` target has
had no in-app emitter. This leaf is the first caller of all three, and the C7 recomposition check
runs after it.

**No panel imports another panel.** A diff is shown by emitting a `.diff` `WorkspaceLink` that
the Files tab's target opens (ruled 2026-09-09 at C7.5's merge); a pull request is opened by
emitting a `.pullRequest` link that the Browser's target resolves. This leaf registers exactly one
target of its own — `.commit`, W5's binding row — and imports neither `FilesPanel` nor
`BrowserPanel`.

## Acceptance

### G1 — item 27, in the built app (required)

Root spec item 27: *a repository with a merge commit shows at least two lanes; a commit lists its
files; a file shows a diff; editing a file updates the working-tree row* — plus the composite's
addition, **within one second of the edit**.

**Headless half.** `swift test --package-path Workbench` proves, over repositories the tests build
with the machine's own `git` under temporary directories:

1. **Lanes.** For a repository with a merge commit, the rendered rows — read from the panel's own
   readout, not from `LaneAssignment` directly — occupy at least two distinct lanes, and the test
   names *which* commits sit in which lane rather than asserting that some lane count exceeds one.
   An octopus merge and a detached tag are in the same corpus, because C7.3's lane tests are, and
   a panel that dropped a row would still satisfy a count.
2. **The rendering contract.** For each row, the drawing instructions the graph column produces are
   asserted as values: every edge of row *i* has a segment, an edge whose `truncated` flag is set
   is drawn to the row's own edge and repeats on the row below, and two edges arriving in one
   `toLane` both appear. This is the discriminating test of the whole graph — a renderer that
   indexed edges by destination lane, or stopped a truncated line, passes a lane-count assertion
   and fails this (tracker 119, 121).
3. **A commit lists its files.** Selecting a commit produces exactly one `GitDiff.changes` read at
   `.commitAgainstParent(hash)` and a file list whose paths, statuses and binary flags are the ones
   git reported — asserted by content, over a corpus carrying a modification, an add, a delete, a
   rename, a binary file and a submodule gitlink. A root commit lists its whole tree as added.
4. **A file shows a diff.** Clicking a file in a commit's list emits exactly
   `.diff(DiffRef(repository: root, path: p, base: .commitAgainstParent(hash)))` through the
   context's `LinkRouterCapability`, and clicking one in the working-tree list emits the same with
   `.workingTreeAgainstHEAD`. The assertion is on the link emitted, because that link *is* this
   leaf's whole diff behaviour under C7.5's ruling; that the link then renders a pair is C7.5's own
   G3, already met. A test drives the emission through a **real** `LinkRouter` with a recording
   target registered for `.diff`, so a link that never reached a registry fails.
5. **The working-tree row, within one second.** Over a real repository: the panel is watching, a
   file is written, and the row-zero state changes from clean to dirty within a bounded,
   delivery-fulfilled wait whose bound is one second. The same for the reverse (the edit reverted).
   The bound is the gate's own number and the wait is fulfilled by the change, never by a sleep.
   A test that removes the watcher's re-arm, or the `.git` classification of §5, turns it red; both
   mutations are named in the plan.

**Human leg.** The graph drawn on screen with its lanes, dots, ref badges and dates; the commit
detail beside it; the click that opens the diff in Monaco; and a real `claude` edit making the
working-tree row appear while the user watches.

### G2 — item 28, in the built app (required)

Root spec item 28: *a repository with an open PR lists it with check status; opening it loads the
PR in the Browser tab.*

**Headless half.**

1. Over a recording runner replaying authored `gh --json` documents (real field names, invented
   values, §11): the GitHub tab lists the branch's pull requests with number, title, author, draft

   mixture with a pending is pending, all passing is passing, no checks is *no checks* and not

2. `gh pr checks` exiting **8** with checks printed is a normal answer and the rows are shown
   (C7.3's contract; tracker 118's live half below).
3. Opening a pull request emits exactly `.pullRequest(number)` through the context's
   `LinkRouterCapability` and nothing else — no URL is built here, no remote is parsed, and the
   Browser's resolver is the only thing that turns a number into a page (C7.6, W5). Driven through
   a real `LinkRouter` with a recording `.pullRequest` target.
4. The issue list decodes and renders `number`, `title`, `author`, `labels` and `updatedAt`.

**Live leg, conditional.** With `gh` logged in on the machine, one run against a real repository
proves the three verbs return documents this leaf decodes. It is **conditional on `gh` being
logged in and skips with a named reason otherwise**, and it never prompts for a login. Tracker 118
(no live confirmation of exit 8) is closed only if a repository with a check in flight is reached;
if none is, it stays open and is said so.

**Human leg.** The PR row on screen with its check status, and the click that loads the PR page in
the Browser tab.

### G3 — the `.commit` target, and `gh` absent or logged out (required)

**A `.commit` link selects that commit.**

*Headless half.* A `.commit(hash)` link routed through a real `LinkRouter` with this leaf's target
registered reaches the panel with the link intact and the destination it was opened from, selects
that commit, and loads its detail. Three cases, each its own test: the hash is in the loaded
window; the hash is outside it and is found by paging with `GitLog.commits(skip:)`; the hash is in
no page within the bound and the panel shows a named row rather than selecting nothing silently.
An abbreviated hash — what a timeline row is most likely to carry — resolves by prefix, and an
ambiguous prefix is a named row and not an arbitrary pick. With the session released the target is
inert and the router takes W5's fallback rather than resurrecting it.

**`gh` absent or logged out shows the panel-local empty state with the `gh auth login` hint and
runs no auth flow.**

*Headless half.* Three tests. With a runner that answers `binaryNotFound(.gh)`, the GitHub tab
renders the empty state naming the absence, with an *install* hint and no `gh auth login` hint —
a panel that offered the same remedy for every failure would send the user to re-authenticate over
a missing binary. With a runner that answers a non-zero exit whose stderr tail is a
not-authenticated message, the tab renders the empty state **with** the `gh auth login` hint.
And, structurally: every `gh` argument vector this leaf can ever produce is captured by a recording
runner across the whole suite and asserted to be one of `pr list`, `pr checks`, `issue list` —
the verb `auth` is unrepresentable, not merely unused. Neither error row ever carries a byte the
tool printed (§6.3, §11): stderr is read to *classify* and never to quote.

### G4 — no staging, commit or branch action exists in the UI (required, §9.2 binding)

*Headless half.* Two proofs, because one is not enough. First, the same argument-vector capture as
G3, extended to `git`: every `git` argv this leaf produces across the whole suite is asserted to
be one of C7.3's read verbs (`rev-parse`, `log`, `status`, `diff`, `show`, `cat-file`) — `add`,
`commit`, `checkout`, `switch`, `branch`, `restore`, `stash`, `reset`, `push` are unrepresentable.
Second, the panel's readout — the value type the views draw from — carries the complete action set
of every surface it renders, and a test asserts that set against a written-out list. An action
added to a view and not to the readout fails the readout tests it was added to; an action added to
both fails this one. §9.2 is binding, so the assertion is on the *inventory* and not on a sample.

## Design

Everything the composite, W7 and X7 fix is carried whole. This section is the residue, each item
with the reasoning that settles it. The Decision Log below carries the alternatives.

### 1. The shape: one repository reader, two tabs, views that only draw

Five objects, and only the last is SwiftUI.

- `RepositoryReader` — every read this leaf makes, as `async` functions over `any ToolRunning` and
  a `ResolvedEnvironment`: the root, the commit window, the status, a commit's changed files, the
  working tree's changed files. It writes no command line; each function is one call into
  `GitCommands`, `GitLog`, `WorkingTreeStatus` or `GitDiff`. Its whole job is to be the seam a test
  drives with a recording runner and the place W7's "no second git reader" is visibly true.
- `RepositoryWatch` — the working tree's freshness (§5): an FSEvents stream on the repository root,
  a classification of what changed, and the debounce. Its policy is a pure function with no file
  system in it, so the table of "what does this path mean" is testable as a table.
- `SourceControlModel` — the `PanelTabSession` X7 retains for (`.sourceControl`, channel): the
  loaded window, the lane assignment, the selection, the commit detail, the working-tree detail,
  the panel-local error state, and the `.commit` target's delivery. Main-actor and observable.
- `GitHubModel` — the `PanelTabSession` for (`.github`, channel): the branch, the pull requests,
  their checks, the issues, the panel-local empty and error states.
- The views — `SourceControlPanelView`, `GitHubPanelView` and the graph column's `Canvas` — which
  draw a **readout** and hold nothing. `SourceControlReadout` and `GitHubReadout` are value types
  carrying exactly what a surface shows and every action it offers, in C5's `PlaceholderReadout`
  shape and C7.5's `FilesPanelReadout` shape. G4's second proof and G1's rendering assertions are
  both assertions on a readout, which is what makes them assertions on what the user sees rather
  than on what a model happens to hold.

### 2. Two tabs, two sessions, no shared state between them

X7's tab id set is closed at seven and names `.sourceControl` and `.github` separately, so this
leaf registers two `PanelTab`s. The host retains one session per (tab, channel), and there is no
seam by which two tabs could share one — nor should there be: the two answer different questions
against different tools with different failure modes, and the only thing they have in common is the
repository root, which is one `rev-parse` each and cheap.

So: **no shared model, no cross-tab state, and nothing this leaf writes is read by another leaf's
view.** What it does write is a `WorkspaceLink` — `.diff` and `.pullRequest` — which is a message
and not state.

### 3. What the graph shows, and what it reads to show it

One read cycle produces the whole tab:

1. `GitCommands.repositoryRoot(cwd:)` — `.notARepository` is the empty state, not an error row.
2. `WorkingTreeStatus.read(root:)` — gives `headOID`, `branch`, `upstream`, `ahead`/`behind`, and
   `isClean`, which is `workingTreeIsDirty`.
3. `GitLog.commits(root:limit: 2000, skip: 0)` — W7's window.
4. `LaneAssignment.assign(commits:headOID:workingTreeIsDirty:)`.

Row zero is the working tree when and only when the tree is dirty, which is C7.3's rule and not
this leaf's to soften. Each commit row draws its lane dot, its ref badges, an abbreviated hash, the
author name, a relative date and the subject. Ref badges distinguish `.head`, `.branch`,
`.remoteBranch(remote:)` and `.tag` — the distinction `--decorate=full` was amended into W7 to
buy, and the first place it becomes visible (tracker 115's closing note).

The two reads at steps 2 and 3 are issued together and joined; a failure of either is one
panel-local row (§10) naming which tool failed and its exit code, never its output.

### 4. The rendering contract the graph column and `GraphRow` share

C7.3 documented three properties of its edge model and asked, twice in the tracker (119, 121), for
"a rendering contract the panel and this type share". This is that contract, stated here and
asserted by G1.2:

- **A row draws two half-edges.** Row *i*'s canvas draws the *lower* half of every edge in
  `rows[i].edges` — from `fromLane` at the row's vertical centre to `toLane` at the row's bottom
  edge — and the *upper* half of every edge in `rows[i-1].edges`, from `toLane` at the row's top
  edge to `toLane` at the row's centre. Every edge is therefore drawn by exactly two adjacent rows
  and by no other, which is what lets the graph live in a lazy list: a row is drawable from itself
  and its predecessor, and nothing needs the whole assignment to draw a viewport.
- **Edges are drawn as a sequence, never keyed by lane.** `rows[i].edges` may hold two edges
  arriving in one `toLane` and both are drawn (tracker 121). The column iterates; it never builds a
  dictionary keyed by `toLane` or by `fromLane`.
- **`truncated` means the line continues, not that it ends** (tracker 119). A truncated edge is
  drawn to the row's bottom edge exactly like any other; the difference is that its lane stays
  occupied and the same edge reappears on every row below, which the assignment already emits. The
  column adds no terminator glyph. The only visual difference this leaf draws is at the *bottom
  row of the whole window*, where every edge — truncated or not — runs off the end, because there
  is no row below to receive it.

The contract closes the rendering half of 119 and 121; the naming half of 119 stays open and is
noted as such.

### 5. Freshness: one second, and what an FSEvents stream must ignore

G1's clause is the only timing number in this leaf, and it is a bound on *the working-tree row*,
not on the graph. Polling `git status` every second on a large repository is a process per second
per open channel and was rejected; the answer is an `FSEventStreamCreate` on the repository root
with a latency below the bound and a debounce above it, and a classification of the paths it
delivers:

- A path **outside** `.git` → the working tree may have changed: re-read `WorkingTreeStatus`.
- A path **under `.git`** that is `HEAD`, `packed-refs`, or under `refs/` or `logs/` → history may
  have changed: re-read the window, the status and the assignment.
- Every other path under `.git` → **ignored**. This is the load-bearing exclusion and the reason
  the classification exists at all: `git status` writes `.git/index` when it refreshes stat
  information, so a watcher that treated any `.git` write as a change would re-read the status
  because it had just read the status, for ever. The exclusion is a pure function over a path and
  is tested as a table, one row per class, because a classifier that answered "refresh" for
  everything passes any test that only checks the working-tree row.

The stream is created with `kFSEventStreamCreateFlagFileEvents | ...NoDefer | ...WatchRoot`,
scheduled on a private queue, and delivers into the model on the main actor. `NoDefer` is what
makes the *first* event of a burst arrive at once rather than after the latency, which is what the
one-second bound is bought with; the debounce that follows coalesces the rest. A repository root
that disappears (the directory deleted or replaced) is `WatchRoot`'s own event and becomes the
`.notARepository` empty state rather than a stalled panel.

Nothing about the graph is polled: history changes only through `.git`, and `.git` is watched.

**A status-only read is not a peer of a full cycle** (ruled 2026-09-09 at T5's review). The two
reads write different things: a `.workingTree` delivery re-reads the status alone, while a cycle
re-reads the window, the status and the assignment. Given one generation counter the cheap read
wins by starting later — it supersedes an in-flight history read, then re-assigns lanes over the
*old* window, and the commit the user pressed *Refresh* to see never appears with nothing on
screen saying the refresh was discarded. So supersession is claimed **per field group**: whoever
will write the window claims the window's epoch, whoever will write the status claims the
status's, and a read publishes only the groups it claimed. A partial write can no longer
invalidate a document that holds strictly more than it does. Every terminal path of every read —
published, superseded, cancelled, failed — leaves through one function that clears the loading
flags, because a flag cleared on the success path alone latches on the path that skips it, and a
latched loading flag here also disables the tab's first read for the rest of the session.

**`.rootGone` is recoverable** (ruled the same day). The root disappearing is the
`.notARepository` empty state and the watch is torn down — a repository deleted or moved is the
same thing to look at as a channel that was never in one, and a stream left armed on an inode
nobody will write again would show a stale repository for ever. But the state must not latch: a
`mv`, a `git worktree` churn or a checkout that replaces the directory reaches it routinely, so
the panel clears its "has read" flag, re-reads on the next activation, and the empty state carries
the one action that recovers it. An empty state with no way out is a panel that has to be
restarted.

### 6. Commit detail, and the diff that is a link

Selecting a commit reads `GitDiff.changes(root:base: .commitAgainstParent(hash))` — one
invocation, C7.3's mapping to `git show --first-parent --root …`, which is already correct for a
merge (the first-parent question a panel asks) and for a root commit. The detail shows the full
hash, the author, the date, the subject and body's first line as the subject C7.3 parsed, the
parent hashes as selectable rows, and the changed files with status, kind and +/− counts.

Clicking a changed file emits
`.diff(DiffRef(repository: root, path: change.path, base: .commitAgainstParent(hash)))` through
`context.links.open(_:from:)`. Nothing else happens: the Files target opens the pair, brings the
Files tab forward for a `.currentPanel` delivery, and pops out for a `.newWindow` one. Cmd-click
maps to `.newWindow` per §9.4 and this leaf takes X7's default (`popsOutForNewWindow: true`) for
its own target — the Browser's declination is about leaving the app, which nothing here does.

Two file kinds are **not** offered as diffs, and the row says why rather than emitting a link that
resolves to nothing: a `FileChange` whose `kind` is `.gitlink` (a submodule's two sides are a
commit object and a directory, neither blob-readable — C7.3's `Kind` exists for this), and one
whose `isBinary` is true (git counted no lines because there are none). A rename's link carries the
**new** path, which is `FileChange.path`, and C7.5's resolver reads the old side at the old path;
that is C7.5's G3 and is already proved there.

The working tree's detail is the same surface over
`GitDiff.changes(root:base: .workingTreeAgainstHEAD)`, and its rows emit `.diff` with
`.workingTreeAgainstHEAD`. `WorkingTreeStatus.entries` is *not* the file list: it is the row-zero
signal (`isClean`) and the branch/ahead/behind header. The two answer different questions —
porcelain v2 reports an index side and a working-tree side, and `git diff HEAD` reports what the
tree has that `HEAD` does not — and showing the diff's list beside a diff's link is the pair that
cannot disagree.

### 7. The `.commit` target, and a hash the window does not hold

`.commit(String)` is W5's binding row for this leaf. It is registered **once for the tab**, at
`specificity = 100`, with the session resolved through a `SourceControlTabHost` in exactly the
shape C7.5's `FilesTabHost` takes and for exactly its reasons: every channel's session would
otherwise register an indistinguishable target for one tab id, and `LinkRouter.mostSpecific`
compares specificity and canonical tab order and never channel identity (tracker 240). The
mitigation is the same and so is its limit — a delivery reaches the channel the host resolves for
the destination, which is right for the click a user just made and wrong for a link on behalf of a
channel that is not on screen. Only X7's amendment closes that, and this leaf does not attempt a
local fix.

The handler selects the commit. Three cases:

1. **In the loaded window** — select it, load the detail.
2. **Not in the window** — page with `GitLog.commits(skip:)` in `defaultLimit` steps up to a bound
   of five pages (10,000 commits), matching on full hash or unambiguous prefix, and select it when
   found. Paging is the only answer available: W7 makes every git invocation C7.3's, and C7.3
   ships no "does this object exist" reader. A page that finds the hash *extends* the window, so
   the graph the user then sees actually contains the row that was selected.
3. **Not found within the bound, or an ambiguous prefix** — a named panel-local row. Not a silent
   no-op: a link that reached a live target and produced nothing on screen is the failure §17.7
   exists to prevent.

The bound is a number and not "until the history ends", for the reason `LinkRouter`'s re-resolution
bound is one: an unbounded search over a repository with a million commits is a panel that never
answers.

**A delivery is owed an answer, even when its read was cancelled or superseded** (ruled
2026-09-09 at T5's review, resolving a collision this document created). §5's rule that a
cancelled read publishes no notice and this section's rule that a delivery is never a silent
no-op are both written as absolutes, and a delivery whose paging read is cancelled must break one
of them. §7 wins, and §5's rule is hereby the narrower statement it was always meant to be: it
governs **background** reads — the cycle, the watch's re-reads — which the user did not ask for
and is owed no row about. A `.commit` link is a click. The user pointed at a commit and is owed
an answer about *that commit*, so a delivery interrupted by a background cycle is retried or
reported, never dropped. For the same reason a completed background cycle does not clear a
delivery notice the user has not answered: a row that vanishes unattended because a `claude`
session committed elsewhere is the same silence by a slower route.

**An unambiguous prefix is unambiguous in the history the walk covered, not in one page.** A
prefix matching one commit on page 1 and another on page 2 is ambiguous, and deciding `.one` at
the first page that yields a single match is exactly the arbitrary pick this section forbids. The
walk therefore reaches its bound — or the end of history — before it calls a prefix unique.

**A selection does not survive a change of root.** A cycle that resolves a different repository
than the one on screen — the channel's own directory becomes a repository, a submodule is
swapped — invalidates the selection and the changed-file list with it, and re-arms the watch on
the new root. Otherwise the panel emits a `DiffRef` whose `repository`, `path` and `base` were
read from two different repositories, and C7.5's resolver is handed a triple that never existed.

### 8. The GitHub tab: what it reads, when, and what it never runs

Three reads, all through `GhCommands`, all in the repository root:

- `pullRequests(root:head:state:limit:)` with `head` = the branch `WorkingTreeStatus` reported and
  `state = "open"` — the composite's "pull requests for the branch". A segmented control switches
  `head` to `nil` for *All open*; the branch scope is the default because item 28's question is
  about the branch the channel is on.
- `checks(root:pullRequest:)` for **each listed pull request when the list is branch-scoped**
  (ordinarily zero or one, so the round trips are bounded by the branch and not by the repository),
  and for the **selected** pull request when the list is not. A row whose checks have not been read
  says so; it never shows "passing" for a rollup it does not have.
- `issues(root:limit:)` — open issues, in a section of their own.

**No polling.** These are network round trips through GitHub's API on the user's token, and a panel
that refreshed them on a timer would spend the user's rate limit while they read. The reads run on
first appearance of the tab for a channel, when the branch changes (which `RepositoryWatch` already
reports), and on an explicit *Refresh*.

**The check rollup** is a named function of `CheckRun.bucket` over a PR's checks, and it is
deliberately five-valued: `none` (no checks — not "passing"), `pending`, `failing`, `passing`, and
`unknown` for a bucket `gh` reports that this table does not name. `gh pr checks` exiting 8 is
`pending` with rows, not a failure (C7.3's D3).

**Absent, logged out, and never a login.** `binaryNotFound(.gh)` is one empty state; a non-zero
exit whose stderr tail classifies as *not authenticated* is another, carrying the `gh auth login`
hint as text the user can read and type. Neither renders a byte `gh` printed (§6.3, §11); the tail
is matched to classify and then dropped. afleet holds no token, runs no `auth` verb, and the
argument-vector assertion of G3 is what makes that structural rather than a promise. The same
classification exists in C7.6's `PullRequestURLResolver` and cannot be imported across panel
targets; the duplication is filed rather than worked around.

### 9. Why this leaf does not register `.pullRequest`

C7.6's `BrowserLinkTargets` documents its low specificity as an invitation: "C7.7's source-control
panel is the expected case" for a higher-specificity `.pullRequest`. The invitation is declined.
W5 is binding that Browser registers `.pullRequest`, the composite's G2 for this leaf is that a PR
**opens in the Browser tab**, and C7.6's resolver already does the one thing a competing target
would have to do — turn a number into a page through `gh` in the right channel's repository. A
second registrant would win by specificity and then either duplicate that resolution or hand the
URL back to the Browser, and the first afternoon someone changed one of the two they would diverge.
This leaf emits `.pullRequest(number)` and lets the registry do its job.

### 10. Persistence: this leaf writes no store document

W6 reserves `panel.sourceControl.<configHomeHash>.<sessionId>` in the `workbench` namespace, and
this leaf leaves it unwritten.

What there is to persist is a selected commit hash and a scroll offset. Neither survives its own
meaning across a relaunch: a selected hash can be rebased or garbage-collected away, and a scroll
offset into a window read fresh from `git log` points at a different commit the moment anything is
committed. Against that, nothing in this leaf's gates asks for restoration, and X7 already retains
the session per (tab, channel), so selection survives channel switching — which is what the
composite's acceptance actually requires ("panes and open editors are per channel and survive
switching away and back"). A document written for the sake of the key would be a schema, a version,
a migration and a stale-hash branch, bought with nothing.

The key stays reserved. A later milestone that finds a use writes it, with a schema version, and
W6 needs no change for that to be true.

### 11. Availability, surfaces, and what the views hold

Both tabs answer `isAvailable(in:) == true` for every channel, including a channel whose cwd is in
no repository, which renders the `.notARepository` empty state. Availability is what X7's Cmd+1…7
indexes over, and a tab that appeared and disappeared as the user moved between channels would
renumber the shortcuts under them; an empty state is the honest and stable answer.

Both tabs describe views rather than owning `NSView`s, so `makeView(session:context:surface:)`
ignores its `surface` — the same description is right in the main column and in a pop-out. The
`PanelSurface` parameter is taken and named, not defaulted, because X7 has no default.

## Surprises & Discoveries

- **`NoDefer` is not what buys G1's one-second bound.** The plan named dropping
  `kFSEventStreamCreateFlagNoDefer` as one of three mutations that must turn a test red. It does
  not, and T2 said so rather than bending a test to make it look red. Measured on this machine at
  a 0.5–1 s latency, deliveries arrive in 11–14 ms **with the flag and without it**; the deferral
  only becomes visible far above the bound, where a 3 s latency without the flag costs 1.79 s.
  So the bound is bought by the stream's latency sitting well under it, and `NoDefer` is kept as
  the API contract rather than as the mechanism. The mutation obligation is discharged by
  measurement and disproof, which is the honest form of §17.7 when a named mutation turns out to
  be equivalent.
- **A lane sequence does not name a graph.** T3's fixtures asserted `rows.map(\.lane)`, and the
  octopus fixture's real assignment (`two work@2, one work@1, main work@0`) and the reading its
  own comment invited (`main work@2, two work@1, one work@0`) produce the *same* sequence
  `[0, 2, 1, 0, 0]`. The assertion could not tell a correct graph from a permuted one until the
  rows were named with their commits — found by a fix, not by a review.
- **Four workers in one worktree cannot each show a test failing first.** A task that lands its
  tests before its implementation makes `swift test` unbuildable for every sibling, so two of
  Wave A's four had to take their failing-first evidence in a throwaway copy of the package. The
  evidence is sound; the shape is not. A per-task worktree, or a rule that tests and
  implementation land in one commit, is what the next parallel wave wants.

## Outcomes & Retrospective

### The numbers

`swift test --package-path Workbench` **958 tests, 0 failures** from a 673-test baseline; this
leaf's own `SourceControlPanelTests` is **173** of them (the count the App scheme reports, since
the live `gh` leg runs there). The App floor is `** TEST SUCCEEDED **` read from the captured
file, zero failed cases across nineteen bundles; `check-imports`, `check-x7` (27 requirements, 6
protocols, 3 documents) and `check-wiring` (19 allowlisted, 0 findings) clean. Twenty commits.
Nine tasks, four review rounds, four fix waves.

### What each gate returned

- **G1 — item 27.** Headless. Lanes are named *with their commits* through the panel's own
  readout over merge, octopus and detached-tag repositories, and the rendering contract (every
  edge drawn by exactly two adjacent rows, edges as a sequence and never keyed by lane, a
  truncated edge continuing) is asserted as draw operations the `Canvas` executes. The
  commit-file corpus — modification, add, delete, rename, binary, gitlink, and a root commit
  listing its whole tree — is asserted at the selected-commit readout, not only at the reader. A
  click emits its `.diff` link through a **real `LinkRouter`** to a recording target. The
  one-second working-tree clause measured 5 of 5 standalone runs inside the bound (~0.23 s to
  appear, ~0.50 s to clear), delivery-fulfilled, and it is proved again after a
  deactivate/activate cycle. **Human leg:** the graph drawn on screen, the diff opening in
  Monaco, and a real `claude` edit making the row appear while the user watches.
- **G2 — item 28.** Headless over authored `gh` documents: the branch-scoped list by value, the
  five-valued rollup with its mixed cases, exit 8 accepted *and its rows asserted*, issues with
  their labels, and `.pullRequest(number)` emitted through a real router with no URL built here.
  The live `gh` leg ran (logged in) and decodes all three verbs; it reached **no check in
  flight**, so tracker 118 stays open and is restated as 289. **Human leg:** the PR row with its
  check status, and the click that loads the PR page in the Browser tab.
- **G3.** Met. A `.commit` link routed through a real router selects the commit — in the window,
  outside it by paging with the window extended, by unambiguous prefix, and as a named row when
  the hash is absent or the prefix ambiguous. A delivery arriving *before the first read* now
  waits for it and selects, which is the shape a click from a timeline actually takes. `gh`
  absent and `gh` logged out are distinct empty states with distinct hints, neither carrying a
  byte the tool printed, and no `auth` verb is representable — enforced at `tearDown()` across
  every flow rather than by an assertion a test can forget.
- **G4.** Met by two proofs, as designed. Every `git` and `gh` argument vector the leaf produces
  is drawn from a written-out read-verb allowlist with a non-vacuity floor; and each readout's
  action inventory is `Action.allCases` compared against a written-out list in **both**
  directions. A third proof was added at the whole-branch review: a source-level scan asserting
  neither view file acts on its session outside the single `Control` door, because the inventory
  alone could not see a `Button` written straight into a body. Its limits are recorded as 286
  and 287 rather than claimed away.

### What this leaf would tell the next one

The reviews were worth more than the implementation. Four rounds found 41 confirmed findings,
and the ones that mattered were never "this code is wrong" — they were *"this test cannot fail"*.
A lane sequence that could not distinguish a correct graph from a permuted one; a readout whose
entire graph payload could be replaced with `lane: 0, edges: []` under a green suite; an argv
gate that a prohibited `gh auth login` walked straight past because one flow handed it a bare
runner. Every one of those would have shipped as a passing gate. §17.7 is not a style rule.

The second lesson is about parallelism. Four workers in one worktree cannot each show a test
failing first, because a task that lands tests before its implementation breaks the build for its
siblings; two of the four took their evidence in a throwaway copy (290). The gain was real but
smaller than it looks, and the next parallel wave wants a worktree per task.

The third is that a leaf which only *emits* into other leaves' seams is cheap to build and easy
to under-test. Nothing here renders a diff or resolves a pull-request URL; C7.5 and C7.6 do. That
made the panel small and made it tempting to assert on a double instead of the registry — which
is exactly where the review found the gap.
