## Purpose

Two things every later Workbench leaf stands on, and neither of them is a panel.

The first is an editor: VS Code's own Monaco, built once by a script into a committed bundle,
loaded by an `NSView` over a `WKWebView`, and spoken to over one small JSON vocabulary. C7.5
opens a file in it at a line and saves it; C7.7 renders a commit's diff in it. Neither of them
should have to know what a `WKURLSchemeHandler` is, and neither should discover at integration
that the bridge means something different from what the other assumed.

The second is a router: `LinkRouter`, the registry every panel and C6 register a
`WorkspaceLink` claim against. C5 shipped the app's `HostLinkRouter` before this leaf existed
and wrote into its own source that when this module lands the host **delegates** to it rather
than a second registry coming into being. That hand-over is this leaf's, not C7.5's.

After C7.2 the whole Workbench package still shows nothing on a screen. What it has is the two
seams the four panel leaves would otherwise each invent a corner of.

### G1 — the package tests (required)

`swift test --package-path Workbench` passes and covers:

1. **The bridge codec round trip for every message in W4.** Six host-to-editor messages
   (`open`, `setText`, `gotoLine`, `setTheme`, `showDiff`, `save`) and five editor-to-host
   messages (`ready`, `dirty`, `saveRequested`, `cursor`, `error`), each round-tripped, each
   also **decoded from a literal JSON string**, and one test asserting that every `type` string
   the Swift codec emits appears in the committed bootstrap JavaScript. The round trip alone
   cannot fail on the defect it exists to catch — Swift agrees with itself whatever the
   JavaScript does — so the literal strings and the bootstrap check are what make it
   discriminating.
2. **`LinkRouter` over every `WorkspaceLink` case** (`.file`, `.diff`, `.url`, `.commit`,
   `.pullRequest`, `.command`): the registered target is called with the link intact **and the
   destination it was opened from**, the fallback with nothing registered, the specificity rule,
   and the tie-break by canonical `PanelTabID` order tested separately from specificity, because
   a comparison written only against unequal specificities passes with the tie-break missing.
   Withdrawal by tab is tested here too: after `unregister(tab:)` the link falls through to the
   next target and the withdrawn one receives nothing further.
3. **A resource test**: the bundle is present in `Bundle.module`, its `VERSION` names the pinned
   Monaco version, the licence is beside it, and the entry points the view loads (the document,
   the bootstrap and the five workers) all exist.

Evidence: the test count before and after, and the failing-first run of each new test (§17.7).

### G2 — S3, the spike (required)

## Design

Everything the composite and X7 already fix is carried whole. This section records only the
residue, each item with the reasoning that settles it.

### 1. What "tree-shaken" resolves to in 0.56.0

One document entry and five worker entries, built by `Tools/build-monaco.sh` with `bun build`:

```
src/editor.js       -> monaco-editor/editor/editor.main.js, plus this leaf's bootstrap
src/editor.worker.js, ts.worker.js, json.worker.js, css.worker.js, html.worker.js
```

`editor.main.js` is W4's list exactly, as the Grounding records, so the tree-shaking is a
consequence of the entry points rather than a hand-curated import list that would drift at
every Monaco bump. **Code splitting stays on**: the ~85 language grammars are behind lazy
`import()`s, and splitting is what keeps them out of the cold-load path. It also means the
bundle is a directory of 107 files rather than a handful, which is the shape the resource test
and the scheme handler are written for.

`monaco-lsp-client` arrives as part of `editor.main.js` and is left in place; excluding it would
mean curating the entry by hand for a saving the measurement says is not there.

### 2. The bundle, its stamp and its licence

`Workbench/Sources/EditorCore/Resources/monaco/`, declared in the manifest as
`resources: [.copy("Resources/monaco")]`. **`.copy`, not `.process`**: a web bundle's directory
layout *is* its URL space, and `.process` reserves the right to rewrite it. Read at run time
through `Bundle.module`.

Beside it: `VERSION`, naming the Monaco version, the bun version and the build date, which the
resource test compares against a constant in Swift; and Monaco's MIT licence text, copied from
the package. `Tools/monaco/package.json` and `bun.lock` are committed so the build is
reproducible; `node_modules` never is.

**The size question the human gate reserved is answered before the gate, by measurement**: 13 MB
across 107 files, 2.91 MB compressed. That is under the 20 MB threshold at which this leaf was
told to stop and report, so the bundle is committed and the leaf proceeds. If a later Monaco
bump pushes it over, the lever is `ts.worker.js`: dropping the TypeScript language service while
keeping `json`, `css` and `html` removes about half the bundle, and that is a W4 change, not a
local one.

### 3. `LinkRouter` — where it lives, what it owns, and what it refuses to own

`LinkRouter` is an **`actor`** in `LinkRouting`. The 2026-09-06 Revision Note kept
`unregister(tab:)` `async` expressly so this could be an actor rather than main-actor-isolated
state, and left the choice here; this leaf takes it. Serialised execution is also what makes the
withdrawal-before-registration ordering that note is about structural rather than argued.

It owns registration, withdrawal by tab, resolution and the fallback:

- **Resolution.** Highest `specificity` wins; ties break by `PanelTabID`'s canonical order, so
  the choice is total and independent of registration order. This is the rule `HostLinkRouter`
  already ships — moved, not re-decided.
- **Withdrawal.** `unregister(tab:)` drops every target that tab registered.
- **Fallback.** `.url` with nothing registered goes to an external opener; the other five cases
  emit a diagnostic **naming the kind and never the link**, because a path, a commit hash or a
  PR title in a log is exactly what §11 forbids. Both are `@Sendable` closures given at `init`
  with production defaults (`NSWorkspace.shared.open`, an `OSLog` line), so the fallback is
  testable without opening a browser and without the app, which is what W5's "pure and tested
  without the app" asks for.

It does **not** own pop-out. `.newWindow` has to pop the target's tab out before the target
delivers, and that needs the host. A stored host hook on an actor the host owns is a retain
cycle, so the hook is **per call**:

```swift
public func open(_ link: WorkspaceLink, from destination: LinkDestination,
                 prepare: (@MainActor @Sendable (LinkTarget, LinkDestination) async -> Void)? = nil) async
```

`prepare` runs after the target is resolved and before it is delivered to, which is the ordering
the `.newWindow` rule is about. With no `prepare` the router is the pure registry W5 describes
and its own tests use it that way.

### 4. The host delegates; a second registry never exists

`HostLinkRouter` keeps its `LinkRouterCapability` conformance, its weak host reference and its
pop-out logic, and delegates registration, withdrawal, resolution and the fallback to one
`LinkRouter`. Its `private var targets` is deleted — that array is the second registry X7's
amendment forbids.

Two consequences inside this leaf's fence, both in `App/Panels/HostLinkRouter.swift` and its
tests:

- `targetCount` becomes `async`, because the count now lives on an actor. Its only caller is
  `AppTests/PanelHostTests.swift`.
- The `openExternally` and `diagnostic` seams move to `LinkRouter.init`, so `HostLinkRouter`
  gains `init(externalOpener:diagnostic:)` with production defaults and `PanelHostModel`
  continues to construct it with none.

The single-registry claim is structural — it rests on a property being deleted — and no test can
witness the absence of a field. That is stated rather than papered over with a test that would
pass either way. What the tests do witness is behavioural parity: C5's link tests, including the
withdrawal-and-specificity one, pass unchanged against the delegated implementation, plus a new
app-side test that a `.url` nobody claimed reaches the injected external opener through the
delegated router.

### 5. The bridge codec, and the test that can actually fail

Flat tagged JSON — `{"type": "open", "path": …, "language": …, "text": …, "line": …}` — because
the other side of the wire is hand-written JavaScript that a Swift-shaped nested encoding would
make needlessly awkward to read. Two enums with custom `Codable`:

```
EditorCommand  (host -> editor)   open, setText, gotoLine, setTheme, showDiff, save
EditorEvent    (editor -> host)   ready, dirty, saveRequested, cursor, error
```

Exactly W4's vocabulary "and no other". Host-to-editor goes out through `evaluateJavaScript`;
editor-to-host arrives on a `WKScriptMessageHandler` named `afleet`.

The round-trip test W4 asks for is necessary and not sufficient: Swift encoding and decoding
its own enum agrees with itself no matter what the JavaScript believes. So each message is also
decoded from a **literal JSON string** written the way the bootstrap writes it, and one test
asserts every `type` string in the codec appears in the committed bootstrap source. That last
test is the one that fails when the two sides drift, which is the only failure this codec has.

### 6. `MonacoEditorView`

An `NSView` owning a `WKWebView`. The bundle is served through a `WKURLSchemeHandler` on the
`afleet-editor` scheme (advisory in W4; kept). The view is not exercised by `swift test` — a web
view in a package test buys a slow test that proves the framework works — and is exercised by
the S3 harness instead, which is what the spike is for.

`isInspectable` is `true` under `#if DEBUG`; in Release it is a settable property the app sets
from the Developer setting, so `EditorCore` reads no setting of its own. `setTheme {name}` passes
a Monaco built-in through (`vs`, `vs-dark`, `hc-black`, `hc-light`) and the default follows
`NSApp.effectiveAppearance`; any UI over it is C7.5's.

### 7. S3 measures three load paths, not two

The composite names two: the document and the workers. Code splitting adds a third —
**dynamic-import chunks**, which is how ~85 language grammars arrive — and a chunk fetch under
`afleet-editor:` is a load the scheme handler must service just as much as the document is. A
spike that measured only the document and the workers could promote a bundle whose Swift syntax
highlighting silently never loads.

The order of routes stays the composite's, with chunks measured at each step:

1. scheme for document, chunks and workers;
2. Blob-URL workers built by the bootstrap, document and chunks still on the scheme;
3. `loadFileURL(_:allowingReadAccessTo:)` for everything.

A fourth resort exists and is named so it is never reached silently: `MonacoEnvironment.getWorker`
returning nothing, which runs the language services on the main thread and leaves syntax
highlighting unaffected, because highlighting is not a worker's job. If S3 ever reaches it, it is
a Revision Note here and a degraded promotion, not a pass.

### 8. The S3 harness

`executableTarget(name: "S3Harness", dependencies: ["EditorCore"], path: "Spikes/S3Harness")`,
inside the C7.2 fence, in no product and not in the `Workbench` umbrella. It opens an `NSWindow`
from `swift run` with no app bundle, per the composite's decision. Its fixtures — the 5 MB file
and the 2,000-line diff pair — are generated at run time and never committed.

## `[parent-impact]` — W1's dependency table and X7's amendment contradict each other

W1's table, which is inside a `[binding]` block, gives `LinkRouting` a dependency on `AfleetCore`
alone. The composite's own later Revision Notes (2026-09-06) put the registry's whole vocabulary
in `PanelHostAPI`: `LinkTarget`, its `(WorkspaceLink, LinkDestination)` handler, and withdrawal
keyed by `PanelTabID`. A registry over those types cannot be built without importing that target.

The table row predates the seam. It was written when `LinkRouter` was imagined as a switch over
`WorkspaceLink` alone; X7 then made the target a `PanelTabID`-tagged, destination-carrying value,
and nothing went back to the table.

**What this leaf does:** adds `PanelHostAPI` to `LinkRouting`'s dependencies inside the C7.2
fence. The edge is acyclic — `PanelHostAPI` depends on `AfleetCore` and `FleetKit` only — and it
changes nothing for the panel leaves, which already depend on both.

**Rejected:** re-declaring `LinkTarget` and a tab identifier inside `LinkRouting` (two
`LinkTarget` types is precisely the duplication X7's amendment forbids); making `LinkRouter`
generic over a `Tab` parameter that would only ever be given `PanelTabID`, to preserve the
wording of a table row rather than its intent.

**For the architect at merge:** amend W1's table row for `LinkRouting` to read `AfleetCore,
PanelHostAPI`.

## `[parent-impact]` — "with no network" cannot be literally true of a clean checkout

C7.2's G3 says a clean checkout "builds and tests with the network disabled", and the
composite's Parent-Level Acceptance item 6 says the package tests pass "from a clean checkout
with no network". Neither can be literally true: `Workbench` depends on `libghostty-spm` by URL,
and a checkout on a machine that has never fetched it must fetch it once. `Package.resolved`
pins the revision; it does not carry the sources.

What is true, and what this leaf proves, is the clause those sentences exist for — **that
nothing in the build or the test run reaches the network**, Monaco included, which is the whole
reason the bundle is committed. The proof is a fresh clone tested under `sandbox-exec` with
`network*` denied; it passed, and running it taught two things the filing did not originally say.

**The bound is two caches, not one.** SwiftPM resolves `libghostty-spm` and its transitive
`MSDisplayLink` from the machine-level **repository** cache, and `GhosttyKit.xcframework.zip` from
the **artifact** cache, because libghostty-spm ships GhosttyKit as a binary target. A filing that
named only the repository cache would send a cold machine looking for the wrong thing.

**`swift test` needs `--disable-sandbox` when it runs inside one.** SwiftPM sandboxes its own
manifest compilation with `sandbox_apply()`, which macOS refuses inside an existing sandbox, so
without the flag the run dies at `Invalid manifest` before compiling a line. The flag disables
only SwiftPM's *inner* sandbox; the outer `sandbox-exec` still denies the network to every process
in the tree, manifest compilation included, so the claim is if anything stronger than it would
have been. C7.1 and C7.3 will need the same flag.

The denial is proven rather than assumed, with a positive control: the same `curl` is run inside
the sandbox (fails DNS, exit 6) *and* outside it (exit 0), so a merely-offline machine cannot
masquerade as a working sandbox. SwiftPM's own words corroborate it — "no connectivity to
https://github.com/Lakr233/libghostty-spm.git, using previously cached repository state".
`Tools/verify-offline-build.sh` performs all of this and cleans up its clone.

**For the architect at merge:** amend C7.2's G3 and Parent-Level Acceptance item 6 to say "with
no network beyond SwiftPM's resolution of the package's declared dependencies, which warm
repository and artifact caches serve". C7.1 and C7.3 inherit the same clause, the same bound, and
the `--disable-sandbox` requirement.

## Surprises & Discoveries

- **Monaco 0.56.0 is not the package the composite's baseline describes.** The `exports` map
  rewrites every specifier, `editor.all.js` is gone, and `editor.main.js` now bundles the basic
  languages and the four web language features that used to be separate contributions. Following
  the baseline's spelling fails to resolve, which is how this was found rather than reasoned.
- **The bundle is 13 MB, and half of it is one file.** `ts.worker.js` is 6.47 MB minified. The
  10–20 MB the composite guessed was right, and the composition inside it — one worker dominating
  — is the part that matters, because it is the only lever if a future bump breaks the budget.
- **`HostLinkRouter`'s two fallback seams have never been exercised.** `openExternally` and
  `diagnostic` are settable for tests and no test sets them; the `.url` fallback and all five
  diagnostics are unproven in the app today. `LinkRoutingTests` covers them from this leaf on.
- **Code splitting turns the worker question into a chunk question too.** The composite's risk
  register names workers under a custom scheme; the same uncertainty applies to the dynamic
  imports that carry the language grammars, and nothing in the baseline had noticed.

### What the spike actually settled

**`loadFileURL` is not a fallback — it is impossible.** Route 3 does not load at all: every
`file:` URL is its own opaque origin, so a split, module-based bundle is cross-origin to its own
document and the module graph never evaluates. WebKit reports this as an empty error event. The
custom scheme is therefore not a preference over the alternative the composite named; it is the
only route the document has, and the composite's ordered fallback list has one fewer real member
than it appears to.

**The Blob-worker hazard did not fire, and the reason is worth keeping.** `bridge.js` writes each
worker shim as `import "<absolute afleet-editor:// URL>"`. A module's base URL is where it was
fetched from, so the real worker entry resolves its chunk imports back onto the scheme and `blob:`
never enters resolution. Written *relatively* it would have failed exactly as this document
predicted. The unsplit-worker lever was never needed.

### What this leaf would tell the next one

- **`monaco.typescript`, not `monaco.languages.typescript`.** In 0.56 the service namespaces sit
  at the top of `monaco` beside `editor` and `languages`; the nested spelling is `undefined`.
- **Re-opening the path that is already open is the normal case, not an edge one.** §9.1's file
  watcher refreshes open files when the agent edits them, and the first implementation of `open`
  threw on the second call for one URI, leaving stale contents and skipping the line reveal. The
  bridge now reuses the model at that URI rather than recreating it, because the URI is what
  language workers, markers, decorations and view state are keyed to.
- **A host-driven `setText` must not announce the buffer dirty.** The content listener saw the
  host's own write and posted `dirty: true` immediately followed by `dirty: false` — enough to
  flicker a save indicator that does not exist yet.
- **Entry 97 in the tracker is C7.5's to care about**: the host releases a tab's sessions before
  awaiting the link-target withdrawal, so the router's guarantee is sound and the layer above it
  is not yet.
