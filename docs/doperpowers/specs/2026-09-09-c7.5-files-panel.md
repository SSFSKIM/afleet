## Purpose

The Files tab is where the user looks at what the agent is doing to the working tree. A path in
a Read row opens the file at the line the timeline pointed to; the file opens in Monaco and is
editable and savable; when the agent edits the same file underneath, the buffer refreshes, and
when the buffer is dirty the user is told rather than overwritten in either direction. Files
that are not code — markdown, images, PDFs, audio, video — open in the viewer macOS already has
for them rather than as bytes in a text editor.

It is also the leaf that turns two of C7.2's seams into something a user can see. `LinkRouter`
has had no `.file` or `.diff` target since it landed; `MonacoEditorView` has been exercised by a
spike harness and by nothing that renders in the app. Both change here.

C7.7 is blocked on this leaf for its diff views, and the shape of that unblocking is recorded
below rather than left to negotiation: **C7.7 opens a diff by emitting a `.diff`
`WorkspaceLink`**, which this leaf's target renders. No panel imports another panel.

### G1 — item 24, in the built app (required)

Root spec item 24: *click a path in a Read row; Monaco opens it at that line; edit and save;
`git diff` shows the change; ask Claude to edit the same file; the editor refreshes* — plus the
composite's addition, *the conflict banner when the buffer is dirty*.

**Headless half.** `swift test --package-path Workbench` proves, over real files under
temporary directories:

1. A `.file(url, line:)` link routed through a real `LinkRouter` reaches the Files target and
   produces exactly the command sequence `open {path, language, text, line}` on the editor
   seam — the path being the file's own path, the text being the file's own bytes, the line
   being the link's line. A target that opened the file and dropped the line passes nothing
   here, because the assertion is on the sequence and not on "an open happened".
2. The save round trip: a `saveRequested {path, text}` event writes those bytes to that path
   and nothing else; the file on disk equals the buffer; a save whose write fails leaves the
   buffer dirty and raises a panel-local error rather than reporting a save.
3. The watcher: a file open and **clean** that is rewritten on disk produces a refresh —
   `open` again for the same path with the new text, followed by `gotoLine` restoring the
   cursor — within a bounded, delivery-fulfilled wait.
4. The conflict: the same rewrite with the buffer **dirty** produces no refresh and raises the
   conflict state; *Reload* then produces the refresh and clears it; *Keep mine* leaves the
   buffer and marks the next save as an overwrite.
5. Save-echo suppression: the panel's own save produces a watcher event and **no** refresh and
   **no** conflict, proven by a test that would fail without the suppression (the mutation is
   named in the plan).

**Human leg.** The click in a real Read row, Monaco rendering the file at the line on screen,
typing into it, and a real `claude` edit of the same file refreshing the pane. Named in the
closing report as a human witness.

### G2 — item 25, the native viewers (required)

Root spec item 25: *a `.md`, `.png`, `.pdf` and `.mp4` each open in their native viewer.*

**Headless half.** The routing decision is a pure function of the file's name and its leading
bytes, and it is tested as one: for a corpus the tests generate under a temporary directory —
a markdown file, a PNG, a single-page PDF, a WAV, an MP4 container, a UTF-8 source file, a file
with no extension whose bytes are text, and a file with no extension whose bytes are not — the
decision names the viewer, and for the four of item 25 it names markdown, image, PDF and media
respectively. A viewer that could not construct its content is a panel-local error state and is
tested as one (a truncated PNG is not an image).

**Human leg.** That each viewer actually renders — an image visible, a PDF paged, an MP4
playing — in the built app.

### G3 — a `.diff` link with each `DiffRef.Base` (required)

`.diff(DiffRef)` for each of `.workingTreeAgainstHEAD`, `.commit(hash)` and
`.commitAgainstParent(hash)` opens **the right pair** in the diff editor.

**Headless half.** Over git repositories the tests build in a temporary directory with the
machine's own `git`: for each base, the resolved pair is asserted by its *contents* — the
original text is the side git records at that revision and the modified text is the other side —
for a modified file, an added file (no original side), a deleted file (no modified side), a
renamed file (the original side read at the *old* path, which is the case a pair keyed on the
new path gets wrong), a root commit under `.commitAgainstParent` (no parent, so no original
side), a binary file (no text diff offered) and a submodule gitlink (never blob-read). The
`showDiff {path, original, modified, language}` command carrying that pair is the assertion, so
a resolver that produced the right texts and sent the wrong command fails.

**Human leg.** The pair rendered side by side in Monaco's diff editor.

### G4 — per-channel persistence (required)

Open files and cursor positions persist per channel under W6 and restore on relaunch.

**Headless half.** Against a real `FileStateStore` in a temporary directory: a session that
opened two files and moved the cursor writes one document under the channel's key; a fresh
session constructed over the same store restores the same open files, the same selection and
the same cursor positions, and reopens the selected one at its stored line. A second channel
writes a second key and neither reads the other's. A document written by a future schema
version is refused into the empty state rather than decoded, and a file recorded in the
document that no longer exists on disk is dropped from the restore rather than opened as an
error.

**Human leg.** Relaunching the built app and finding the files still open.

## Design

Everything the composite and X7 fix is carried whole. This section is the residue, each item
with the reasoning that settles it.

### 1. The shape: a state machine the tests can drive, and views that only draw

The panel is four objects, and only the last one is SwiftUI.

- `FileTree` — the directory listing: enumeration, the filter, the gitignore classification.
- `FileKind` — what a path is, and which surface opens it.
- `FileWatch` — one watcher per open file, and the pure policy that decides what an event means.
- `FilesPanelSession` — the `PanelTabSession` X7 retains per (tab, channel): which files are
  open, which is selected, each one's cursor and dirty state, the conflict state, persistence,
  and the two link targets. It talks to the editor through a **seam**, not through a
  `MonacoEditorView` directly:

```swift
@MainActor protocol EditorSurface: AnyObject {
    func send(_ command: EditorCommand)
    var onEvent: (@MainActor @Sendable (EditorEvent) -> Void)? { get set }
}
```

`MonacoEditorView` satisfies this as it stands; a test drives a recorder that captures the
command sequence. This is the whole reason G1, G3 and G4 have headless halves at all: the
assertions above are on *the sequence of `EditorCommand`s a session emits*, which is the
observable behaviour C7.7 and the human both see, and a `WKWebView` in a package test would
prove WebKit works and nothing else (C7.2's Design §6 took the same position for the same
reason). The seam is declared here rather than in `EditorCore` because C7.2 is merged and this
leaf does not edit another leaf's target; if C7.7 wants it too, promoting it is a W4 amendment
and a one-line move.

**Rejected:** putting the state in `@State` on the view (X7 exists because SwiftUI discards it
on a channel switch); making `FilesPanelSession` an actor (it is main-actor state that a
main-actor view reads, and the bridge's `send` is main-actor).

### 2. Language: one map, checked against the bundle

`open` and `showDiff` both take a `language`. Monaco can infer a language for `open` from the
model URI's extension and cannot for `showDiff`, whose models have no URI — so a panel that
relied on inference would show a file one way and its diff another. One map is used for both.

The map is a Swift table from lowercased extension (and a small set of extensionless well-known
names) to a Monaco language id, and the test that makes it discriminating **reads the committed
bundle**: every `{id:"…",extensions:[…]}` registration in `Resources/monaco` is parsed, every id
this leaf emits must appear among them, and every extension this leaf maps must be mapped to the
same id by the bundle. A typo, an invented id, or a Monaco bump that renames a language fails a
named test rather than showing a file as plain text in front of a user. The map is deliberately
smaller than the bundle's 84 registrations — it carries what the extensions in this repository
and the common ones a working tree holds need — and an unmapped extension is `plaintext`, which
is what Monaco would have done anyway.

**Rejected:** generating the map from the bundle at build time (a generated Swift source with no
reader, to replace a table whose errors a test already catches); passing the empty string and
letting Monaco infer (correct for `open`, impossible for `showDiff`, and the two would drift).

### 3. The tree: what it enumerates, and what "gitignore toggle" costs

The tree is lazy per directory: a node is enumerated when it is expanded, sorted directories
first then by localized name, and re-enumerated on an explicit refresh. It is **not** watched.
§9.1 asks for a watcher over *open files*, and a recursive watch over a working tree is a
different instrument with a different failure mode (a `node_modules` under an FSEvents stream);
the tab refreshes a directory when it is expanded, on the panel's *Refresh*, and after a save
that created a file. A tree that follows the working tree live is named in *Deferred* below.

`.` entries are hidden by default with a toggle; symbolic links are listed and are **not**
followed into (a link to an ancestor is a cycle, and the tree has no other defence), which is
recorded on the node so the view can draw it.

**The gitignore toggle is one batched `git check-ignore` per enumerated directory**, through
C7.3's `ToolRunner` in the channel's resolved environment — one process for a listing, never one
per row. A directory in no repository, or a `git` that is missing, disables the toggle and shows
everything: a panel-local state (§10), never an error that reaches the channel. `check-ignore`
exits 1 when nothing matched, which is a normal answer and not a failure — the same class of fact
as C7.3's `gh pr checks` exiting 8 — so only 0 and 1 are answers and everything else is
unavailable.

**The spelling is `--verbose --non-matching --no-index -- ./<name>…`, and the answer is read by
position.** Amended 2026-09-09 during T1, which measured that this leaf's first spelling
(`--stdin -z`) cannot run here at all: `ToolRunning.run` has no stdin and opens every child's
descriptor 0 on `/dev/null`, so `--stdin` would read EOF and report *nothing ignored* — a silent
wrong answer, the worst shape this toggle could fail in — and on `git` 2.55.0 `-z` is refused
outright without `--stdin`, so dropping half of it is not available either. Without `-z` git
C-quotes any name carrying a newline, a quote or a backslash, which is the quoting C7.3's D7
refused to reimplement. `--non-matching` closes that gap instead: git prints exactly one record
per input path in input order, so the *position* of a record answers the question and the echoed
pathname is never decoded. What the record *means* is read from its **pattern** field, not from the
`::` prefix alone: measured on `git` 2.55.0, a path re-included by a negation is reported with that
negation — `.gitignore:2:!keep.log` — so treating every non-`::` record as ignored hid exactly the
files a user had explicitly asked to see (found at the merge review). Measured with it: git refuses
to re-include a file whose parent directory is excluded, so `build/` followed by `!build/keep.me`
reports the *directory's* pattern and the file really is ignored. A record count that does not
equal the input count makes the toggle unavailable rather than hiding the wrong rows. Each name is
passed as `./<name>` after `--`, because a name beginning with `:` is otherwise read as pathspec
magic; names are chunked under an argument budget so a pathological directory does not fail at
spawn and read as "unavailable". The ordering claim is pinned by a test against the machine's own
`git`, with a fixture whose name contains a newline, in the style C7.3 used to pin
`--raw --numstat`.

**The alternative was rejected deliberately.** Adding a stdin capability to `ToolRunning` would be
an edit to C7.3's target and a change to W7's runner, for a spelling this one does not need; the
finding is filed for the tracker instead, so the next leaf that wants to write to a `git` child's
stdin finds the gap named.

The filter is a case-insensitive substring over the names of the *loaded* nodes. It is not a
search: §9's *Deferred* names "search across the Files tree" as out of scope, and a filter that
silently walked the tree would be that feature with no budget for it.

### 4. Viewers: the decision is a pure function, the surfaces are native

`FileKind.of(url:)` decides by lowercased extension first and by the file's leading bytes second,
and returns one of: `code(language:)`, `markdown`, `image`, `pdf`, `media`, `quickLook`,
`binary`. The extension is first because it is what the user named the file; the bytes are the
tie-break for an extensionless file (a leading UTF-8-valid, control-character-free prefix is
text) and the *veto* for a claimed one (a `.png` whose first bytes are not a PNG signature is
not handed to `NSImage` to fail inside a view — it is a panel-local error state, which is what
§10 asks for).

The surfaces, in the composite's own order of preference: markdown through
`AttributedString(markdown:)` in a selectable text view; images through `NSImage`; PDF through
PDFKit's `PDFView`; audio and video through AVKit's `AVPlayerView`; anything else that macOS
has a preview for through Quick Look's `QLPreviewView`; and a file that is none of those, or is
larger than the panel's cap, draws its size and offers *Reveal in Finder* rather than loading it.

**The cap is real and is the same one C7.3 chose for the same reason**: a file is read whole to
hand Monaco a string, and a working tree contains files nobody meant to open. Above the cap the
file is not read at all. The number is the runner's own retained-output cap; the editor's
practical limit is far below it and is the human's to observe, not this leaf's to guess.

**Markdown is rendered, not highlighted, by default**, with a toggle to open the source in
Monaco — because item 25 asks for a `.md` to open in *its native viewer*, and a `.md` the user
wants to edit is the same file. The toggle is per open file and is part of the persisted state.

### 5. The diff pair: the changed-file list decides which sides exist

A `.diff(DiffRef)` link names a repository, a repository-relative path and a base. The pair is
resolved in three steps, and the middle one is what makes it correct:

1. `GitCommands.repositoryRoot` resolves the root (the link's `repository` is documented as the
   working-tree root, and resolving it again costs one `rev-parse` and makes a subdirectory
   harmless).
2. `GitDiff.changes(root:base:)` is read, and **the record for this path decides which sides
   exist**: `added` has no original side, `deleted` has no modified side, `renamed(from:)` and
   `copied(from:)` read the original side at the *old* path, `isBinary` offers no text diff,
   and `kind == .gitlink` is never blob-read. Without this step a resolver has to guess, and the
   two guesses it would make — read both sides and treat a failure as empty, or key both sides
   on the new path — are exactly the added-file and renamed-file defects G3 tests for.
3. The sides are read: for `.workingTreeAgainstHEAD` and `.commit(hash)` the modified side is
   `GitDiff.workingTreeFile` and the original side is `blob(rev: "HEAD" | hash)`; for
   `.commitAgainstParent(hash)` the modified side is `blob(rev: hash)` and the original side is
   `blob(rev: hash + "^")` — the first parent, which is the side
   `show --first-parent` diffs against, and which does not exist for a root commit, where step 2
   has already said every path is `added`.

This mapping is not invented: it is read off `GitDiff.arguments(for:)`, so the pair the panel
shows is the pair the changed-file list is a list of. A path the base did not change is not a
diff and is answered as a panel-local state, not as an empty diff editor.

Both sides are decoded as UTF-8 for Monaco, which takes strings. Tracker 189 records that
`SourceControlCore` already decodes path bytes lossily; the *contents* are decoded here for the
first time, and an invalid sequence is replaced rather than refused, because the alternative —
refusing to show a diff of a file with one bad byte — is worse for the user than showing it with
a replacement character. Filed as a tracker entry rather than hidden.

**Why `SourceControlCore` and not a second reader.** W7 makes C7.3 the owner of every `git`
invocation and its parsers, and its `blob`/`workingTreeFile` pair exists, in its own words,
"because the Monaco bridge takes two texts rather than a patch" — that is this leaf's use, named
by the leaf that built it. W1's dependency row for `FilesPanel` does not list it; that is the
`[parent-impact]` below.

### 6. Persistence: one document per (panel, channel)

`FilesPanelState` is `Codable` with a `schemaVersion`, holding: the open files (absolute path,
cursor line and column, the markdown source/rendered toggle), which is selected, the gitignore
and hidden-files toggles, and the filter is **not** persisted (a filter restored from a previous
launch hides files for a reason the user cannot see).

The key is `panel.files.<configHomeHash>.<sessionId>` in the `workbench` namespace the host
binds, so the full path reads `workbench.panel.files.<configHomeHash>.<sessionId>`.
`<configHomeHash>` is the twelve-hex-character prefix of the SHA-256 of the config home's path —
the same spelling §11 uses for capture directories, recomputed here because that function lives
in ClaudeWire and X1 forbids the import. Two deviations from W6 as written, both filed as
`[parent-impact]` below: the key is per *panel* as well as per channel, and it does not restate
its own namespace.

Writes are debounced and coalesced (a cursor moves on every keystroke; the store is a document
rewritten whole). The restore drops a recorded file that no longer exists rather than opening an
error, and a document whose schema version is newer than this leaf's is refused into the empty
state — the store already raises `schemaTooNew` for the namespace, and a panel that decoded a
future document would be the one thing the version exists to prevent.

### 7. Save, and the two keys that are not in the vocabulary

W4's vocabulary is closed. Two things a Files panel obviously wants — *the user pressed Cmd+S*
and *the user pressed Cmd+F* — would each be a new editor-to-host message, and this leaf adds
none.

**Save** is therefore a host-side action: a *Save* button in the editor's header, and a
`Save` menu item bound to Cmd+S at `.saveItem`, which is the placement that puts it in the **File**
menu where a macOS user reaches for it. Both do the same thing: `send(.save)`, and the
`saveRequested {path, text}` that comes back is written. The write is where the second half of
the conflict rule lives (Design §8). Find stays Monaco's own (Cmd+F inside the web view is
Monaco's find widget, which is already there and needs no message).

The menu item is the leaf's one unavoidable edit to `App/AfleetApp.swift`. §8.7 does not list
Cmd+S; the addition is proposed in *Parent revisions*, and the button alone satisfies item 24 if
the architect declines it.

### 8. The watcher and the conflict, as a policy a test can drive

One watcher per **open file**, not per directory: `DispatchSource.makeFileSystemObjectSource`
over a descriptor for the path, watching `.write`, `.extend`, `.delete`, `.rename`, `.revoke`
and `.link`. A vnode source watches an *inode*, so an editor that writes by rename — which the
engine's own edit path may do — delivers `.delete` or `.rename` and then never fires again; the
source therefore **re-arms on those events by re-opening the path**, after a short coalescing
delay, and a path that has not come back within the delay is reported as deleted. A poll
fallback (stat the path on an interval) covers a file system where the source cannot be armed at
all, and is the same code path with a different trigger, so the policy below is tested once.

The policy is a pure function, which is what makes it testable and what makes the mutations in
the plan meaningful:

```swift
enum WatchOutcome { case ignore, refresh, conflict }
func outcome(observed: FileSnapshot?, lastLoaded: FileSnapshot, lastWritten: FileSnapshot?,
             isDirty: Bool) -> WatchOutcome
```

A `FileSnapshot` is size, modification time and a digest of the contents. The rules:

- The observed snapshot equals `lastWritten` → `.ignore`. **This is the save echo**, and it is
  keyed on the digest rather than on a flag the save sets and forgets to clear, because a save
  produces one, two or no events depending on how the write landed and a flag cannot be
  un-set correctly for all three.
- The observed snapshot equals `lastLoaded` → `.ignore` (a touch, a metadata change, a write of
  identical bytes).
- Otherwise, `isDirty` → `.conflict`, else `.refresh`.

`.refresh` sends `open` with the new text and then `gotoLine` with the cursor the session last
heard from the editor, in that order, on the ordered send chain. The bridge reuses the model at
that URI, so markers, decorations and view state survive the refresh; the cursor does not, which
is why it is restored explicitly.

`.conflict` raises a banner naming the file with two actions: *Reload* (discard the buffer,
refresh, clear the conflict) and *Keep mine* (leave the buffer; the next save is an overwrite).
The banner is per open file and is cleared by either action, by the file's contents returning to
what the buffer would write, or by the file being closed.

**The save side of the same rule.** A save re-reads the file's snapshot immediately before
writing. If it does not match `lastLoaded`/`lastWritten` and the user has not chosen *Keep
mine*, the write is refused and the conflict is raised instead — because a watcher event that
has not been delivered yet is not the same as a file that has not changed, and item 24's
conflict is about not losing the agent's work any more than the user's. A destination that has
**vanished** is a conflict on the same terms rather than a file to recreate silently. The write is
atomic (write a sibling temporary, `rename`), which is what keeps the file whole if the app dies
mid-write, and the new snapshot is recorded as `lastWritten` **before** the rename lands so the
echo cannot arrive first.

Six clauses were added to this paragraph at the merge review, each closing a real defect and each
worth stating because a later reader would otherwise reintroduce it:

- **A save never writes under a config home.** CLAUDE.md's first rule and X9 are about afleet
  writing there, and a `.file` link carries any URL: a settings file under the channel's config
  home, `CLAUDE_CONFIG_DIR` or `~/.claude` was directly replaceable through *Save*. The refusal
  compares resolved destinations, so a symlink or a different spelling cannot slip past it, and
  reading such a file stays allowed.
- **A successful write sends `setText` with the bytes written.** The bridge's `readBuffer`
  deliberately does not clear the dirty flag and `reportDirty` only fires on a *transition*, so
  without this the editor stays dirty in its own eyes, the next edit reports nothing, *Save* is
  disabled and a refresh replaces edits nobody was told about. The bridge's own comment names this
  as the host's job.
- **The destination's final symlink is resolved before the temporary is placed.** `rename` onto an
  unresolved link replaces the *link* with a regular file and leaves the target untouched — the
  opposite of what the buffer was read from. (C7.3's `workingTreeFile` deliberately reads a link's
  own text; that is the diff path, where the link is the git object.)
- **Both baselines retire to the bytes just written.** Keeping `lastLoaded` at the pre-save
  contents made an external writer *restoring* them invisible to the policy and acceptable to the
  save preflight. `lastWritten` stays, because it is what covers the window between predicting the
  snapshot and the rename landing.
- **The temporary carries the destination's mode before any content reaches it.** `rename` installs
  a fresh inode, so a mode applied afterwards is a mode applied too late: saving a 0600 file wrote
  every byte into a 0644 temporary first. Ownership and ACLs are still not carried (tracker 239).
- **The destination is revalidated immediately before the rename**, because the only check used to
  precede the whole temporary write. This narrows the window rather than closing it — a race-free
  replace needs an exchange primitive — and the code says so rather than implying atomicity.

### 9. Link targets, registration and withdrawal

`FilesPanelSession` registers two `LinkTarget`s through `context.links.register(_:)` when the
session is created: `.file` and `.diff`, both with `tab: .files`. Specificity is the same for
both and above the fallback; nothing else claims either case today, and the tie-break is C7.2's
canonical order.

Two things the composite's Revision Notes make binding here:

- **The handler receives the destination**, and uses it: `.currentPanel` opens in this session's
  editor; `.newWindow` has already had the tab popped out by the host's `prepare` before the
  handler runs, so the handler's work is the same open in the session the popped-out window
  renders — which is the *same* session, because the host retains one per (tab, channel) and a
  pop-out draws the same channel. So the handler does the same thing for both and does not
  branch; the fact that it does not branch is recorded here so a later reader does not read it
  as a dropped case.
- **Registration is per channel and so is withdrawal.** The host's `unregister(.files)` withdraws
  every target for the tab at once, which is right at teardown and wrong at eviction: a session
  released by LRU pressure must take *its* targets with it and leave the other channels'
  alone, and `LinkRouterCapability` has no per-registration withdrawal. The answer is that a
  target holds its session **weakly** and does nothing when it is gone, so an evicted channel's
  target is inert rather than resurrecting a released session. Filed as a tracker entry, because
  the registrations still accumulate for the life of the tab, and a per-registration withdrawal
  is an X7 change no gate here needs.

### 10. What the tab is, and where it registers

`FilesTab: PanelTab` with `id: .files`, the id's default title and symbol, `isAvailable` true for
every channel, `makeSession` building a `FilesPanelSession` for the context, and `makeView`
returning the panel. The app registers it in `AppModel.init` beside C5's placeholder. `.files` is
held by nothing, so this is a plain `register`, not X7's unregister-then-register handover, and
`register` is synchronous and throws only on a duplicate — which on a freshly built host it
cannot be, so it is asserted rather than swallowed, exactly as the placeholder's registration is.

The App fence for this leaf is `App/Composition/AppModel.swift` (the registration),
`App/AfleetApp.swift` (the Cmd+S item), and their tests. Nothing else under `App/` is touched.

## `[parent-impact]` — W1's dependency row for `FilesPanel` cannot satisfy G3

**The contradiction.** W1's ownership table gives `FilesPanel` the dependencies `EditorCore,
LinkRouting, PanelHostAPI, FleetKit`. This leaf's own gate G3 requires a `.diff` link with each
`DiffRef.Base` to open the right pair in the diff editor, and a pair is two texts read out of a
git repository. Every git invocation and every parser belongs to `SourceControlCore` by W7,
whose `blob` and `workingTreeFile` were built — by C7.3's own account — "because the Monaco
bridge takes two texts rather than a patch". With the row as written, the only ways to satisfy
G3 are to write a second git reader inside `FilesPanel` (which W7 forbids) or to drop the gate.

The row is also missing `AfleetCore`, for the reason C5 and C7.2 have each already recorded on
this manifest: `LinkRouting` and `PanelHostAPI` do not re-export it, and under Swift 6's
member-import-visibility rules a target that names a `WorkspaceLink` or a `DiffRef` must depend
on the module that defines them.

**Filed, not fixed.** The composite is edited by the architect at merge, not by a leaf; three
leaves still share that file.

**Recommendation.** W1's `FilesPanel` row becomes `AfleetCore, EditorCore, SourceControlCore,
LinkRouting, PanelHostAPI, FleetKit`. The edge is acyclic — `SourceControlCore` depends on
`AfleetCore` alone — and it does not widen the package's external dependencies. The
`SourceControlPanel` row already carries both `SourceControlCore` and `EditorCore`, so the
combination is one W1 already sanctions for a panel.

**What it does not mean.** It does not make Files a source-control panel. The tree's gitignore
toggle and the diff pair are the only two uses, both are reads, and §9.2's scope rule (no
staging, committing or branch operations) is untouched.

## `[parent-impact]` — W6's per-channel key cannot be one document across three leaves

**The contradiction.** W6 is binding and says Workbench persists under two keys:
`workbench.browser` and `workbench.panel.<configHomeHash>.<sessionId>`, the second being "per-channel
panel state: open files with cursor positions, pane count and cwd overrides, the selected tab".
That single document's contents belong to three independently owned leaves — open files to
C7.5, panes and cwd overrides to C7.4, the selected tab to C5's host — and `ScopedStore`'s write
is a whole-value write with an `await` in front of it. Three owners doing read-modify-write on
one key lose each other's writes whenever two land close together, which for "the cursor moved"
and "a pane opened" is ordinary. They would also have to share one `Codable` type and one schema
version across three worktrees, which is the coupling W1's target split exists to prevent.

A second, smaller point: the key as spelled restates its own namespace. The host binds
`workbench` and passes keys through unchanged, so a key spelled `workbench.panel.…` produces
`workbench` twice on the path to the document.

**Recommendation.** W6's second key becomes `panel.<tab>.<configHomeHash>.<sessionId>` within the
`workbench` namespace — one document per (panel, channel), each owned, versioned and migrated by
the leaf that owns the tab, and the full path still reads `workbench.panel.…` exactly as W6
spells it. The Browser's window-wide document becomes the key `browser` in the same namespace
for the same reason. C7.6 is not yet dispatched, so the convention costs nothing to set now;
C7.4's panes and C5's selected tab each become their owner's own key.

**What this leaf does meanwhile.** It writes `panel.files.<configHomeHash>.<sessionId>` and reads
nothing else, which is forward-compatible with the recommendation and with the architect ruling
otherwise: if the single-document reading is upheld, this leaf's document becomes one field of
it and the change is local to one type.

- Decision: the tree's filter keeps a directory whose **loaded** descendant matches.
  Rationale: the column flattens the listing depth-first, so a directory the filter drops takes
  every loaded node under it off the screen; filtering for `main` removed `src` and with it the
  `main.swift` already loaded inside it. Loaded descendants only, so setting a filter still
  enumerates nothing, which is what §9 means by "not a search".
  Date/Author: 2026-09-09 / C7.5 fix wave B.

## Surprises & Discoveries

- **The committed Monaco bundle is a machine-readable language table — but only if you read it
  loosely.** 84 registrations survive minification, which turns "is this language id real?" from a
  question a reviewer answers by eye into an assertion. The trap is that 83 of them spell `id` and
  `extensions` adjacently and one does not: `swift` puts its `aliases` between them, so the obvious
  pattern drops exactly the language this repository is written in. `plaintext` is not literal at
  all and is exempted by name.
- **`showDiff`'s models carry no URI.** The bridge builds them with `createModel(text, language)`
  and no `Uri`, so Monaco's own filename inference — the thing that makes `open` forgiving — is
  simply absent on the diff surface. A panel that passed the empty string would have shipped a
  colourless diff editor and no test would have said so.
- **The bridge already refuses `save` while a diff is on screen.** C7.2 anticipated this leaf's
  worst bug (handing the host a file it is not showing) and answered it in the bridge, which
  means this leaf's job is to *not* ask, and to have a test that proves the refusal is handled
  rather than logged.

### What this leaf would tell the next one

- **`ToolRunning` cannot write to a child's stdin**, so every `git` verb whose batch form is
  `--stdin` is unavailable, and its failure shape is silent success (tracker 234). The gitignore
  batch is `check-ignore --verbose --non-matching` read by position instead.
- **X7 never tells a session it is being released.** The host drops the reference under LRU
  pressure and there is no hook, so anything a session owes the world at teardown has to be owed by
  a `deinit` that cannot await (tracker 238). C7.4's panes will feel this harder than open buffers
  did.
- **The bundle is the language table, if you read it loosely.** One of its 84 registrations puts
  `aliases` between `id` and `extensions` — and it is `swift`.
- **A save that renames is a save that re-modes.** `rename` replaces the inode, so an atomic write
  hands the file the umask's permissions unless the destination's mode is carried over. An
  executable script saved from a panel that skips this stops being executable.
- **A `DispatchSource` released without `cancel()` never runs its cancel handler**, so the
  `O_EVTONLY` descriptor stays open; and a poll loop that captures its own actor strongly outlives
  everything. Both matter precisely because the host has no teardown hook.
- **The bridge's vocabulary decides more of the panel than it looks like it does.** `save` is the
  only way to obtain the buffer, so "keep the user's unsaved text when the panel shows something
  else" becomes a *request with an intent* and a presentation that waits on the answer — and every
  race that follows (a reply matched to its request, a presentation that can lose, a timeout that
  must not authorise a write) is a consequence of that one closed door. A leaf reading W4 for the
  first time should count the round trips its UI implies before it designs the UI.
- **One session, several windows.** X7 hands the *same* session to the main window and to a
  pop-out, and each builds its own web view. Commands must be broadcast, ownership of the buffer
  has to follow the user rather than the last command, and a cursor event the panel itself caused
  is not evidence of anything. C7.4's panes will meet the same shape with a PTY behind it.
