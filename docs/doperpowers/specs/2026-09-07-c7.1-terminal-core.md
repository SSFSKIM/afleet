## Purpose

Everything a terminal pane needs below the panel, and nothing a panel would need above it:

1. **`TerminalSurface`** (contract W2) — the renderer seam. One protocol, so that which
   terminal emulator afleet renders with is one file's decision and not a commitment.
2. **The PTY layer** — an actor that opens a pty, spawns a process in a given directory
   with a given environment and nothing else, carries keystrokes in and bytes out, resizes
   the tty, and reports the child's end **once**, distinguishing an exit from a signal from
   a stop. The hatch's re-adoption (root §7.4, §7.2 rule 5) keys on that report, so it is
   the load-bearing deliverable: C4 already ships `PaneExit` and waits for it.
3. **The GhosttyKit adapter** over `InMemoryTerminalSession`, which is what makes the first
   two real on screen.
4. **S1** — the spike that settles whether GhosttyKit renders a login shell and the CLI's
   own attach client well enough to be the renderer, with SwiftTerm behind the same
   `TerminalSurface` as the named fallback.

After C7.1, C7.4 can build panes without knowing what a pty is, and the composite's items
15, 17 and 23 have their floor.

## Acceptance

The composite's three gates, restated as things a test or a person can observe. Four rules
bind all of them and are repeated in the plan's Global Constraints.

**Discriminating tests (root §17.7, binding).** Every test written to prove a fix is
demonstrated failing against the pre-fix code before the fix is accepted. Where the break
cannot be executed, the substitute is stated as such in the test's own comment. A test that
compares two things also asserts that it found them.

**Nothing is written under a config home (X9).** Not by this child's code, not by its tests.
The only writer under `/tmp/afleet-fixtures/config-home` is the `claude` this child spawns
in G2. Test trees live under `FileManager.default.temporaryDirectory`.

**Reports emit counts, and environments are asserted by name (root §6.3, §11).** No test,
failure message or report prints a path, an environment dump, a session id or a slug. An
environment assertion names the variables it expects and the variables it forbids, and reads
the child's answer as `present`/`absent` tokens the child prints — never as a dump.

**Zero model turns.** G2 attaches to a **promptless** `claude --bg --resume <id>`, which the
CLI documents as "continues that session in the background under the same ID"
(`claude --help`, 2.1.263). No prompt is ever sent. `AFLEET_LIVE_CLI_TURNS` is never read.

### G1 — the PTY layer, under `swift test --package-path Workbench` (required)

Every item is a headless XCTest in `TerminalCoreTests` with a real child process:

- **a.** `/bin/sh -c` in a temporary directory reports that directory back as its `pwd`, and
  reports a crafted variable's value; both read from the child's own stdout through the pty.
- **b.** **Nothing is inherited.** The test process sets a sentinel variable of its own
  before spawning; the child, given an environment that does not contain it, prints `absent`
  for the sentinel and `present` for exactly the names the request carried. The pre-fix
  demonstration is a spawn that passes `environ` through: it prints `present` and the test
  fails. Names only, both directions, never a dump.
- **c.** The child's initial window size is the one requested (`stty size`), and a resize
  after spawn is seen by the child as a new `TIOCGWINSZ` **and** as a `SIGWINCH` it can trap.
- **d.** The child is the session leader of its own session with the pty slave as its
  controlling terminal — proven from inside the child (`ps -o tpgid`/`tty` is not needed: an
  open of `/dev/tty` from the child succeeds and a `stty` read works, both of which fail
  without a controlling terminal), and by the layer's own `tcgetpgrp` on the master.
- **e.** **Exit, signal, stop, each observed and each reported once.** `exit 7` reports
  `.exited(7)`; `kill -TERM $$` reports `.signalled(15)`; `kill -STOP $$` reports a *stop*,
  which is not a termination, and under the detaching policy is followed by `SIGCONT` then
  `SIGHUP` and one terminal report of `.signalled(1)`. A counter proves each report fires
  exactly once even though the master's EOF and `waitpid` both fire.
- **f.** A spawn failure (an executable that does not exist, a cwd that does not exist) is a
  typed error at the call, never a report of an exit that never happened.

  package ships its own copy at
  `Sources/GhosttyTerminal/Resources/terminfo/{78/xterm-ghostty, 67/ghostty}`, delivered as a
  SwiftPM resource bundle. Residue Q4, and a `[parent-impact]` below.
- **The pty mechanism is measured, not assumed (2026-09-07, macOS 26.5.2).** A C spike
  outside the repository established three things the Design rested on. (a) `posix_spawn`
  with `POSIX_SPAWN_SETSID`, the slave path opened as descriptor 0 in the child and dup'd to
  1 and 2, **does** give the child a controlling terminal: the child's `tty` names the pty and
  `exec 3</dev/tty` succeeds, and `tcgetpgrp(master)` returns the child's group. The
  composite's `forkpty` fallback is therefore not needed and the risk it hedged is closed.
  (b) `ioctl(master, TIOCSWINSZ)` reaches the child as a new size **and** as `SIGWINCH`.
  (c) **The trap:** if the parent closes its slave descriptor before the child reopens the
  slave by name, macOS resets the pty's window size to `0x0`, and a `TIOCSWINSZ` issued on
  the master in that window is discarded — the child then reads `0 0` from `stty size`
  forever. The parent must hold its slave descriptor open across the `posix_spawn` and close
  it afterwards, while the child still opens the slave *by name* (a dup'd descriptor never
  becomes a controlling terminal). Both halves are load-bearing. This also makes the
  composite's suggested `stty size` check dangerous if written loosely: G1c asserts exact
  numbers, because `0 0` is what a wrong implementation reports and "some size" would pass.
- **The terminal-describing overlay works, measured end to end (2026-09-07).** The package
  exposes a supported accessor — `GhosttyRuntimeResources.terminfoDirectoryURL` — and it

## Design

W2 is the design and is carried whole. This section records only what building it fixes.

### The PTY layer

`PTYProcess`, an actor in `TerminalCore`, owns one pty master and one child.

```
PTYSpawnRequest    executable: URL, arguments: [String], cwd: URL,
                   environment: [String: String]        // complete; X11's composition, not ours
                   size: TerminalSize
                   terminal: TerminalDescription        // TERM and an optional terminfo directory
                   stopPolicy: .report | .detach
PTYEvent           .output(Data) | .stopped(signal: Int32) | .ended(PTYTermination)
PTYTermination     .exited(code: Int32) | .signalled(signal: Int32)
                   var paneExitCode: Int32              // code, or 128 + signal (shell convention)
```

The recommended mechanism of W2 is adopted unchanged: `openpty(3)`, then `posix_spawn` with
`POSIX_SPAWN_SETSID` and file actions that open the slave path as descriptors 0, 1 and 2 in
the child so the slave becomes the new session's controlling terminal at that open;
`ioctl(TIOCSWINSZ)` on resize; a `DispatchSource` read loop on the master on a private queue;
`waitpid` with `WUNTRACED`. `forkpty(3)` stays the named fallback and G1d is the test that
would send us there.

**Three things this fixes that W2 left open.**

1. **A stop is not an end.** `.stopped` is reported as its own event and the child stays
   alive. Under `stopPolicy: .detach` — which C7.4 selects for an attach pane — the layer
   answers a stop with `SIGCONT` then `SIGHUP` to the child's process group and the child's
   real termination follows as the single `.ended`. Under `.report` — the default, and what a
   shell pane uses — the pane decides. The policy lives here rather than in the panel because
   the signalling is process-group work the panel has no handle for, and it is a *parameter*
   rather than a rule because SIGHUP-ing a plain shell pane the user suspended would be a
   defect, not a detach.
2. **Exactly one `.ended`.** The master's EOF and `waitpid`'s answer race on every exit; the
   actor's state machine emits the first and swallows the second. G1e's counter is the test.
3. **Terminal-describing variables are overlaid on the request's environment.** See the
   `[parent-impact]` below. The set is exactly `TERM`, and `TERMINFO_DIRS` when the surface
   supplies its own database; a test pins the set by name so an addition is deliberate.

### `TerminalSurface` and the adapter

The protocol is W2's, with two additions recorded as *Parent revisions* below: it is
`@MainActor` (it vends an `NSView`, which is main-actor-isolated in Swift 6, so the
annotation states what the compiler already requires), and it gains a read-only
`terminalDescription: TerminalDescription` so the PTY layer can be told what the renderer
*is* without the panel knowing either.

`GhosttyTerminalSurface` implements it over `AppTerminalView` with
`TerminalSurfaceOptions(backend: .inMemory(session))`. `feed` calls `receive`; the session's
`write` closure drives `onInput`; its `resize` closure drives `onResize`;
`processDidExit(code:)` calls `finish(exitCode:runtimeMilliseconds:)` with the elapsed time
the adapter measured. The two closures are invoked by the session off the main actor, so the
handler pair lives in one lock-guarded box owned by the adapter — the single-owner-box escape
the root spec's concurrency conventions permit, documented at the site.

`suppressesPixelOnlyResizes` is left **off** (the package's default): W2's `TerminalSize`
carries pixel dimensions, so a host that stopped seeing sub-cell changes would report stale
pixel metrics to `TIOCSWINSZ` forever. `resizeThrottleMilliseconds` is left at 0 for the same
reason, and revisited only if G2 shows a live drag outrunning a full-screen TUI.

### Backpressure: what G3 actually requires

The read loop never touches the main actor per read. Bytes are drained on the private queue
into a bounded buffer and delivered to the surface in coalesced chunks, one main-actor hop
per delivery, with a cap on bytes per hop. Nothing is dropped: a producer faster than the
renderer is bounded by the pty's own flow control, which is the correct back-pressure and the
one a terminal is designed around. G3a measures the property (main-actor responsiveness)
rather than a proxy for it (a hop count, which a slow renderer would also satisfy).

### The pane seam (W8, X7) — what C7.4 inherits

`TerminalCore` does not import FleetKit and therefore never sees a `PaneRequest`. C7.4 maps
`PaneRequest {id, executable, arguments, cwd, environment, purpose}` onto `PTYSpawnRequest`,
choosing `stopPolicy: .detach` for `.attach` and `.report` otherwise, and maps the single
`.ended` event onto `PaneExit(request:code:observedAt:)` using `PTYTermination.paneExitCode`.
That mapping is one function and it is C7.4's; `paneExitCode` is provided here so C7.4 does
not invent the convention. `PaneExit` cannot distinguish `.signalled(7)` from `.exited(135)`;
that is acceptable and is recorded as an observation for the architect rather than a change,
because X5's re-adoption keys on the *event*, not on the number.

### The S1 harness

`Workbench/Spikes/S1Harness`, an `executableTarget` in C7.1's manifest region, not in the
`Workbench` product. It sets `NSApplication.setActivationPolicy(.regular)` and activates —
an unbundled `swift run` executable is otherwise a background application and never receives
key events or an input method, which would make G2a's IME check untestable for the wrong
reason. It opens one `NSWindow` programmatically, hosts one adapter and one `PTYProcess`, and
takes its command from arguments so the same binary runs the login shell, the `yes` flood and
`claude attach` legs. It prints counts and durations, never paths.

## Residue, and how it is answered

Every question the inherited material leaves, with the answer this child takes. Q1–Q5 are
decided here; Q6 is the one the architect may want to see before execution.

**Q1. `TerminalSurface` collides with a public class of the dependency.**
*Answer (decided).* Keep W2's name — it is binding, C7.4 consumes it, and the collision is
containable. `TerminalCore` declares the protocol; within that module the local declaration
wins unqualified lookup, and the adapter file spells the dependency's type
`GhosttyTerminal.TerminalSurface` wherever it means that one. `TerminalCore` does **not**
`@_exported import GhosttyTerminal`, so no consumer ever sees both. Task 3 carries a test
that names both types in one file, so a future toolchain that stops permitting the shadowing
fails a test rather than a merge. If it ever does fail, the answer is more qualification, not
a rename.

**Q2. What does the PTY layer report for a signal, given `PaneExit.code: Int32`?**
*Answer (decided).* A typed `PTYTermination` here, plus `paneExitCode` (code, or 128 + signal)
so the lossy projection has exactly one implementation and it is tested. The composite's "the
code or signal" is honoured in full inside `TerminalCore`, and the loss happens at C4's
boundary, once, visibly.

**Q3. Is "a stopped attach child is detached" the PTY layer's rule or the pane's?**
*Answer (decided).* The mechanism is the layer's, the choice is the request's:
`stopPolicy: .report | .detach`, default `.report`. Reasons in the Design above. The
composite's sentence is satisfied — a stopped attach child *is* treated as detached — without
imposing it on a shell pane.

**Q4. `TERM` and terminfo.** The request's environment is the user's, composed by C4; the
pty is ours. A Ghostty-rendered pane handed the user's `TERM=xterm-256color` renders through
a description of a different terminal, and one handed `TERM=xterm-ghostty` with no database
breaks every ncurses program on a machine with no Ghostty installed — which is the ordinary
machine, since the entry is not part of macOS.
*Answer (decided, and filed as a `[parent-impact]`).* The layer overlays exactly the
terminal-describing variables the surface declares — `TERM`, and `TERMINFO_DIRS` prepended
with the renderer's own database directory when it has one — onto the request's environment,
and a test pins that set by name. This is not inheritance from afleet's environment, which is
what X11 forbids; it is the description of a device the layer just created.

**Q5. Can the adapter be tested without a window?**
*Answer (decided).* Yes, for the half we own: a real `InMemoryTerminalSession` with no
surface attached exercises `write` → `onInput`, `resize` → `onResize`,
`processDidExit` → `finish`, and proves `feed` with no surface neither crashes nor blocks.
`readViewportText()` returns `nil` there, so *rendering* is asserted only in G2. The plan
states which claims the headless tests can and cannot make, so nobody later mistakes green
tests for a rendered terminal — the lesson C4 and C5 both paid for.

**Q6. How much of `AppTerminalView` does the pane need, and does a second surface conform?**
*Answer (recommended, and the one place the architect may prefer otherwise.* W2 says the
protocol is "kept to what a pane needs and nothing the renderer happens to offer", and this
child keeps it there: six members plus `terminalDescription`. Selection, scrollback search,
hyperlink hover, bell, progress and pwd reporting are all available on `AppTerminalView` and
are all **left out**, so that the SwiftTerm fallback is a day's work rather than a rewrite,
and so that C7.4 cannot quietly become Ghostty-specific. The cost is that a later pane
feature is a W2 amendment. Recommendation: accept the cost.

## `[parent-impact]` — the pty's own environment is not the request's environment alone

**What the parent says.** W2, marked `[binding — X11 and the lifecycle seam]`: the PTY layer
"spawns with the channel's cwd and `ResolvedEnvironment.variables` as the complete
environment (no inheritance from afleet's own)". X11 says the same of every spawn.

**Why it cannot be kept literally.** `TERM` in the resolved environment describes the
terminal emulator the *user's login shell* was captured under — Terminal.app, iTerm, or the
Claude Code session afleet was launched from. The pane's child is talking to a pty this layer
just opened, rendered by libghostty. Handing it the captured `TERM` misdescribes the device;
handing it `xterm-ghostty` without a database breaks every curses program, because that entry
is not shipped by macOS and resolves on this machine only from a per-user database installed
by a Ghostty application afleet does not require. Either way item 23's promise — that a pane
behaves as the user's terminal does — fails for a reason the user cannot see.

**What this child does.** The PTY layer overlays exactly the terminal-describing variables
the surface declares (`TERM`, and `TERMINFO_DIRS` with the renderer's bundled database
prepended when it has one) over the request's environment, pinned by name in a test. Nothing
else is added and nothing from afleet's own environment is inherited.

**The amendment recommended to the architect.** W2 and X11 gain the clause: *"…as the
complete environment, except for the terminal-describing variables the surface requires
(`TERM`, and `TERMINFO_DIRS` when the renderer supplies its own terminfo database), which
describe the pty the layer just created rather than any environment afleet inherited; the set
is pinned by a test."* Filed rather than edited: three leaves share the composite.

## Parent revisions (advisory; the architect applies them at merge)

1. **W2's protocol is `@MainActor`.** `var view: NSView` makes it so under Swift 6 whatever
   the snippet says; writing the annotation is a clarification, not a change.
2. **W2's protocol gains `var terminalDescription: TerminalDescription { get }`.** The PTY
   layer must be told what terminal it is driving (see the `[parent-impact]`), and the
   renderer is the only thing that knows. A separate refinement protocol was rejected: it
   would exist only to avoid editing text the architect edits at merge anyway, and C7.4
   consumes the source, not the snippet. The SwiftTerm fallback satisfies it
   (`xterm-256color`, no database of its own).
3. **W2's mechanism sentence is POSIX, not macOS.** Its recommendation that the slave's
   `open` after `setsid` is what makes the pty the controlling terminal does not describe
   this platform: Darwin grants it at `setsid`, and neither `O_NOCTTY` nor a `dup2`-only
   shape changes the outcome (measured; Grounding baseline). The recommendation still leads
   to correct code and the child keeps it, so this is a factual correction to the parenthetical
   rather than a change of design — but a later leaf debugging a pty on another platform
   should not read that sentence as a measured fact about this one.
4. **W2 gains the stop policy.** `PTYSpawnRequest.stopPolicy` with the default `.report` and
   `.detach` for attach panes, per Q3.
5. **Observation, no change asked.** `PaneExit.code` cannot distinguish a signalled child
   from an exit with the same number. Recorded because a reader of C4's tests may otherwise
   assume it can.

## Decision Log

- Decision: keep W2's `TerminalSurface` name despite the dependency's class of the same name;
  contain it by never re-exporting `GhosttyTerminal` and qualifying at the two sites that
  need the other type.
  Rationale: the name is binding and C7.4 consumes it; a rename would ripple into the
  composite for a problem that a module boundary already solves. Rejected: renaming ours to
  `PaneSurface`; renaming by `typealias` (moves the ambiguity, keeps it).
  Date/Author: 2026-09-07 / C7.1.

- Decision: a stop is a first-class event, and answering it with SIGCONT+SIGHUP is a
  per-request policy rather than a rule of the layer.
  Rationale: the bundle shows the attach client suspends its process group, so a pane must
  observe stops or hang; but SIGHUP-ing a shell pane the user suspended would destroy work.
  Rejected: always detaching on stop (the composite's literal reading); reporting stops and
  leaving all policy to the panel (the panel has no process-group handle).
  Date/Author: 2026-09-07 / C7.1.

- Decision: overlay `TERM` (and `TERMINFO_DIRS`) rather than pass the request's environment
  untouched.
  Rationale: in the `[parent-impact]` above. Rejected: shipping our own terminfo copy into a
  config-home-adjacent path (X9-adjacent, and unnecessary — the package already ships one);
  forcing `xterm-256color` always (throws away the renderer's real capabilities, and misreports
  the emulator to programs that ask).
  Date/Author: 2026-09-07 / C7.1.

- Decision: G3 is a headless test of main-actor responsiveness under a real flood, not only a
  harness observation.
  Rationale: the composite asks for the property; a harness-only check would be unrepeatable
  and would not run in `swift test`, which parent acceptance item 6 requires to cover the PTY
  layer. Rejected: counting main-thread hops (a proxy; the root spec's own warning about
  instruments that measure something correlated with the property).
  Date/Author: 2026-09-07 / C7.1.

- Decision: the S1 harness sets `NSApplication.setActivationPolicy(.regular)`.
  Rationale: an unbundled `swift run` executable is a background application; without this it
  never becomes key, never receives an input method, and G2a's IME leg would fail for a
  reason that says nothing about the renderer. Rejected: building an app bundle by hand
  (C5 owns packaging); deferring IME to C7.4.
  Date/Author: 2026-09-07 / C7.1.
