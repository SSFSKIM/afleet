## Purpose

At the pin, afleet can see an agent run and cannot open one. C3 reduces a whole `AgentRunTree`
per channel — nodes keyed by task id, nested, with status, model, activity line and elapsed
origin — and C6.1's timeline draws an `Agent` chip that resolves a run id and calls a seam whose
implementation is `NoAgentNavigation`, which does nothing. `PanelTabID.agents` is held by C5's
`PlaceholderTab`. The tree, the per-run transcripts, the per-node actions and the two
top-of-tree actions exist as a data model with no surface.

C6.4 is that surface. The Agents tab of §8.8: a tree of the channel's runs, nested by the two-step
join, one node per task id however many times the engine restarts it, parked runs shown as parked
rather than as finished; a transcript beside it that is C6.1's renderer over one run's items, with
the agent type as the author and the model badge the run's own frames disclosed; per-node *Stop*,
*Move to background*, *Send message*, *Open transcript file* and *Copy agent id*; *Stop everything*
and *Background all* over the whole tree, behind confirms; and a subagent's permission card
mirrored on its node, so a waiting agent is visible where the user is looking.

The hardest thing in it is not the tree. It is item 51's honesty: *Send message* is not a delivery.
afleet asks the main agent to relay, the model may not call the tool, may call it for a different
agent, may get an error back, and may end the turn before the target's next tool round. Four ways
to fail silently, and the user has to see each of them. The delivery state is this leaf's own
bookkeeping over frames C3 reduces, and it is the one piece of state here that a row outside this
leaf's directory has to draw.

## Grounding baseline

What is on `main` at the pin, read rather than taken on report. Each line is a fact this child's
design stands on; the file and symbol are named so a reviewer can check the claim.

- **The tree is complete and it is a value.** `AgentRunTree`
  (`FleetKit/Sources/FleetTimeline/Agents/AgentRunTree.swift:59`) is a `Hashable, Sendable`
  struct with `nodes: [String: AgentRunNode]`, `order`, `conflicts`, `parentAnswers`, `slug`.
  `AgentRunNode` (`:9`) carries `id` (the task id), `agentType`, `description`, `model`, `status:
  TaskStatus`, `depth`, `parent`, `parentSource` (`agentMetadata | metaFile | twoStepJoin |
  none`), `activityLine`, `lastToolName`, `elapsedOrigin`, `endedAt`, `toolUseID`, `children`
  and `startedCount`. The queries this child needs already exist: `roots` (`:180`),
  `children(of:)` (`:182`), `node(_:)` (`:184`), `node(withToolUse:)` (`:188`), `isParked(_:)`
  (`:194`) and `transcriptURL(of:)` (`:201`). Nothing about the tree has to be built here.
- **The tree's parent policy is first-source-wins, and it does not re-parent.**
  `AgentRunTree.link(_:to:from:)` (`:247–259`) records every source's answer in
  `parentAnswers[id][source]` and keeps the **first**; a later disagreeing source appends an
  identifier-only sentence to `conflicts` and changes nothing. C3 pins this with
  `testADisagreeingSourceIsRecordedOnceAndTheFirstAnswerIsKept`. This is what makes G1's
  "corrected by it afterwards" a question about precedence and not only about wiring — see D1.
- **`startedCount` is the repeated-`task_started` rule, already enforced.**
  `apply(taskStarted:at:)` (`:87`) increments a counter on an existing node rather than
  inserting a second one, which is what `nested-depth-2`'s README says a host must expect. The
  gate's clause is an assertion about C3's behaviour reaching the screen, not about code this
  child writes.
- **The tree reaches the app in the same read as the items.** `ChannelTimeline.agents:
  AgentRunTree?` (`FleetKit/Sources/FleetTimeline/Model/ChannelTimeline.swift:13`), nil for a
  channel with no wire fold; `StreamIngestion.agents` (`Ingest/StreamIngestion.swift:156`) is
  `wire?.agents`; `TimelineChange.agentsChanged` is appended once per apply when the tree moved
  by value (`Reduce/WireReducer.swift:734`). C6.1 already reads it:
  `TimelineNeighbourhood(items:agents:)` (`App/Timeline/Rendering/TimelineRenderContext.swift:288`)
  and `AgentChip` (`Rows/AgentChip.swift:91`) resolve a chip's run through
  `node(withToolUse:)`.
- **A run's items are separable, and the separation is `Provenance.agentID`.** The wire reducer
  keeps one `ItemBuilder` per agent (`agentBuilders`, `agentOrder`) and `rebuild()`
  (`WireReducer.swift:548–560`) hands each as its own `StreamProjection` to
  `RecordReducer.merge`, which stamps `provenance.agentID` on every item of an agent stream
  (`RecordReducer.swift:241`, `:254`). The file half stamps the same field. So one run's
  transcript is `timeline.items.filter { $0.provenance.agentID == run.id }` and it is the same
  expression live and from disk.
- **The renderer takes rows, not a channel.** `TimelineListView`
  (`App/Timeline/Rendering/TimelineListView.swift:20`) is a thin wrapper: it computes
  `TimelineRenderInput(rows:preview:)` and calls `renderer.view(for:)`, injecting a
  `TimelineRenderContext` it builds in `context(in:)` (`:68`). The reuse this child needs is
  that input and that context, not the wrapper — which is what makes "reuse C6.1's view"
  implementable without a second `ChannelTimelineModel`.
- **The two node control requests are already written, on C6.3's card.** `TaskCardView`
  (`App/Decisions/TaskCardView.swift:96–115`) sends `StopTask(taskID:)` and
  `BackgroundTasks(toolUseID:)` through `LifecycleAPI.send(_:on:)` and treats

  `ClaudeWire/Sources/WireFrames/OutboundRequests.swift:118`, `:121`.
- **The two top-of-tree actions are X5 actions.** `LifecycleAction.stopEverything` and

### D1 — **[architect]** The tree has no correction source and no mirror, and G1 and one node action need both

Two findings with one cause and one closer, so they are one item.

**The correction half.** G1 requires that the depth-2 tree "renders from the two-step join
before the `.meta.json` is written and is corrected by it afterwards". The first half holds at
the pin: `WireReducer` calls `agents.observe(parentToolUseID:carryingToolUseIDs:)` on every
`assistant` and `user` frame and the join answers `parentSource == .twoStepJoin`. The second
half has no production path at all. The mirrored `agent_metadata` entry — which §7.3 says
"arrives at the head of the agent stream's mirror … so `parentAgentId` is known before the
sidecar file exists" — is decoded by `StreamIngestion` into `StreamState.metadata` and used to
build items; `AgentRunTree.apply(agentMetadata:for:)` is never called outside tests, and neither
is `apply(metaFile:)`. So `parentSource` is `.twoStepJoin` or `.none` in every running channel,
`AgentRunNode.parentAnswers` never holds a second source, and there is nothing for a correction
to be a correction *of*. A surface cannot test what no code produces, and a surface that
fabricated it would be asserting its own double.

**The mirror half.** §8.8 shows *Move to background* "only while the run is foreground and
present in the registry mirror", and §8.4's rule needs the entry's `tool_use_id`. The node
carries `toolUseID` itself, so the request can be *formed*; what cannot be answered is
eligibility — whether this run is foreground and listed. `ChannelTimeline` does not carry the
mirror (tracker 321), and reaching `ChannelEventPump.mirror` from a panel tab would be the
second capability path the C6 cut exists to prevent, exactly as C6.1 reasoned when it left the
timeline's task card without the action.

**And wiring alone would not produce the gate's sentence.** `link` is first-source-wins by
design. Two orderings follow, and neither is "the join answers and the metadata corrects it":
where the mirrored `agent_metadata` entry arrives at the head of the agent stream — which §7.3
says is the ordinary case, *before* the sidecar file exists — it answers **first** and the join
becomes the fallback, which is exactly what §8.8 states and the opposite of what the code does
today; where the join happens to answer first, the metadata answer is recorded in
`parentAnswers` and any disagreement in `conflicts`, and the parent does not move. So the gate's
"corrected by it afterwards" describes a re-parenting the reducer deliberately refuses.

**Ruled, with the parent asked to confirm.** C3's first-source-wins is not overturned from a
surface: `conflicts` and `parentAnswers` exist precisely so a disagreement is recorded rather
than silently resolved, and a reducer that re-parented on a late frame would make the tree's
shape depend on arrival order. G1's correction clause is therefore read as what is observable
once metadata is delivered: a depth-2 node whose parent came from the mirror carries
a **metadata source** answered, the join's answer is retained beside it, and a node where the
two disagree is drawn with the parent the tree holds and with the disagreement visible rather
than hidden.

**Which metadata source, corrected 2026-09-09 at Task 4 after the corrective landed.** This
paragraph first said `.agentMetadata`, reading §8.8's sentence about the mirrored entry. On the
app's own channel open it is `.metaFile`: `StreamIngestion.openAgentStreams` calls `loadMetadata`
→ `apply(metaFile:)` while `open` is still buffering the tap (`StreamIngestion.swift:368`, `:396`),
so the **sidecar on disk** speaks before any mirrored entry does. The gate asserts `.metaFile` and
says why in place. Nothing else moves: the observable fact this rule names — a metadata source
answered, the join did not, its answer is retained, a disagreement is visible — holds under either
source, which is why the rule is written about the class and not the case. If the architect wants literal re-parenting instead, that is a C3 change and a
change to X4's semantics, not a surface's.

**Recommendation, and it is one commit on `main`, not two.** File a `[parent-impact]` against
X4 (below) and ask the architect to land a C3 corrective, in the shape tracker 187's and 321's
own *Closer* lines already state:

1. `StreamIngestion` feeds the `agent_metadata` record it already decodes into the wire fold's
   tree through the existing, tested `apply(agentMetadata:for:)`, and feeds a `.meta.json` it
   reads through `apply(metaFile:)`; for a channel with no wire fold it owns a file-only tree so
   `ChannelTimeline.agents` is non-nil for an archived or foreign channel.
2. `ChannelTimeline` carries the fold's `RegistryMirror`, published like `agents` is, and
   `TimelineChange` names it when it moves.

Both entry points exist and are covered by C3's own tests; the corrective is wiring, not design.
This child prepares the patch as a reviewable diff if the architect wants it and does not land
it: `FleetKit/` is outside this leaf's fence and the precedent for this exact situation is
C6.3's D2, where `HostSignal` had no delivery path and the architect landed `01eb7a7` on `main`
before the leaf's Task 8. This child takes `main` at a **task boundary** after the corrective
lands, never mid-task.

**If it does not land**, the fallback is stated now so the gate is not renegotiated later: G1's
join half, the one-node-per-task-id half and the parking half are all provable without it and
stay required; G1's correction half is recorded **blocked with its cause**, in the shape C6.2
and C6.3 used for their blocked live halves; and node *Move to background* is **absent rather
than wrong**, exactly as C6.1 left the timeline's task card, with a tracker entry. The tab's
own tests assert the absence, so a later mirror turning the action on is a visible change and
not a silent one.

### D2 — **[architect]** Item 51's delivery state is written here and drawn in a row this leaf does not own

§8.8 and acceptance item 51 both say the message "appears in the main timeline with its state".
The message afleet sends is an ordinary prompt — `LifecycleAPI.sendPrompt`, C6.2's path, Y5 —
so it lands in the timeline as a plain `userMessage` item. *Pending*, *Relayed*, *Delivered* and
*Not delivered* are **not** on that item and cannot be: §7.3's differential invariant forbids
this leaf adding a reducer, and no engine frame carries the state — it is afleet's own reading
of what the model did next. So the state is host bookkeeping keyed by the prompt uuid, and the
row that must draw it is `App/Timeline/Rendering/Rows/MessageRows.swift`, C6.1's file, reached
through `TimelineRenderContext`, C6.1's value.

This is precisely the pattern the composite named at C6.1's merge as recomposition's first
check — *state written for a reader that did not exist* — and it is the same shape as contract
Y6, where C6.2 owns the model and C6.1 owns the substitution in the row. Y6 was named because
Y4 had named the mirror case and nobody had named this one. The difference now is that C6.1 has
merged and retired, so there is no leaf to hand the row side to.

**Recommendation.** Name it as a contract — **Y8**, in Y6's shape and by the same argument —
with the model side in `App/Agents/` (an app-scoped `AgentRelayRegistry` keyed by `ChannelKey`,
holding one record per *Send message*: prompt uuid, target run id, text hash, state, the model's
reply when the arm is a refusal, and a *Retry*), and the row side as two named edits this child
makes in C6.1's directory under the contract: one field on `TimelineRenderContext` and one
decoration in the user-message row. Both edits are listed in the merge checklist so review sees
them as contract work rather than fence-crossing. The alternative — the state visible only on
the node in the Agents tab — is rejected: item 51 is a parent acceptance item and names the main
timeline, and a *Retry* the user can only find by opening another tab is the silent
non-delivery the decision log says must be visible.

Escalated because naming a contract is the architect's, not a leaf's, and because it is the one
place this child writes outside its directory.

### D3 — Item 51's fixtures: what "records from the scripted stand-in" costs, and what carries the gate

G4 asks for "`fake-claude` fixtures the leaf records from the scripted stand-in". A recorded
fixture is a directory under `Fixtures/`, and `make verify-fixtures` refuses one that a person
other than the recording run has not signed against `Fixtures/REVIEW.md`. Five arms recorded
five ways would be five review walks; one arm's worth of green would be gated on a human being
available.

Two separable things are being asked for, and conflating them is what makes the cost look
unavoidable: the *state machine* (what afleet concludes from a sequence of frames) and the
*sequence* (that the engine can produce it).

**Ruled, by this child.** The four *Not delivered* arms and the positive path are asserted
twice, at two different costs:

- **The machine, on decoded frames, with no fixture and no human.** Each arm is a short frame
  sequence built from ClaudeWire's own types and pushed through the real reducer and the real
  relay registry: a `SendMessage` `tool_use` naming the target id followed by a non-error
  `tool_result` (→ *Relayed*); the run's transcript gaining the text (→ *Delivered*); a turn
  that ends with `result` and no `SendMessage` (→ *Not delivered*); a `SendMessage` naming a
  different agent id (→ *Not delivered*); a **refused resume** (→ *Not delivered*, with the
  model's reply) — read from the result **body**, not from `is_error`; see the correction below; and a `task_notification` for the target arriving after *Relayed* with no
  further tool round (→ *Not delivered*). These are the discriminating tests: each arm is shown
  failing against a machine that concludes *Delivered* too early, which is the defect the
  decision log says must be impossible.
- **The sequence, once, as one synthetic fixture.** A generator beside
  `Tools/probe/synthetic/dialogs.py`, holding every frame against the bundle module it cites,
  producing **one** fixture whose turns are the five arms in order — one directory, one review
  walk, one signature. It is a deterministic rebuild like the dialog fixtures, it invents its
  identifiers, and it carries `synthetic: true`; whether `hypothesis` clears depends on what the
  bundle shows about `SendMessage`'s result strings, and the generator says so in `notes`
  either way.

The human leg is therefore exactly one signature, and G4's headless half does not wait on it.
If the signature does not come, the fixture is not committed (an unsigned directory fails
`verify-fixtures`), G4 stands on the machine half, and the gap is recorded in the outcome rather
than papered over. Recorded here so the plan budgets one review walk and not five.

### D4 — The per-run transcript is C6.1's renderer over a filtered row set, not a second model

**Ruled.** The transcript pane builds `TimelineRenderInput(rows:preview:)` from the channel's
own `ChannelTimelineModel.rows`, filtered to `row.item.provenance.agentID == run.id`, and hands
it to a `NativeTimelineRenderer` the Agents session owns. Not a second `ChannelTimelineModel`:
the app holds one per channel in `ChannelTimelineRegistry` and a second would be a second
subscription to the same fold, which is what Y5 and the C6 cut exist to prevent — and the tree
and the items have to come from one read or a node can point at an item the pane has not seen.

Three consequences worth stating because a reviewer will ask:

- **The preview is the channel's and is passed through only when it belongs to this run.** A
  streaming tail with no agent attribution is the main thread's; drawing it under a subagent
  would put the parent's words in the child's mouth.
- **Authorship and the model badge are the *pane's* framing, not a per-row edit.** §8.8 and item
  38 want messages "authored by the agent type … with a model badge, not by 'Claude'". The
  agent type is `AgentRunNode.agentType`, and the badge is `AgentRunNode.model`, which
  `agents.observe(assistantModel:agentID:)` (`WireReducer.swift:188`) sets from the run's own
  assistant frames — the parity map's §18 confirms nothing else on the wire carries it. So the
  pane supplies both once, through the render context, rather than each row re-deriving them.
  A per-row rewrite would mean editing C6.1's message rows; a pane-level attribution does not.
- **The filter is a filter, never a reduction** (D11's rule from C6.3, and §7.3's invariant): the
  items are C3's, unmodified, and a run with no items renders an explicit empty state.

### D5 — Y4's navigation: what `show(run:in:)` must do, and where the pending selection lives

**Ruled.** `show(run:in:)` is app-scoped and synchronous, and the thing it must reach — the
tab's per-channel session — is built lazily by the host on first render. So it cannot select a
node directly. It does three things in order: focuses the channel through `ShellModel` if the
key is not the one on screen; `PanelHostModel.select(.agents)`; and writes the run id into an
**app-scoped selection store keyed by `ChannelKey`** that the Agents session reads when it
appears and observes thereafter. That store is the same shape as `ComposerRegistry` and
`AppModel.decisions` — one instance, app-scoped, handed to the tab at the `performLaunch`
registration — and it is what makes a chip clicked before the tab was ever opened land on the
right node instead of nowhere.

A run id the tree does not know is **not** silently dropped: the pane selects nothing and says
the run is not in this channel's tree, because a chip on an archived channel resolves nil today
(tracker 187 again, and `AgentChipContent.runID` documents it) and a fabricated selection would
be worse than an empty one.

### D6 — Subagent cards on nodes are Y2's component over the overlay, filtered by `agent_id`

**Ruled.** `DecisionItem.agentID` is set by the reducer from the request payload
(`WireReducer.swift:420`), so a node's pending cards are
`timeline.overlay.decisions.values.filter { $0.agentID == node.id }`. The node draws a waiting
badge from that set being non-empty and hosts `DecisionCardView` with a `DecisionAnswering`
whose `raise` is the channel fold's `signal(_:)` and whose reservation set is `AppModel.decisions`
— the app's one set, so a card answered here and in Activity cannot both reach the wire (Y7,
C6.3's ruling). This child constructs no card and writes no answer mapping; Y2 is satisfied by
using the component, and a static test asserts the tab builds none of its own, as C6.3's G3 does
for Activity.

### D7 — Elapsed ticks without redrawing the tree

**Ruled.** §8.8 requires elapsed ticked locally from `task_started` because `task_progress` is
tool-paced. A one-second timer that invalidates the whole tree would put a periodic layout pass
on a surface whose sibling column is the S7 budget's tenant. So the ticking lives at the leaf of
the view — one small view per running node with its own timer — and the tree's identity, order
and node values change only when `agentsChanged` says the tree moved. A test asserts the tree's
row identities are stable across a tick.

### D8 — `roots` is the reading this child takes, which answers tracker 13

**Ruled, and reported back.** Tracker 13 records that `AgentRunTree.roots` is `parent == nil`
rather than "depth-1 nodes", that the two are identical on the corpus, and that they diverge
only for a depth-2 node no source answered for — "C6 reads `roots` and must be told at
recomposition. Closer: decide which reading C6 needs." This child takes `roots`: a run whose
parent is unknown surfaces at the top level, visible and openable, rather than being filtered
out of a tree that draws only depth-1 roots. An orphan is drawn with its depth shown, so the
user sees *a nested run whose parent we could not place*, which is the truth. Recorded against
tracker 13 at merge.

### D9 — Both top-of-tree actions are confirmed, and the confirm says what it will end

**Ruled.** *Stop everything* is `perform(.stopEverything)` and *Background all* is
`perform(.backgroundAll)` (Y5); neither is reimplemented. Both sit behind a confirm, as §7.7 and
the composite require. The confirms are not symmetric and the copy must not pretend they are:
*Stop everything* interrupts the turn and stops every registered task — work that `--resume`
cannot restore, which is why §7.4 treats it the way it does — and its confirm names the count
of live tasks it will end, read from `LifecycleAPI.liveTaskIDs(of:)`, the fleet's own fact
(counts, never ids or titles — §6.3, §11). *Background all* stops nothing and its confirm says
so. The engine's refusal "Background tasks are disabled in this session." renders as a banner
and hides both backgrounding affordances for that process, per §6.4's table.

### D10 — The tab is available for every channel, and an empty tree is a stated state

**Ruled.** `isAvailable(in:)` returns true always, as `ThreadTab` does. A channel with no runs
draws "no agent runs in this channel"; a channel whose `ChannelTimeline.agents` is **nil** —
every archived and foreign channel until D1's corrective lands — draws a different, explicit
state naming that the tree is wire-fed and this channel has no wire, because "no runs" and "we
cannot see the runs" are different facts and a user told the first when the second is true has
been misinformed. The two states are separate assertions in G1.

**Amended at Wave B, once D1's corrective (`b412f2e`) was on `main`.** The third state stays, and
what it *means* changed: `ChannelTimeline.agents` is nil only **before `open` builds the reducer**,
and non-nil afterwards for every channel kind, because the sidecars beside an archived channel's
transcript now feed its tree. So the state is no longer "this channel has no wire, so the runs are
not visible" — it is "this channel's fold has not been built yet", which is what a channel the host
holds no model for is in. It is `AgentRunRead.State.notOpened`, drawn by
`AgentTreeEmptyState.notOpened`. The distinction D10 exists for is unchanged and still worth
drawing; the fact under the third state is the one that moved. An archived channel now draws its
runs, which is a third assertion in G1 and the closer of tracker 172.

### D11 — Every string the tree draws is sanitised where the content is built

**Ruled, following C6.1's wave H.** `agentType`, `description`, `activityLine`, `lastToolName`
and a notification `summary` all come off the wire. C6.1 sanitises them once where the chip's
content is built (`TextSanitiser`, §12), and this child does the same at the node-content
boundary rather than at each of the four places a node draws a string. Reports and diagnostics
carry counts only.

### D12 — *Copy agent id* and *Open transcript file*

**Ruled.** *Copy agent id* puts `node.id` on the pasteboard; it is the one place a task id
legitimately leaves the app, at the user's explicit request, and it is not logged. *Open
transcript file* is `WorkspaceLink.file(url, line: nil)` through `ChannelContext.links` with the
url from `AgentRunTree.transcriptURL(of:)` — which composes the path from config home, session
id and slug and therefore answers during the run, not only at completion (parity §18.25). No
descriptor is opened on it here: C5's TCC fact binds, and the link's target is the Files panel's.

### D13 — Parking: C3's `isParked` and §8.8's sentence are two different readings

`AgentRunTree.isParked(_:)` is "this node is not running and some child is" — a live reading,
and it has no caller anywhere in the tree. §8.8's is "completed children under a node with no
`task_notification`", and the parity map's §18.23.3 agrees ("detect by completed children but no
notification"). The tree carries no notified bit: `notified` is on `RegistryEntry`, which is the
half D1 says is unpublished.

**Ruled.** The tab uses `isParked` as C3 defines it, because it is the reading the data
supports today and it catches the case the user cares about — a node that looks finished while
work continues under it. The two readings differ only for a node whose children have all
settled and whose notification has not arrived, which is the tail of the same state; that arm
becomes assertable when D1's mirror half lands, and it is filed rather than approximated. The
divergence is recorded against C3 so `isParked`'s comment stops being the only place the two
definitions are compared.

### D14 — The two confirms are the panel's own dialog over C6.2's copy

**Ruled.** `ComposerConfirmation` (`App/Composer/CommandRouting.swift:34`) already carries
`.stopEverything` and `.backgroundAll` with their titles, messages and confirm titles, and the
composer presents them from one hidden `ComposerShortcutBar` dialog. The Agents panel does not
route through that: a panel is drawn in a popped-out window where no composer exists, and a
read-only channel has no composer at all (C6.1's `composerSite` gate), so a confirm that
depended on one would be missing exactly where the user pressed the button. The panel presents
its own `confirmationDialog` and **reuses `ComposerConfirmation`'s strings**, so the copy is
spelled once and a change to it moves both surfaces. The affirmative claims synchronously, as
the composer's does and for the same reason — SwiftUI runs the dismissal before the button's
`Task` body — and the discriminating test is that declining performs nothing.

### D15 — The `agents` command destination gets its `LinkTarget`, closing tracker 207's third

Tracker 207 records that X10's `.native` destinations `tasks`, `agents` and `switcher` are
handed to the link router as `WorkspaceLink.command(_:)` and that no target claims a command
link, so `/agents` typed in the composer answers with a diagnostic; its *Closer* names C6.4 as
the owner of the `agents` half. **Ruled:** the tab registers a `LinkTarget` for
`WorkspaceLink.command("agents")` with the tab, not with a session — the Browser's and Files'
rule, because a session is built lazily and a link raised before anyone opened the tab would
otherwise resolve to nothing — and selecting the tab is all it does. `tasks` and `switcher` stay
open and stay other owners'.

## Acceptance

The composite's six gates, restated as what a test or a person can observe. Three rules bind
every one.

**Discriminating tests (root §17.7, binding).** A test written to prove a behaviour is
demonstrated failing against code that lacks it before it is accepted. Reviewers ask what an
assertion would have to *see* to fail: that a node appeared is not that the right request was
sent, and that a message shows a state is not that the state was concluded from the right
evidence.

**Nothing is written under a config home (X9).** Not by this child, not by its tests. The
default suite builds its scratch trees under `FileManager.default.temporaryDirectory`. G6 runs
under `/tmp/afleet-fixtures/config-home` with C5's `ScratchLiveGate` and the recursive
`ConfigHomeWitness`.

**Reports emit counts (root §6.3, §11).** Every gate report, failure message and diagnostic
states counts, sizes and durations — never a path, a title, a session id, a task id or a slug.
Test inputs use invented identifiers.

### G1 (required) — the tree, on `nested-depth-2`

Replaying the fixture through `FixtureRunner` into the real reducer, the tab's tree model shows:
two nodes, one per task id, the depth-2 node nested under the depth-1 node with
`parentSource == .twoStepJoin`, **before** any metadata source is applied — the discriminating
half is that the depth-2 node is not a root, which a tree built from `spawn_depth` alone or from
`task_started` alone would get wrong, since `task_started` carries no parent id; the same task id
appearing twice (driven by injecting a second `task_started`, the re-engagement
`nested-depth-2`'s README says a host must expect) is **one** node with `startedCount == 2`;
parking — completed children under a node with no `task_notification` — renders as parked and
not as completed, asserted through `AgentRunTree.isParked`; a channel with no runs and a channel
whose tree is nil render their two distinct states (D10). The **correction clause** is asserted
only once D1's corrective is on `main`, and is otherwise recorded blocked with its cause; when
it is, it is asserted as D1 rules it — a node parented from the mirrored `agent_metadata`
carries a metadata `parentSource` — `.metaFile` on the app's own open, for the reason D1
records — the join's answer is retained in `parentAnswers`
beside it, and a node whose sources disagree is drawn with the parent the tree holds and with
the disagreement visible. The clause is *not* asserted as a re-parenting: `link` is
first-source-wins and a test that demanded otherwise would be asserting against C3's stated
invariant.

### G2 (required) — the per-run transcript, with authorship and badge

On the same fixture, selecting each node renders that run's items and only that run's: the item
ids drawn equal `timeline.items.filter { provenance.agentID == run.id }`, and the differential
half is that a main-thread item and a *sibling* run's items are both absent — a filter that
merely excluded the main thread passes the naive assertion. Messages are authored by the run's
`agentType` and never by "Claude" (item 38), and the model badge is the run's own
`AgentRunNode.model`, asserted to be the value the run's assistant frames carried and not the
channel's header model. An empty run and a nil-tree channel render their states.

### G3 (required) — node actions and the two top-of-tree actions, on a lifecycle double

Each assertion is the exact request or action handed to the double:

- *Stop* → `AnyControlRequest(StopTask(taskID:))` with the node's own id, on the node's channel.
- *Move to background* → `AnyControlRequest(BackgroundTasks(toolUseID:))` with the node's
  `toolUseID`; a `{backgrounded: false}` reply is treated as stale and refreshes rather than
  reporting success. Conditional on D1's mirror half for its *eligibility*; the request shape is
  asserted regardless, and if the action is absent the absence is what is asserted, with the
  cause named.
- *Open transcript file* → one `WorkspaceLink.file` through `ChannelContext.links`, at the url

- *Copy agent id* → the node id on the pasteboard, nothing logged.
- *Stop everything* → `perform(.stopEverything)` **after** the confirm and never before it:
  declining performs nothing, which is the half that fails on a confirm wired to a no-op.
- *Background all* → `perform(.backgroundAll)`, same shape.
- The disabled banner: with `background_tasks` refused by the session, both backgrounding
  affordances are hidden and the banner renders.

### G4 (required) — item 51's five arms

The four *Not delivered* arms and the *Pending → Relayed → Delivered* path, as D3 rules them:
the state machine over decoded frame sequences, each arm shown failing against a machine that

### G5 (required) — a chip click lands on the run, through Y4

Driving C6.1's chip action with the real `AgentNavigation` installed, the app selects `.agents`

## Design

### The shape: one tab, one session per channel, one selection store

`AgentsTab: PanelTab` under `.agents`, registered in `performLaunch` immediately after the
`.thread` handover. A plain `register` and not a handover — nothing holds the id — but in the
same place and for Y3's second reason: the lifecycle exists nowhere earlier, and this tab can
neither stop a task nor relay a message without one. Its link target is registered with the tab
(D15), awaited beside the Browser's at the top of `performLaunch` where a link can first exist.
It holds the lifecycle, a `ChannelFold` over the app's one `ChannelTimelineRegistry`, the
app's `DecisionReservations`, the relay registry of D2 and the selection store of D5 — every one
of them app-scoped and handed in, never constructed by the tab, so no surface reaches a channel's
fold twice.

`AgentsModel: PanelTabSession`, one per (tab, channel), retained by the host: the tree read, the
selected node, the per-run renderer and its collapse state, and the pane's scroll position. The
host retains it, so switching channels and back keeps the selected run and the scroll — which is
the whole reason X7 has sessions.

### The tree read

One value per publication, derived from `ChannelTimeline` in one read: the ordered roots, each
node's drawn content (type, badge, status, elapsed origin, activity line, parked flag, waiting
count), and its children. Derived, not stored: the tree is C3's and this leaf keeps no copy that
could drift. Recomputed when `agentsChanged` says the tree moved, and not on every streaming
delta — the same discipline C6.1's `neighbourhood` follows for the same reason.

### The transcript pane

`TimelineRenderInput` over the filtered rows (D4) into a `NativeTimelineRenderer` the session
owns, with a `TimelineRenderContext` the pane builds: the same `links`, `signal`, `decisions`,
`lifecycle` and `retraction` the channel column passes, plus the run's authorship and badge, and
**no composer site** — a subagent transcript is not a place to type, and Y6's *Edit* on a
subagent's user message would rewind the main conversation.

### The relay (item 51)

`AgentRelayRegistry`, app-scoped, one record per *Send message*: the prompt uuid `sendPrompt`
returns, the target run id, a hash of the text (never the text, in any report), the state, the
model's reply on a refusal arm, and the retry lineage. It advances from the frames C3 already
reduces — a `SendMessage` `tool_use` whose input names the target id, its `tool_result`, the
target run's items gaining the text, the target's `task_notification` — and from `result`, which
is what closes a turn with no call. It concludes *Delivered* only on the text appearing in the
agent's transcript, correlated one-to-one, because that is the decision log's rule and the
premature conclusion is the defect the arms are written to catch.

### What this child does not build

No reducer (§7.3). No second timeline model, no second wire subscription, no second registry
mirror. No agent colour: nothing on the wire carries it and the sidecar does not on this
baseline (parity §18, top gap 3); reading the agents' markdown frontmatter is a later item and
is filed as such. No `subagentStatusLine` execution (parity §18.32, top gap 10). No
host-initiated resume: none exists (parity §18.25), which is exactly why *Send message* carries
a delivery state at all.

## `[parent-impact]` — item 51's fourth arm is not an error result, and the engine says so

**Finding.** Acceptance item 51 names its third failure as "when the tool result is **an error**
because the resume was refused", and §8.8 carries the same reading. The pinned bundle does not
agree. `SendMessage`'s stopped-by-user branch returns `{data: {success: false, message: …}}` and
the result mapper `JSON.stringify`s it into one text block exactly as it does a success
(`cli.pretty.js:774468`, `:774612`, `:774891`/`:774893`); `is_error` is set only for the tool's
*validate-input* refusals (`:114646`). So a relay to an agent the user had stopped comes back as
a **non-error** `tool_result` whose body says `success: false`.

**Why it matters more than a wording slip.** A host that reads `is_error` alone concludes
*Relayed* and leaves it there for ever — the false-positive direction, and the reassuring one:
the surface tells the user their message is on its way to an agent that will never receive it,
which is precisely the silent non-delivery item 51 exists to make visible. This child now reads
the result body as well as the flag, with two discriminating tests and a fixture whose arms 1
and 4 are two non-error results differing only in that field.

**Asked of the parent.** Item 51's third failure re-worded from "the tool result is an error" to
"the tool result reports the resume refused", and §8.8's *Send message* paragraph with it. The
`is_error` reading stays correct for the tool's own input refusals, which is a different arm.
Found at C6.4 Task 8, from the bundle rather than from the prose.

## `[parent-impact]` — X4's tree has no correction source and its mirror is unpublished

**Finding.** Contract X4 names "the agent-run tree node (task id, type, model, status, depth,
parent, activity line, elapsed origin) and the registry mirror entry" as FleetKit types, and
§8.8 says the parent link "comes first from the `agent_metadata` entry the engine mirrors at the
head of the agent stream … the two-step join is the fallback". In the shipped code the primary
source is never consulted: `AgentRunTree.apply(agentMetadata:for:)` and `apply(metaFile:)` have
no production caller, `StreamIngestion` routes the decoded record to the item side only, and the
registry mirror is not on `ChannelTimeline` at all. Two consequences bind this child: the
composite's G1 clause "corrected by it afterwards" is unassertable, and §8.8's eligibility rule
for *Move to background* on a node cannot be answered. A third binds recomposition: an archived
or foreign channel has no tree, so the Agents tab is empty for every channel afleet opens from
disk. Tracker 187 and 321 record the first and second; this filing is that they are now blocking
a gate rather than deferred.

**Asked of the parent.** A C3 corrective on `main` in the shape both tracker entries already
state — the ingestion feeding its metadata into the tree through the two existing tested entry
points and owning a file-only tree where there is no wire, and `ChannelTimeline` carrying the

## `[parent-impact]` — contract Y3 says `.agents` is taken by a handover; nothing holds it

**Finding.** Y3 reads "C6.3 takes `.thread` by `unregister(.thread)` then
`register(ThreadTab(lifecycle:))`, and **C6.4 takes `.agents` the same way**." It is not the

**Asked of the parent.** Y3's second clause corrected to: C6.4 *registers* `.agents`, plainly,

## Parent revisions

0. **Root §8.8's `b412f2e` amendment overstates what the depth-2 recording shows.** It reads
   "on the depth-2 recording the join answers first and the mirror's agreeing answer is retained
   beside it in `parentAnswers`". That is true only when no `.meta.json` is on disk. Opened
