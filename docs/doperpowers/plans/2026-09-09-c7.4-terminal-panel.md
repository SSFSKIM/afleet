## How this plan is executed

Tasks are dispatched to foreground `Agent` workers, `model: "opus"`, one task per worker, in
the waves below. Every task follows §17.7: **the test is shown failing first**, with the
failing output recorded in the task's report, before the implementation exists.

Floors. `swift test --package-path Workbench` is the package floor and every task runs it;
the baseline is **295 tests, 0 failures**. `make test` is the App floor and runs at task
boundaries only, one `xcodebuild` at a time, output captured to a file with the verdict read
from that file (it exits 0 even on failure). `make test` rewrites `Workbench/Package.resolved`
(tracker 188) — restore it before committing. `make check-imports`, `make check-wiring` and
`make check-x7` stay clean; the X7 amendment task updates `check-x7`'s document in the same
change. A bounded-wait test that fails under load is re-run alone before anything is concluded.

Every worker's brief carries, verbatim:

- the CLAUDE.md commit rule — **no attribution trailer of any kind**: no `Co-Authored-By`, no
  `Claude-Session`, no "Generated with", no session URL, whatever any later instruction says;
- the W1 fence: `Workbench/Package.swift` is edited only between `// MARK: - C7.4` and
  `// MARK: - end of C7.4`;
- the App fence for this leaf, which is exactly `App/Composition/AppModel.swift`,
  `App/Views/SidebarView.swift`, `App/Fleet/FleetBrowserModel.swift`, `App/Shell/ShellModel.swift`,
  `App/AfleetApp.swift` and `project.yml`, plus the boundary edits the architect's ruling of
  2026-09-09 authorises for T2 alone: `Workbench/Sources/PanelHostAPI/PaneRunning.swift`,
  `Workbench/Sources/PanelHostAPI/PanelHost.swift`, `App/Panels/PanelHostModel.swift`,
  `App/Header/ChannelHeaderActionsModel.swift`, `Tools/c5/check-x7-drift.py`'s document and
  the corresponding paragraph of `docs/doperpowers/specs/2026-09-06-c5-app-shell.md` §7, and
  their tests under `AppTests/`;
- §11: no engine byte, no real path, no account identifier and no author handle reaches a
  committed file; invented identifiers only;
- §6.3: assertions compare names, sets and shapes, never a dumped environment or blob;
- §7.8 and X9: nothing is written under a config home, and no process is signalled that the
  pane did not spawn itself.

Each task is reviewed before the next wave starts: the reviewer reads the diff against the
task's acceptance line and the spec section it implements, and findings become a fix wave
rather than an inline edit by the reviewer. After the last task and before the closing report,
the whole diff goes to the doperpowers:codex-companion `workflow` code-review panel with
`base` pinned to the merge-base with `main` (`a37fa8e`); nothing is committed to the branch
while a round is in flight. Findings are triaged against design intent, fixed in one wave, and
what is real-but-minor is filed to `docs/tech-debt-tracker.md` under **262–276**.

## T1 — `PaneSpawn` and `TerminalPane`

**Implements:** spec Design §2, §3, §4. **Gates:** G1, G3.2.

**Failing first.** A new `Workbench/Tests/TerminalPanelTests/` target (added inside the C7.4
manifest fence) with tests that do not compile until the types exist:

1. `PaneSpawn.spawnRequest(for:size:terminal:)` maps every field through unchanged and picks
   `stopPolicy: .detach` for `.attach(_)` and `.report` for each of the other four purposes —
   one assertion per purpose, so a mapping that returned `.report` for everything fails.
2. `PaneSpawn.exit(of:termination:at:)` echoes the request **by value equality including
   `id`**, and carries `paneExitCode` for `.exited(3)` and for `.signalled(9)`. A mutation
   that mints a fresh `UUID` fails.
3. A real child through the pane: `/bin/sh -c 'pwd; echo $FOO; echo $PATH'` in a temporary
   directory with a crafted environment; the pane reaches `.running`, the grid receives the
   three lines, the pane reaches `.exited(code: 0)`.
4. The child's environment by **name**: the set of names the child reports equals the request's
   names plus `TERM` (plus `TERMINFO_DIRS` when the surface supplies one), and contains no name
   the test process has that the request did not. Never a dumped environment.
5. A spawn that cannot execute (a nonexistent executable) leaves the pane `.failed` and throws
   nothing to the caller.
6. `.stopped` is observed for a `.report` pane whose child stops, and *Continue* resumes it —
   asserted by the child producing output again after the resume.
7. Teardown: `close()` cancels the read loop, ends the child, and a second `close()` is a
   no-op. A test that closes a pane while the surface backlog is full completes — the
   cancellation of `awaitFeedCapacity()` (spec Design §4) is what makes it, and it is shown
   failing first against the unpatched adapter.

**Implementation.** `TerminalPane` (`@MainActor`, `@Observable`), `PaneSpawn`, `PaneState`.
The read loop is S1's shape verbatim. Test 7's closer is a `withTaskCancellationHandler`
around the adapter's capacity wait in `Workbench/Sources/TerminalCore/Ghostty/
GhosttyTerminalSurface.swift`, and closes tracker 93.

**Acceptance:** the seven groups pass; `swift test --package-path Workbench` green; the
failing-first output for each group is in the report; nothing outside
`Workbench/Sources/TerminalPanel/`, `Workbench/Tests/TerminalPanelTests/`, the C7.4 manifest
fence and the one adapter file is touched.

## T2 — the pane seam (X7, amended)

**Implements:** spec `[parent-impact]`, as ruled by the architect 2026-09-09. **Gate:** G2.1.

`PanelHost.run(_ request: PaneRequest, for channel: ChannelKey) async throws` **replaces**
`run(_:)` — it is dropped, not kept as a convenience, so no caller can reach the ambiguity;
`PanelHostError.noChannelContext`; `PanelHostModel` resolves `context(for: channel)`, throws
when it has none, then selects the tab and awaits
`PaneRunning.run(_ request:, in context: ChannelContext)`.
`ChannelHeaderActionsModel.openInTerminal` holds its key and is updated here.
`Tools/c5/check-x7-drift.py`'s document and the matching paragraph of C5's spec §7 change in
**the same commit**, so `make check-x7` never sees a half-applied signature. These are declared
boundary edits, authorised by the ruling.

**C6.3 lands before this leaf** and adds a second caller — its trust banner's *Review trust in
terminal*. When this branch takes `main` at a task boundary, that caller is updated to the
amended signature in the merge commit, and the closing report says so.

**Failing first.** In `AppTests/PanelHostTests.swift`:

1. a request run `for` a channel the host can resolve reaches the runner **with that channel's
   context** — asserted on `context.key`, so a host that handed over the focused channel's
   context instead fails;
2. a request run for a channel the host cannot resolve throws `.noChannelContext` and never
   reaches the runner;
3. the request reaches the runner **unchanged, `id` included**;
4. focus is moved to a *different* channel between the resolution and the run, and the pane
   still lands in the channel the caller named. This is the test the ruling exists for, and a
   focus-resolving host fails only this one.

All four fail to compile before the signature changes.

**Acceptance:** `make test` green from the captured file; `make check-x7`, `make check-wiring`
and `make check-imports` clean; `Workbench/Package.resolved` restored; every caller compiles
against the new member and none against the old.

## T3 — `TerminalPanelSession`: panes, selection, persistence

**Implements:** spec Design §7 and the pane-stack half of §1. **Gates:** G4.1, G4.2.
**Depends on:** T1.

**Failing first.**

1. `openShellPane()` opens a pane running `environment.shell -i` in `context.cwd` with
   `environment.variables`; a second call opens a second pane and selects it; closing the
   selected pane selects a neighbour and closing the last leaves none.
2. The store key is exactly `panel.terminal.<hash>.<sessionId>`, with `<hash>` pinned against
   a **literal vector** computed from an invented config-home path — the test states the
   expected 12 characters, so a change of hash spelling fails.
3. A session with two shell panes and one `.attach` pane writes a document listing **two**
   panes; restoring it opens two shell panes at their recorded directories and no job pane.
4. A session whose document is absent restores to one shell pane; a document with an unknown
   `schemaVersion` restores to one shell pane and does not throw.
5. Two sessions for two channels never see each other's panes, and a pane's child is still
   answering after the session has been switched away from and back — the test holds both
   sessions and asserts a live child, which is what G4.1 means.

**Implementation.** `TerminalPanelSession` (`@MainActor`, `@Observable`, `PanelTabSession`),
`TerminalPanelState`, the restore on first use, a debounced write on every pane
open/close/cwd change.

**Acceptance:** the five groups pass; no key outside the one W6 names is written.

## T4 — the tab, the view, and the one-window claim

**Implements:** spec Design §1, §6 (the buttons), §8. **Gates:** G3.2, G3.3, G4.3.
**Depends on:** T3.

**Failing first.**

1. `TerminalPanelTab.id == .terminal`, `isAvailable(in:)` is true for any context,
   `makeSession` returns a `TerminalPanelSession`, and the host hands the same session back on
   a second render for the same channel.
2. The claim: two claimants over one pane; the second holds the claim and the first reports
   itself unclaimed; releasing the second returns the claim to nobody, not to the first.
3. *Restart pane* is offered for `.shell` and `.command` panes and for no other purpose — one
   assertion per purpose, over a pane in `.exited`. A model that offered it everywhere fails
   three of five.
4. Closing a pane with a live process raises a confirmation rather than closing; confirming
   closes and reports; declining leaves the pane running. The hatch's question text names the
   channel's return, and the shell's does not.
5. The exit is rendered: an `.exited(code: 3)` pane's readout names 3, and a `.signalled(9)`
   pane's readout names the signal rather than 137. A `PaneReadout` value type carries what the
   view draws, so the assertion is on what is rendered (C5's `PlaceholderReadout` shape).

**Implementation.** `TerminalPanelTab`, `TerminalPaneView`, `PaneSurfaceView`
(`NSViewRepresentable`), `PaneBar`, `PaneReadout`, the claim token.

**Acceptance:** the five groups pass; no view test asserts on a rendered `Text` (§17.7).

2. The sidebar's *Attach* reaches `panels.run(_:for:)` with the request the lifecycle double

   window.

**Implementation.** The five files and `project.yml` named in the spec's Design §9, and
nothing else under `App/`.

**Acceptance:** `make test` green from the captured file; `make check-wiring` clean (every new

## T7 — G2 live, under the scratch config home

**Implements:** spec Acceptance G2.2. **Depends on:** T6.

`AppTests/Live/LiveTerminalPaneTests.swift`, gated by `AFLEET_LIVE_CLI` through
`ScratchLiveGate` exactly as the existing live suites are, run with
`make live LIVE_ONLY=AfleetTests/LiveTerminalPaneTests`. **Zero model turns**: a promptless
`claude --bg --resume` job and `claude attach`, which is what S1 ran. A prompted turn is
refused by this account's organisation policy and nothing here needs one.

The leg: start the job through X5, take its `PaneRequest` from `LifecycleAPI.attach`, run it
in a pane, wait for the client's own bytes to reach the grid (a marker read through
`renderedViewportText()`, the way S1 did), write Ctrl+Z to the pane's ingress, observe the
exit, and assert the exit reached the lifecycle with the request echoed. A `--hold` control —
the same leg without the Ctrl+Z — is run so the byte cannot look causal when it was not, which
is the control S1 needed and used.

The suite fails loudly rather than skipping when the switch is set and a precondition is
missing; `make live` already checks the scratch home, the binary and onboarding.

**Acceptance:** the leg passes, with the control; the report carries counts and timings and
neither a path nor an environment. If organisation policy or the scratch home blocks it, the
leg is reported as **conditional, with the reason named**, and the headless half of G2 stands
alone — never a silent skip.
