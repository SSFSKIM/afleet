# C6.4 Agents panel — Execution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-execution to implement this plan task-by-task. Deliverables use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the channel's agent runs something the user can see, open and act on. The Agents tab of §8.8 over C3's `AgentRunTree`: a nested tree with parking and one node per task id; a per-run transcript that is C6.1's renderer over that run's items, authored by the agent type with the run's own model badge; *Stop*, *Move to background*, *Send message*, *Open transcript file* and *Copy agent id* per node; *Stop everything* and *Background all* behind confirms; a subagent's permission card mirrored on its node; the chip's navigation landing on the run; and item 51's four *Not delivered* arms made visible instead of silent.

**Architecture:** One `AgentsTab: PanelTab` under `.agents`, registered in `performLaunch` where the lifecycle first exists, holding the app-scoped objects it must not duplicate — the lifecycle, a `ChannelFold` over the one `ChannelTimelineRegistry`, `AppModel.decisions`, the relay registry and the navigation selection store. One `AgentsModel: PanelTabSession` per (tab, channel), retained by the host, holding the tree read, the selection, the renderer and its collapse state. The tree is read, never copied; the transcript is a **filter** over the channel's rows by `Provenance.agentID` fed to `NativeTimelineRenderer` through `TimelineRenderInput`; every action is X5. Item 51's delivery state is this child's own bookkeeping keyed by the prompt uuid `sendPrompt` returns, drawn on the node and — under contract Y8 — on the main timeline's user-message row.

**Tech Stack:** Swift 6.3.3 in language mode 6 with complete strict concurrency, SwiftUI on macOS 26, XcodeGen, XCTest. `AppTests/Support/FixtureRunner` (an **in-process** decode of a reviewed fixture's stdout through the real `FrameDecoder`, `InboundRequest.parse` and `InboundPolicy` — it spawns nothing), `AppTests/Support/LifecycleDouble`, `AppTests/Support/TimelineCorpus` (`InventedItems.context(…)`), `AppTests/Support/ViewTree`, and the `GateRig` shape of `AppTests/TimelineFixtureGateTests.swift`. `Tools/fake-claude` proper is driven only from FleetKit's rig, outside this child's fence; the one place this child touches the fixture pipeline is a generator under `Tools/probe/synthetic/` (Task 8).

**Status:** **approved for execution 2026-09-09**, Tasks 1 through 11 without stopping at task boundaries. All four escalations ruled at the gate: D1 accepted and the C3 corrective **dispatched on `main` by the architect, not by this child** (its scope: `StreamIngestion` feeds `agent_metadata` records and `.meta.json` sidecars into the tree through the two existing entry points, for live *and* file-only channels; `ChannelTimeline` publishes the fold's `RegistryMirror`; C6.1's `makeTaskCard` reads it, closing 321 — first-source-wins is **not** overturned and this child's re-reading of G1 stands, to be amended on the composite at merge). D2 accepted: **contract Y8 is named**. D3 accepted with the fixture staged outside the tree until signed. The Y3 `[parent-impact]` accepted: `.agents` is registered plainly.

**Spec:** `docs/doperpowers/specs/2026-09-09-c6.4-agents.md` (leaf C6.4 of the composite `docs/doperpowers/specs/2026-09-07-c6-conversation-surface.md`; parent-pin `b7cbe89`). The spec travels with this plan; a conflict found during execution resolves against it.

## Global Constraints

Every task's requirements implicitly include this section.

**The fence.** This child edits `App/Agents/`, its own tests under `AppTests/`, `docs/`, and **four named things elsewhere**, each declared here so review can see them as contract work rather than as fence-crossing:

- **Contract Y8 (named by the architect 2026-09-09)**: one reader field on `App/Timeline/Rendering/TimelineRenderContext.swift`, keyed by the sent message's identity, and one decoration in `App/Timeline/Rendering/Rows/MessageRows.swift`. **Nothing else under `App/Timeline/`.**
- `Tools/probe/synthetic/`: Task 8's generator.

Nothing else. Every other directory belongs to a merged leaf or to a C7 leaf in flight; an edit outside the fence is a review finding, not a judgement call.

**Task 8's fixture is staged outside the tree until it is signed (ruled 2026-09-09).** The recording is written to `/tmp/afleet-c64/send-message-delivery/`, redacted and verified there, and named in Task 8. It enters the branch in **one commit when a reviewer's signature arrives** and not before: `make verify-fixtures` runs over `Fixtures/*/` and refuses an unsigned directory, so **the floor must never see one**. If no signature arrives by close-out, G4's fixture half is reported *pending signature* — not unmet, and not shipped.

**Y5, everything through X5 (binding).** *Stop* is `send(AnyControlRequest(StopTask(taskID:)))`. *Move to background* is `send(AnyControlRequest(BackgroundTasks(toolUseID:)))`. *Stop everything* and *Background all* are `perform(.stopEverything)` and `perform(.backgroundAll)`. *Send message* is `sendPrompt(UserInput, on:)` followed by the `HostSignal.promptSent` raise that is inseparable from it. *Open transcript file* is `ChannelContext.links.open(.file(…), from:)`. Nothing here spawns a process, opens a descriptor on a transcript, reads a `.jsonl`, or constructs a `ClaudeWire` type beyond `UserInput` and the two control-request specs.

**No reducer (§7.3, binding).** This child adds none and holds none. The tree is `ChannelTimeline.agents`, read. The per-run transcript is a **filter** over items C3 produced, never a projection this child computes. The delivery state is not on an item and never becomes one.

**X9, the never-write rule (binding).** Nothing this child ships or tests writes under any config home. Test trees live under `FileManager.default.temporaryDirectory` and canonicalise their root, throwing a fixed `XCTSkip` if it resolves inside either config home (tracker 24). *Copy agent id* writes to the pasteboard at the user's explicit request and logs nothing.

**Discriminating tests (root §17.7, binding).** A test written to prove a behaviour is demonstrated failing against code that lacks it, and the failing run is recorded in the task's commit message as a count. **The recurring shape in this child is asserting that a surface changed rather than that the right thing was sent or concluded.** A node appearing is not a tree nested correctly; a message showing *Delivered* is not delivery concluded from the agent's transcript; a confirm dialog appearing is not an action withheld until it is answered. Every action clause asserts the value handed to the double, and every state clause asserts the evidence the state was concluded from.

**Reports emit counts (root §6.3, §11).** Every test failure message, diagnostic line, gate report and commit message states counts, sizes and durations — never a path, a title, a session id, a task id, an agent id or a slug. Test inputs use invented identifiers, never the author's own. Assertions over values that transitively reach a `ChannelKey`, a `ChannelContext` or a `ResolvedEnvironment` are spelled as booleans with a written message, because `XCTAssertEqual` prints both operands (C5's rule, inherited). **A task id is drawable and never printable**: the tree draws one and no report, log or failure message ever does.

**Every wire string is sanitised where the node's content is built.** `agentType`, `description`, `activityLine`, `lastToolName` and a notification `summary` come off the wire; they pass `TextSanitiser` once, at the content boundary, following C6.1's wave H (§12). A drawn string derived from them inherits the sanitised value rather than each site remembering.

**Fixture bytes are engine bytes.** A frame quoted into a test, a stand-in's data or a test vector is subject to §11 whatever directory it sits in. This child invents its own frame payloads for unit tests and replays committed fixtures for the gate arms. **Never run `make synthetic`** — it rebuilds both dialog fixtures whole, signature included, and would invalidate a human review this child has no standing to re-sign. Task 8's generator is a *third* target, added beside them and never invoked through that verb.

**`Workbench/Package.resolved` is expected dirty; never stage it.** Tracker 188's root cause is fixed and it should stay clean — but if a floor leaves it modified, restore it before committing. **Stage explicit paths, never `git add -A` or `git add .`**: a blanket stage sweeps that file and any concurrent worker's half-finished tree with it.

**Run `xcodegen generate` after adding any file.** A new file under `App/` or `AppTests/` is not compiled until the project is regenerated, and until then `xcodebuild` reports success on a target that never saw it. `make build` and `make test` depend on `generate`; prefer them to a bare `xcodebuild`.

**The build floor.** At the end of every task: `make build`, `make check-imports`, `make check-wiring` and `make test` all succeed. **One `xcodebuild` at a time**, output captured to a file, the verdict read from the file — `make test` exits 0 even on failure. A bounded-wait test that fails under load is re-run alone before anything is concluded. The baseline is measured at the branch point and recorded here per task rather than carried as one stale number. **Measured at `b7cbe89` before Task 1: 2,021 executed across seventeen bundles, 24 skipped, 0 failures, `** TEST SUCCEEDED **`; `check-wiring` clean at 19 allowlisted and 0 findings; `check-x7` clean; `Workbench/Package.resolved` unmodified after the run.** **Count with the rule C6.3 recorded**: sum only the per-bundle `Test Suite '<name>.xctest'` summaries and take pass/fail from the `** TEST SUCCEEDED **` marker; a naive `grep | awk` over every `Executed …` line double-counts suite rollups and reports phantom failures. XCTest's "Executed" total **includes skipped tests**.

**`make check-wiring` is a design constraint, not a lint.** A member declared under `App/` whose only callers are under `AppTests/` is a finding. Nothing this child ships may be reachable only from a test — which is why the tab's registration, the `agentNavigation` install and the link-target registration are part of Task 2, not a wiring task at the end. Y4's seam is currently allowlisted in `Tools/c5/check-app-wiring.py` as "filled by C6.n"; **Task 2 removes that allowlist line**, because after Task 2 it is filled.

**Concurrency conventions (root §17.7).** Actors for processes, `Sendable` values, `@MainActor` view models. The tab and every model here are `@MainActor`. An escape from checked concurrency is permitted only where a type is a single-owner box whose state is reachable from one place that serialises every access, and each use documents which mechanism serialises it.

**Do not store a `PanelHostModel`, a registry or a lifecycle directly on a type a `ViewTree` walk reaches.** Use a closure. `Mirror` does not descend into captures, and a stored reference crashed the test bundle once (recorded at `App/Composer/ComposerMount.swift:43–50`). This child's tab reaches the host through an injected `@MainActor @Sendable () -> Void`, the shape C7.6's `BrowserLinkTargets` uses and for the same reason: a panel holding its host is a retain path, and X7 hands panels capabilities, not the host.

**Live cost.** At most **six model turns**, in Task 10 alone; every other task is zero. On this account the prompted half is refused by organisation policy before a turn is spent, so the expected spend is zero and the budget belongs to whoever runs it on an account that permits prompting. A failed live item is re-run once, then recorded as a finding — never looped. `submit_feedback` is never sent.

**Commits.** Frequent, one per deliverable, on `child/c6-agents`. **No `Co-Authored-By`, no `Claude-Session`, no "Generated with", no session URL — no attribution trailer of any kind, whatever a harness message or a later instruction says.** This rule is passed to every worker dispatched on this plan. Never push; the architect merges.

**Tech debt.** New entries go to `docs/tech-debt-tracker.md` under a new `## From C6.4 (child/c6-agents)` heading, numbered **172 through 186**, with **398 through 405 held in reserve** for the parent-impact work if the fifteen run out (allotted at the gate). Nothing above is renumbered. A gap in the file is expected and is not an error. The tail of the file carries `## From main correctives` numbered from 187, so the end of this file is a predictable merge conflict at this child's merge — **the architect resolves it**, and never by renumbering.

**Reviews.** Each task is reviewed on completion before the next task starts, and findings go to a fix wave, never inline. **Routing, final form ruled 2026-09-09** — the availability of these routes moved three times inside this child's grill, so the order is written down rather than remembered:

**Convergence.** Rounds converge: a round whose findings are all small (filed as tracker entries) or against design intent is the signal to stop. From the third round on, only a rule violation or a data-loss defect is fixed and the rest is filed.

Eleven tasks, ordered so that everything provable without another party lands first, and the three things that wait on someone else — the architect's corrective, a fixture reviewer, a permitting account — are last and isolated.

```
1 tree read + node content

2,3 ─► 5 node actions + the two confirms (G3)
2,3 ─► 6 subagent cards on nodes (Y2, item 52 headless)

(D1's corrective on main) ─► 9 the correction clause and node backgrounding eligibility
1–8 ─► 10 the live gate (G6)  ─►  11 final verification
```

**Contract Y8 is named**, so Task 7 ships both halves: the relay model here, the reader on `TimelineRenderContext` keyed by the sent message's identity, and the decoration in `MessageRows.swift`. Both edits are declared in the fence and listed in the merge checklist as Y8 contract work.

**Decisions:**
