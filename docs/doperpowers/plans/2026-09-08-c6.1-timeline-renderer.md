# C6.1 Timeline renderer — Execution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-execution to implement this plan task-by-task. Deliverables use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace C5's placeholder list with the conversation surface: an `NSTableView`-backed, bottom-anchored, virtualized timeline that renders every `TimelineItem` kind but `decision` and `sentFile`, streams at thirty updates per second with markdown and highlighted code, folds clusters and thinking, navigates from an `Agent` chip to its run, emits file links from tool rows, and reads back the channel's model, mode, effort and context above it.

**Architecture:** `ChannelTimelineModel` (C5's, extended) gains a second `LifecycleAPI.events(of:)` subscription feeding one C3 `WireReducer` per channel, so the app finally has an overlay and a streaming preview; it publishes `ChannelTimeline(durable:overlay:preview:)` where durable is `StreamIngestion`'s and the wire reducer's own durable half is discarded. `App/Timeline/Rendering/` holds one `TimelineRendering` protocol, a `NativeTimelineRenderer` behind it, the markdown and highlighting pipelines behind content-keyed caches, and the twelve row builders C6.1 claims in Y1's registry. `App/Timeline/Header/` holds the readout value and its view. Everything expensive — markdown parsing, syntax highlighting, attributed-string construction — happens off the SwiftUI body and off the main thread, cached by content hash.

**Tech Stack:** Swift 6.3.3 in language mode 6 with complete strict concurrency, SwiftUI and AppKit on macOS 26, XcodeGen, XCTest, `swift-markdown` (Apple, Apache-2.0), `PhraseHQ/HighlightKit` (MIT), the twenty fixtures under `Fixtures/`, `Tools/fake-claude`.

**Status:** draft, 2026-09-08. Held at the architect's gate with the spec; not approved for execution.

**Spec:** `docs/doperpowers/specs/2026-09-08-c6.1-timeline-renderer.md` (leaf C6.1 of the composite `docs/doperpowers/specs/2026-09-07-c6-conversation-surface.md`; parent-pin `5e24f1a`). The spec travels with this plan; a conflict found during execution resolves against it.

**§11's leak rule reaches into assertion choice.** `XCTAssertEqual`/`XCTAssertNotEqual`/`XCTAssertNil` print both operands, and a struct prints every field it transitively holds. **Discriminating tests (root §17.7, binding).** A test written to prove a fix is demonstrated failing against the pre-fix code before the fix is accepted, and the demonstration is recorded in the task's report. Where the break cannot be executed, the substitute is a trace assertion that the dangerous path was never entered, stated as such in the test's own comment.
