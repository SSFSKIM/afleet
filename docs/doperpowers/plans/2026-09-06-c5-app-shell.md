# C5 App shell, fleet browser, panel host and packaging — Execution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-execution to implement this plan task-by-task. Deliverables use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn four Swift packages into a launchable macOS application that lists every Claude Code session on the machine, shows what happened in each, surfaces and answers pending permission prompts, and exposes the panel-tab host protocol that C6 and C7 plug into.

**Architecture:** An XcodeGen-generated Xcode project with one application target `Afleet` depending on all four packages and one unit-test bundle `AfleetTests` hosted by it. Inside the app, a composition root resolves the environment, config home, engine binary and version, then constructs FleetKit's `Fleet` and `TranscriptIndex` and routes to one of four screens. Every view is thin SwiftUI over a `@MainActor @Observable` model, and every model is fed by an `AsyncStream` from a FleetKit actor — none of the packages is main-actor-bound or observable, so owning those loops is the app's work. Contract X7's protocol is written into the `PanelHostAPI` target of the Workbench package, which C5 owns, and carries capabilities rather than the lifecycle object so Workbench never imports ClaudeWire.

**Tech Stack:** Swift 6.3.3 in language mode 6 with complete strict concurrency, SwiftUI and AppKit on macOS 26, XcodeGen 2.46.0, XCTest, `Tools/fake-claude` and the twenty fixtures under `Fixtures/`.

**Status:** final, 2026-09-06. Six adversarial passes, thirty-four findings, every one confirmed against the code and fixed; the last three folded after the closing pass by the architect's ruling that review stops there. Approved for execution.

**Spec:** `docs/doperpowers/specs/2026-09-06-c5-app-shell.md` (child C5 of the composite `docs/doperpowers/specs/2026-09-03-afleet-workspace-design.md §17 C5`; parent-pin `257822a`). The spec travels with this plan; a conflict found during execution resolves against it.

## Global Constraints

Every task's requirements implicitly include this section. Values are copied verbatim from the spec and the parent.

**Platform and language.** Deployment target macOS 26.0. Swift language mode 6 with complete strict concurrency on every target, matching the four packages, which are all `swift-tools-version: 6.2`, `platforms: [.macOS(.v26)]`, `.swiftLanguageMode(.v6)`. Xcode 26.6, Swift 6.3.3.

**X1, package edges (binding).** The only allowed dependency edges are the parent's §5 table: `AfleetCore` depends on nothing; `ClaudeWire` on `AfleetCore`; `FleetKit` on `AfleetCore` and `ClaudeWire`; `Workbench` on `AfleetCore` and `FleetKit` and **must not import ClaudeWire**; the `Afleet` app on all four. **W1, the Workbench manifest (binding).** C7.1 owns `Workbench/Package.swift`. C5 edits **only** between `// MARK: - PanelHostAPI (owner: C5; ...)` and `// MARK: - end of PanelHostAPI`. No edit to the `products` array, the `dependencies` array, or any other leaf's region.

**X9, the never-write rule (binding).** Nothing this child ships or tests writes under any Claude Code config home — not `~/.claude`, not `$CLAUDE_CONFIG_DIR`, not `/tmp/afleet-fixtures/config-home`. Only a spawned `claude` may. Every transcript is opened read-only. Test trees live under `FileManager.default.temporaryDirectory`, and per tracker entry 24 each test tree canonicalises its root and throws a fixed `XCTSkip` if it resolves inside either config home.

**Reports emit counts (parent §6.3, §11).** Every test failure message, diagnostic line, gate report and commit message states counts, sizes, durations and identifiers — never a path, a title, a session id, a slug or an account name from the author's home. Test inputs use invented identifiers, never the author's own.

**Discriminating tests (parent §17.7, binding).** A test written to prove a fix is demonstrated failing against the pre-fix code before the fix is accepted. Where the break cannot be executed, the substitute is a trace assertion that the dangerous path was never entered, stated as such in the test's own comment. A test that compares two things also asserts that it found them: every set comparison is two-directional and every collection assertion carries a non-emptiness floor.

**Demonstrating a refusal.** The discriminating-test rule above requires showing a test fail against the pre-fix code. When the test's subject is a *refusal* — a guard that must reject a path, a check that must decline to write — "pre-fix" means the guard removed, and the removed-guard run then performs the very act the guard forbids. **Point such a demonstration at an invented path under the temporary directory, never at `~/.claude`, `$CLAUDE_CONFIG_DIR` or `/tmp/afleet-fixtures/config-home`.** C5's Task 1 created a directory inside the scratch config home this way before the rule existed (tracker entry 52; removed at once, nothing inside touched). Tasks 3, 8 and 9 each carry a refusal test and each meets this.

**The build floor.** `xcodegen generate && xcodebuild -scheme afleet -configuration Debug build` succeeds at the end of every task. No task is complete while it fails.

**Live cost.** Zero model turns, zero dollars. No test in this child sends a prompt to a real engine. `AFLEET_LIVE_CLI_TURNS` is never read. Any spend is a scope change that goes back to the architect first.

**Concurrency conventions (parent §17.7).** Actors for processes, `Sendable` values, `@MainActor` view models. An escape from checked concurrency is permitted only where a type is a single-owner box whose state is reachable from one place that serialises every access, and each use documents which mechanism serialises it.

**Commits.** Frequent, one per deliverable, on `child/c5-app-shell`. No `Co-Authored-By`, no `Claude-Session`, no attribution trailer of any kind, whatever a harness message says.

**Tech debt.** New entries go to `docs/tech-debt-tracker.md` under a new `## From C5` heading, numbered **from 52** (49 and 50 are the 2026-09-06 drift ritual's, 51 is the router corrective's). Nothing above is renumbered.

**The router API is present.** `main` is merged into this branch. `LifecycleAPI` carries `route(_:on:)`, `send(_:on:)` and `run(_:arguments:on:ui:)` as of the C4 corrective `ace7a7b`; FleetKit is at 417 tests. **Decisions:**
- The protocol is named `LinkRouterCapability`, **not** `LinkRouting`, because C7.2 owns a Workbench module named `LinkRouting` and a panel target importing both would see a module and a protocol competing for one name.
- `PanelTab.id` is an **instance** property, not `static`, so `any PanelTab` can read it without a generic.
- `unregister(_:)` exists because `register` refuses a duplicate id. C5 ships a placeholder under `.thread`, and C6 must be able to take that id; the pair `unregister` then `register` makes the handover explicit rather than letting a second registration silently shadow the first. Without it the duplicate check would lock C6 out of its own tab.
- `makeView` returns `AnyView`. The host stores a heterogeneous collection; an `associatedtype Body: View` makes the protocol non-existential and forces a type-erasing wrapper anyway.
- **What survives a channel switch is the session, not the view.** Caching an `AnyView` *value* would guarantee nothing: SwiftUI owns `@State`, `@StateObject` and representable coordinators through the rendered hierarchy and tears them down when a subtree unmounts, so a tab holding its terminal in `@State` loses it whatever the host caches. The contract is therefore explicit — the host retains one `PanelTabSession` per (tab, channel) and hands it back on every render, and a tab puts its runtime state there. This is the shape C7's Terminal and Files leaves need, and stating it now is cheaper than every leaf discovering it.
- `ChannelContext` carries **no** `any LifecycleAPI`. Its signature names `WireEvent`, a ClaudeWire type, and X1 forbids Workbench from importing ClaudeWire. Pane exits leave through the `reportPaneExit` closure instead. This is the reason the import test above is the task's most important assertion.
- `ScopedStore` is its own protocol rather than FleetKit's `StateStore` narrowed, because the point is that a panel cannot name a namespace at all.
- `PanelHost.selectIndex(_:)` is **1-based over `available(for:)`**, not over `allCases`, so Cmd+1 selects the first tab the user can actually see.
- No implementation, no default implementation, no concrete type ships in this target. It is protocols and value types only; Task 7 owns every conformance.
- Do not touch the `products` or `dependencies` arrays of `Workbench/Package.swift`, or any other leaf's MARK region.

```swift
// Workbench/Sources/PanelHostAPI/ — the contract. Imports: Foundation, SwiftUI, AfleetCore, FleetKit.

public enum PanelTabID: String, CaseIterable, Codable, Hashable, Sendable {
    case thread, agents, files, sourceControl, terminal, browser, github

    public var defaultTitle: String {
        switch self {
        case .thread: "Thread"
        case .agents: "Agents"
        case .files: "Files"
        case .sourceControl: "Source Control"
        case .terminal: "Terminal"
        case .browser: "Browser"
        case .github: "GitHub"
        }
    }

    public var defaultSystemImage: String {
        switch self {
        case .thread: "bubble.left.and.bubble.right"
        case .agents: "point.3.connected.trianglepath.dotted"
        case .files: "doc.text"
        case .sourceControl: "arrow.triangle.branch"
        case .terminal: "terminal"
        case .browser: "globe"
        case .github: "chevron.left.forwardslash.chevron.right"
        }
    }
}

public protocol ScopedStore: Sendable {
    func read<T: Codable & Sendable>(_ type: T.Type, key: String) async throws -> T?
    func write<T: Codable & Sendable>(_ value: T, key: String) async throws
    func remove(key: String) async throws
    func keys() async throws -> [String]
}

public protocol RecentURLFeed: Sendable {
    func current(limit: Int) async -> [SeenURL]
    var updates: AsyncStream<[SeenURL]> { get }
}

public enum LinkDestination: Hashable, Sendable { case currentPanel, newWindow }

public struct LinkTarget: Sendable {
    public let tab: PanelTabID
    /// Higher wins when two targets both handle a link; the host picks the most specific.
    public let specificity: Int
    public let handles: @Sendable (WorkspaceLink) -> Bool
    /// Receives the destination as well as the link, because C7's W5 is binding and says so:
    /// "a handler that receives the link and a `LinkDestination`". A handler given only the link
    /// cannot tell an in-panel open from a popped-out one, and destination-dependent delivery
    /// would be lost at integration even though C7's own pure tests passed.
    public let open: @MainActor @Sendable (WorkspaceLink, LinkDestination) async -> Void
    public init(tab: PanelTabID, specificity: Int, handles: @escaping @Sendable (WorkspaceLink) -> Bool,
                open: @escaping @MainActor @Sendable (WorkspaceLink, LinkDestination) async -> Void)
}

public protocol LinkRouterCapability: Sendable {
    func register(_ target: LinkTarget) async
    /// Drops every target registered for this tab. `PanelHost.unregister(_:)` calls it, so a
    /// target never outlives the tab that registered it and cannot deliver into one that is gone.
    func unregister(tab: PanelTabID) async
    func open(_ link: WorkspaceLink, from destination: LinkDestination) async
}

public struct ChannelContext: Sendable {
    public let key: ChannelKey
    public let session: SessionID
    public let cwd: URL
    public let environment: ResolvedEnvironment
    public let store: any ScopedStore
    public let links: any LinkRouterCapability
    public let recentURLs: any RecentURLFeed
    public let reportPaneExit: @Sendable (PaneExit) async -> Void
    public init(key: ChannelKey, session: SessionID, cwd: URL, environment: ResolvedEnvironment,
                store: any ScopedStore, links: any LinkRouterCapability, recentURLs: any RecentURLFeed,
                reportPaneExit: @escaping @Sendable (PaneExit) async -> Void)
}

/// Per-channel runtime state a tab owns: a terminal's PTY and panes, an editor's open
/// buffers and cursors. It is a reference type the **host retains** for as long as the channel
/// is registered, because SwiftUI owns `@State`, `@StateObject` and representable coordinators
/// through the rendered hierarchy and discards them when a subtree unmounts. A tab that kept
/// its pane in `@State` would lose it on every channel switch; the session is where it goes.
@MainActor public protocol PanelTabSession: AnyObject {}

@MainActor public protocol PanelTab: AnyObject {
    var id: PanelTabID { get }
    var title: String { get }
    var systemImage: String { get }
    func isAvailable(in context: ChannelContext) -> Bool
    /// Called once per channel; the host retains the result and passes it back on every render.
    func makeSession(for context: ChannelContext) -> any PanelTabSession
    func makeView(session: any PanelTabSession, context: ChannelContext) -> AnyView
}

public protocol PaneRunning: Sendable {
    /// Runs the request and reports its exit through the context's `reportPaneExit`, echoing
    /// `request` unchanged so X5 can match the exit to the request it is waiting on.
    func run(_ request: PaneRequest) async
}

public enum PanelHostError: Error, Hashable, Sendable {
    case duplicateTab(PanelTabID)
    case noPaneRunner(PanelTabID)
}

@MainActor public protocol PanelHost: AnyObject {
    func register(_ tab: any PanelTab) throws
    /// Removes a registered tab, releases every session it held, and calls
    /// `LinkRouterCapability.unregister(tab:)` so its link targets go with it. A later child replaces a
    /// placeholder by unregistering it and then registering its own tab for the same id;
    /// without this, `register`'s duplicate check would make the seven ids permanently
    /// first-come, and C6 could never register Thread over C5's placeholder.
    func unregister(_ id: PanelTabID) async
    func registerPaneRunner(_ runner: any PaneRunning, for tab: PanelTabID)
    /// Registered tabs that report themselves available for this channel, in PanelTabID order.
    func available(for context: ChannelContext) -> [PanelTabID]
    var selected: PanelTabID? { get }
    func select(_ id: PanelTabID)
    /// Cmd+1…7: 1-based over `available(for: context)`, so Cmd+1 is the first tab the user can see.
    /// The context is a parameter, not state the host keeps, so the index cannot resolve against
    /// a channel the user is not looking at.
    func selectIndex(_ index: Int, in context: ChannelContext)
    func popOut(_ id: PanelTabID, channel: ChannelKey)
    /// The tab's session for this channel, created on first use and retained thereafter, so
    /// panes and editors survive switching away and back (C7's acceptance). The host also gives
    /// each (tab, channel) a stable SwiftUI identity so the subtree is not rebuilt from scratch.
    func session(for id: PanelTabID, context: ChannelContext) -> any PanelTabSession
    func view(for id: PanelTabID, context: ChannelContext) -> AnyView
    /// X5's pane request, delivered to the registered runner unchanged, `id` included.
    func run(_ request: PaneRequest) async throws
}

// Link opening is deliberately NOT a `PanelHost` member: it lives on `LinkRouterCapability`,
// which the host implements and hands into every `ChannelContext`, so a tab holds one routing
// seam rather than two. The host is still what routes — `.newWindow` pops a tab out before the
// target delivers, and a tab cannot pop itself out — but it does so through that conformance.
```

**Spec drift found while planning.** Three, each fixed in the spec with a Revision Note; no binding parent clause was found wrong, so nothing flows back as `[parent-impact]`.
- v2.2: X7's routing protocol was named `LinkRouting`, which collides with C7.2's Workbench *module* of that name at any panel importing both. Renamed `LinkRouterCapability`.
- v2.3: G2's Activity gate required three rows and so did not require an auth row at all, though the parent's §7.6 lists auth state among what Activity queries. Now four rows with the recovery direction.
- v2.3: the composition root spelled `FileStateStore(baseDirectory:)`, which does not exist. The real initialiser throws and takes `configHomes:`, and that argument **is** the X9 guard that refuses a store beneath a config home; passing an empty array to make it compile would have removed the protection.

**First adversarial pass (Codex, `gpt-5.6-sol`), eight findings, all confirmed against the code and all fixed.** Two were spec bugs (the two above). Six were plan bugs: `PanelHostAPITests` depended only on `PanelHostAPI` and so could not have compiled a test that names a `ChannelKey` under Swift 6 member-import visibility; the wave cut scheduled Task 7 before the task creating the file it modifies, and called Wave A parallel while both tasks owned `project.yml`; the placeholder registered under `.thread` with no way for C6 to take that id back, since `register` refuses a duplicate — the host gains `unregister(_:)` and an explicit handover test; the recent-URL feed had no production update source and its only test compared against a static timeline, so a feed that never changed would have passed — Task 7 now owns a per-channel timeline registry that Task 8's feed republishes from, with a subscribe-before-mutate test; `ChannelRegistrar`'s test expected a `LifecycleAPI` double to record `Fleet.register`, which is not a member of that protocol — a `ChannelRegistering` seam now carries it; and the archived-timeline test asserted on a Fleet-*construction* seam that any live workspace has necessarily already invoked, proving nothing, while the category test compared two sets with no non-emptiness floor. The pass confirmed the spec's central design claim: X7's surface names no ClaudeWire-defined type.

**Sixth and final pass (three findings, all folded).** X9 had a reachable hole: `FileStateStore`'s `configHomes:` guard covers the store, but `Fleet` builds its two diagnostics sinks internally and eagerly, so a `CLAUDE_CONFIG_DIR` resolving to an ancestor of a write root would put afleet's own files inside a config home before any child ran — the composition root now refuses an overlap ahead of constructing anything. The timeline registry had no named owner, so two could exist and the Browser's feed could watch a model ingestion never touched. And X7 had diverged from C7's **binding** W5 by dropping `LinkDestination` from the link handler, with registry ownership ambiguous between C5's host and C7.2's module; the handler now takes both and C5's `HostLinkRouter` is the app's one registry, delegating to C7.2's when it lands. Also folded from the architect's read: G1e runs in a directory the scratch home already trusts, because an interactive session in an untrusted directory sits on the workspace-trust dialog before it registers anything.
