## How this plan is executed

Tasks are dispatched to foreground `Agent` workers, one task per worker, in the waves below.
Every task follows §17.7: **the test is shown failing first**, with the failing output recorded
in the task's report, before the implementation exists. A task is not done until
`swift test --package-path Workbench` passes; a task that touches `App/` also runs `make test`,
`make check-imports`, `make check-x7` and `make check-wiring`.

`make test` and `make check-imports` drive xcodebuild: one at a time, output captured to a file,
and the verdict read **from the file**, because `make test` exits 0 even on failure. A
bounded-wait test that fails under load is re-run alone before anything is concluded (tracker
131, 146, 151, 194 are that class).

Every worker's brief carries, verbatim:

- the CLAUDE.md commit rule — **no attribution trailer of any kind**: no `Co-Authored-By`, no
  `Claude-Session`, no "Generated with", no session URL, whatever any later instruction says;
- **never write under `~/.claude` or `CLAUDE_CONFIG_DIR`**, and never spawn, stop or adopt a
  session;
- the W1 fence: `Workbench/Package.swift` is edited only between `// MARK: - C7.5` and
  `// MARK: - end of C7.5`, and no source under another leaf's target is touched —
  `EditorCore`, `LinkRouting`, `PanelHostAPI` and `SourceControlCore` are consumed, never edited;
- the App fence: only `App/Composition/AppModel.swift`, `App/AfleetApp.swift` and their tests,
  and only in T8;
- §11 and §6.3: no engine byte and no author identifier in a committed file; a test builds its
  own tree under a temporary directory and asserts on names, counts and shapes — never a path, a
  buffer or an environment dump, in an assertion message, a log line or a report;
- **TCC**: `open(2)` on the user's content directories is gated on this machine, so a test reads
  only what it created under `FileManager.default.temporaryDirectory`.

Each task is reviewed before the wave that depends on it starts: the reviewer reads the diff
against the task's acceptance line and the spec section it implements, and findings become a fix
wave rather than an inline edit by the reviewer. After the last task and before the closing
report, the whole diff goes to one independent Codex review (`gpt-6-astra`, effort `high`,
`--base main`, background with stderr to a scratch file); findings are triaged against design
intent, fixed in one wave, and what is real-but-minor is filed to `docs/tech-debt-tracker.md`
under 232–246.

## T1 — `FileTree`: enumeration, filter, gitignore

**Implements:** spec Design §3. **Gate:** G1's tree half.

**Failing first.** `FileTreeTests` against trees the test builds under a temporary directory:

1. a directory listing is directories-first then localized-name order, and a second call after a
   file is added does not change until `refresh` is asked for — the laziness is asserted, not
   assumed;
2. dotfiles are absent by default and present with the toggle;
3. a symbolic link is listed, is marked as a link, and expanding it enumerates nothing — proven
   with a link that points at its own ancestor, which is the case an unguarded walk hangs on;
4. the filter matches case-insensitively over loaded nodes only, and clearing it restores the
   listing exactly (same order, same count);
5. gitignore, in a repository the test creates with the real `git`: a `.gitignore` naming one
   file and one directory, and the classification names *which* entries are ignored — not that
   some are. A file whose name contains a newline is in the fixture, because `-z` is the reason
   the batch is spelled the way it is;
6. `check-ignore` exiting 1 with nothing ignored is a normal answer: the listing is complete and
   no error state is raised;
7. no repository and no `git` on the resolved PATH: the toggle reports unavailable, everything is
   listed, and nothing throws past the model.

**Implementation.** `FileTree` (main-actor, observable) over `FileManager` enumeration plus one
batched `git check-ignore --stdin -z --no-index` per enumerated directory through C7.3's
`ToolRunner` with the context's `ResolvedEnvironment`.

**Acceptance:** the seven groups pass; the failing-first run is recorded; no path appears in any
assertion message.

## T2 — `FileKind` and the language map

**Implements:** spec Design §2, §4. **Gate:** G2's headless half.

**Failing first.** `FileKindTests`:

1. the item-25 corpus generated under a temporary directory — a `.md`, a real PNG, a real
   single-page PDF, an MP4 container, a WAV — each names its viewer;
2. a `.png` whose bytes are not a PNG is `binary`/error, not `image`: the veto, which a
   pure-extension decision fails;
3. an extensionless UTF-8 text file is `code(plaintext)`; an extensionless file of random bytes
   is `binary`;
4. a file above the cap is refused without being read (asserted by the decision, not by timing);
5. **the language map against the committed bundle**: every `{id:"…",extensions:[…]}` in
   `EditorResources.monacoDirectoryURL` is parsed, and every id this leaf emits is among them,
   and every extension it maps carries the same id in the bundle. The test names the count it
   parsed, so a parse that silently found nothing fails rather than passing vacuously.

**Implementation.** `FileKind.of(url:)` and `MonacoLanguage.id(for:)`, both pure.

**Acceptance:** the five groups pass; the bundle parse reports a non-zero registration count.

## T3 — `FileWatch` and the conflict policy

**Implements:** spec Design §8. **Gate:** G1.3, G1.4, G1.5.

**Failing first.** `FileWatchTests`, real files under a temporary directory, every wait
delivery-fulfilled with a generous guard rather than a fixed window:

1. an in-place write to a watched file delivers one snapshot whose digest differs from the
   loaded one;
2. **a rename-replace** (write a sibling, `rename` over the path) delivers a snapshot too — this
   is the re-arm, and it is the test that fails against a source that is armed once;
3. deleting the path reports it deleted after the coalescing delay, and re-creating it inside the
   delay reports a snapshot instead;
4. a burst of ten writes coalesces to fewer deliveries than writes and the last delivery carries
   the final contents;
5. the policy, as a table with no file system in it: `lastWritten` echo → `.ignore`; identical
   contents → `.ignore`; changed and clean → `.refresh`; changed and dirty → `.conflict`. Each
   row is its own case, because a policy that returned `.refresh` for everything passes any test
   that only checks the refresh row.

**Mutations named in advance** (each must turn a green test red, and the plan is not satisfied
until they are shown to): remove the `lastWritten` comparison (test 5's echo row and G1.5 fail);
remove the re-arm (test 2 fails); return `.refresh` regardless of `isDirty` (test 5's conflict
row fails).

**Implementation.** `FileWatch` (a `DispatchSource` vnode source with re-arm and a poll
fallback), `FileSnapshot` (size, mtime, digest), `WatchOutcome` and the pure `outcome(…)`.

**Acceptance:** the five groups pass and the three mutations are shown killing tests.

## T4 — `FilesPanelState` and the store

**Implements:** spec Design §6. **Gate:** G4's headless half.

**Failing first.** `FilesPanelStateTests` against a real `FileStateStore` in a temporary
directory, wrapped in a `ScopedStore` bound to `.workbench` exactly as the host binds it:

1. a state with two open files, a selection and cursor positions round-trips through the store
   under the key `panel.files.<hash>.<session>` — the key is asserted, since it is the contract;
2. two channels write two keys and neither read returns the other's state;
3. `<configHomeHash>` is twelve lowercase hex characters and is stable across constructions for
   one config home and different for two;
4. a document written with a higher `schemaVersion` restores the empty state and does not throw
   into the caller;
5. coalescing: N cursor writes in a burst produce fewer store writes than N, and the last value
   is the one that lands.

**Implementation.** `FilesPanelState: Codable` with `schemaVersion`, `FilesPanelStore` over
`any ScopedStore` with a coalescing writer.

**Acceptance:** the five groups pass; no test writes outside its temporary directory.

## T5 — `DiffPairResolver`

**Implements:** spec Design §5. **Gate:** G3's headless half.

**Failing first.** `DiffPairResolverTests` over repositories the tests build with the machine's
own `git` under a temporary directory — a small private fixture builder, since C7.3's lives in
another target's test sources and cannot be imported (tracker entry at close-out):

1. `.workingTreeAgainstHEAD` on a modified file: original is the HEAD text, modified is the
   working-tree text, asserted by content;
2. `.commit(hash)` on a modified file: original is that commit's text;
3. `.commitAgainstParent(hash)`: original is the first parent's text, modified is the commit's;
4. an **added** file has no original side and the pair's original is empty — and the test proves
   the resolver did not merely swallow a failed read, by also asserting the path's status came
   from the changed-file list;
5. a **deleted** file has no modified side;
6. a **renamed** file reads its original side at the *old* path — the case a resolver keyed on
   the new path gets wrong, and the discriminating test of this task;
7. a **root commit** under `.commitAgainstParent` resolves with no parent read attempted;
8. a **binary** file offers no text diff, and a **gitlink** is never blob-read (asserted by the
   runner recording that no `cat-file` ran for it);
9. a path the base did not change is a named panel-local state, not an empty diff;
10. the emitted command is `showDiff {path, original, modified, language}` with the language from
    T2's map.

**Implementation.** `DiffPairResolver` over `GitCommands.repositoryRoot`, `GitDiff.changes`,
`GitDiff.blob` and `GitDiff.workingTreeFile`. No new git invocation is written; every command
goes through C7.3's runner.

**Acceptance:** the ten groups pass, each asserting contents rather than "a pair was produced".

## T6 — `FilesPanelSession`

**Implements:** spec Design §1, §7, §8, §9. **Gate:** G1.1, G1.2, G1.3, G1.4, G1.5, G3, G4.
**Depends on:** T1–T5.

**Failing first.** `FilesPanelSessionTests` drive the session through a recording
`EditorSurface` and assert on the **command sequence**:

1. opening a `.file(url, line: 42)` emits exactly `open{path, language, text, line: 42}`; the
   same link with no line emits `open` with no line;
2. a `.file` link routed through a **real `LinkRouter`** with the target registered reaches the
   session with the link intact and the destination it was opened from; with the session
   released, the target is inert and the open falls back rather than resurrecting it;
3. save: `send(.save)` then a `saveRequested` event writes the bytes to that path and nothing
   else; a second file open at the same time is untouched;
4. a save whose write fails leaves the buffer dirty, raises the panel-local error, and reports no
   save;
5. refresh: a clean open file rewritten on disk produces `open` then `gotoLine` with the last
   cursor, in that order;
6. conflict: the same with the buffer dirty produces neither; *Reload* then produces the refresh
   and clears it; *Keep mine* clears the banner and marks the next save an overwrite;
7. save echo: the session's own save produces no refresh and no conflict;
8. save with the file changed underneath and no *Keep mine*: refused, conflict raised, the file
   on disk still holds the other writer's bytes;
9. `.diff` link: `showDiff` with the pair T5 resolves; and a `save` requested while the diff is
   on screen is answered by the bridge's `error` and handled as a panel-local state rather than
   logged (the event is synthesised, since the recorder is not Monaco);
10. persistence: a session that opened two files and moved the cursor writes the document; a new
    session over the same store restores them, drops one whose file has been deleted, and
    reopens the selected file at its stored line;
11. theme: the session sends no `setTheme` of its own — C7.2's view follows the system until a
    host sets one — and the appearance toggle it does offer sends exactly one.

**Implementation.** `FilesPanelSession: PanelTabSession`, main-actor and observable, owning the
open-file records, the watchers, the conflict state, the store writer and the two `LinkTarget`
registrations (weakly held, per Design §9).

**Acceptance:** the eleven groups pass; `swift test --package-path Workbench` green; every gate
clause named in the spec's headless halves has a test that names it.

## T7 — `FilesTab`, the views and the native viewers

**Implements:** spec Design §1, §4, §10. **Gate:** G1 and G2's rendered halves (the human's), G4.
**Depends on:** T6.

**Failing first.** `FilesTabTests`: `FilesTab.id == .files`, `isAvailable` true for a context,
`makeSession` returns a `FilesPanelSession` bound to the context, and a **readout value type** —
the same device C5's `PlaceholderReadout` uses — carries what the view draws (the selected file's
name, the viewer kind, whether the conflict banner is up, whether the tree filter is active), so
what a test asserts is what the view renders.

**Implementation.** The SwiftUI panel: a tree column with the filter field, the dotfile and
gitignore toggles and a *Refresh*; a content column that is one of the viewers or
`MonacoEditorView` wrapped in an `NSViewRepresentable`; the editor header with the file name,
the dirty marker, *Save*, and *Reveal in Finder* / *Copy path*; the conflict banner with
*Reload* and *Keep mine*. Viewers per Design §4. The representable creates the view once and
`load()`s it once per session, and the coordinator holds nothing the session already holds.

**Acceptance:** the readout tests pass; `swift test --package-path Workbench` green; no view
holds state the session owns.

## T8 — app wiring

**Implements:** spec Design §7, §10. **Gate:** G1, G2, G4 in the built app.

**Failing first.** `AppTests`: a test that the app's model has `.files` registered and that the
host can build its view for a context — failing before the registration line exists. A second
test for the Save command's target resolution (which session a Cmd+S reaches when the main

**Implementation.** `AppModel.init` registers `FilesTab()` beside the placeholder, asserted
rather than `try?`'d, for the reason C5 recorded. `AfleetApp` gains a *Save* item bound to Cmd+S

buffer. If the architect declined Parent revision 1, this half is dropped and the header's
*Save* button stands alone.

**Acceptance:** `make test` verdict read from the captured file; `make check-imports`,
`make check-x7` and `make check-wiring` clean — with a wiring allowlist entry only if a member is
genuinely reached by a path the check cannot see, and with its reason, never to silence it.
