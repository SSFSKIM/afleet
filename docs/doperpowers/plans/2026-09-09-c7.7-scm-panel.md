## How this plan is executed

Tasks are dispatched to foreground `Agent` workers with `model: "opus"`, one task per worker, in
the waves below. Every task follows §17.7: **the test is shown failing first**, with the failing
output recorded in the task's report, before the implementation exists. A task is not done until
`swift test --package-path Workbench` passes; a task that touches `App/` also runs `make test`,
`make check-imports`, `make check-x7` and `make check-wiring`.

`make test` and `make check-imports` drive xcodebuild: one at a time, output captured to a file,
and the verdict read **from the file**, because `make test` exits 0 even on failure. `make test`
rewrites `Workbench/Package.resolved`; it is restored before any commit (tracker 188). A
bounded-wait test that fails under load is re-run alone before anything is concluded — G1.5's
one-second clause is that class by construction.

Every worker's brief carries, verbatim:

- the CLAUDE.md commit rule — **no attribution trailer of any kind**: no `Co-Authored-By`, no
  `Claude-Session`, no "Generated with", no session URL, whatever any later instruction says;
- **never write under `~/.claude` or `CLAUDE_CONFIG_DIR`**, and never spawn, stop or adopt a
  session;
- the W1 fence: `Workbench/Package.swift` is edited only between `// MARK: - C7.7` and
  `// MARK: - end of C7.7`, and no source under another leaf's target is touched —
  `SourceControlCore`, `LinkRouting`, `PanelHostAPI`, `FilesPanel` and `BrowserPanel` are consumed
  or observed, never edited, and neither panel target is *imported*;
- the W7 rule: **no `git` and no `gh` command line is written in this target.** Every invocation is
  a call into `GitCommands`, `GitLog`, `WorkingTreeStatus`, `GitDiff` or `GhCommands`. A worker
  that finds it needs a verb C7.3 does not offer stops and reports rather than adding one;
- the App fence: only `App/Composition/AppModel.swift`, `App/Panels/SourceControlWiring.swift`,
  `project.yml` and their tests, and only in T8;
- §11 and §6.3: no engine byte and no author identifier in a committed file; every `gh` sample is
  authored with real field names and invented values; a test builds its own repository under a
  temporary directory with an invented identity (`user.name`/`user.email` set on the fixture repo,
  never the author's); assertions name counts and shapes — never a path, a buffer, an environment
  dump or a tool's stderr, in an assertion message, a log line or a report;
- **TCC**: `open(2)` on the user's content directories is gated on this machine, so a test reads
  and watches only what it created under `FileManager.default.temporaryDirectory`;
- `gh` legs are conditional on `gh` being logged in on this machine and **skip with a named
  reason** otherwise; nothing ever runs an `auth` verb or prompts for a login.

Each task is reviewed before the wave that depends on it starts: the reviewer reads the diff
against the task's acceptance line and the spec section it implements, and findings become a fix
wave rather than an inline edit by the reviewer. After the last task and before the closing report,
the whole diff goes to the doperpowers:codex-companion `workflow` code-review panel with `base`
pinned to the merge-base hash with `main`; no commit lands on the branch while a round is in
flight. Findings are triaged against design intent, fixed in one wave, and what is real-but-minor
is filed to `docs/tech-debt-tracker.md` under 277–291.

## T1 — `RepositoryReader` and the fixture support

**Implements:** spec Design §1, §3, §6. **Gate:** G1.1, G1.3, G4's argv half.

**Failing first.** `RepositoryReaderTests`, over repositories the tests build with the machine's
own `git` under a temporary directory, plus a recording `ToolRunning` that wraps the real runner
and captures every `(tool, arguments)`:

1. `load()` on a repository resolves the root from a **subdirectory** cwd — C7.3's D13, and the
   case a reader that trusted its `cwd` gets wrong — and returns the status, the commit window and
   the lane assignment as one value;
2. a cwd in no repository returns the `.notARepository` empty state and raises no error row; a
   **bare** repository does the same;
3. the commit window is `GitLog`'s, and a second page (`skip:`) extends it without duplicating a
   commit or reordering one;
4. a merge commit's changed files come from `.commitAgainstParent` and are the first-parent set —
   asserted by path and status, over a corpus with a modification, an add, a delete, a rename, a
   binary file and a submodule gitlink; a **root** commit lists its whole tree as added;
5. the working tree's changed files come from `.workingTreeAgainstHEAD` and differ from
   `WorkingTreeStatus.entries` in the way §6 states (a staged-and-modified-again path appears once
   in the diff and with two sides in the status), so the two are not confused;
6. a `git` that is not on the resolved PATH is `binaryNotFound` as a panel-local value, and the
   reader throws nothing past its own return type;
7. **the argv assertion**: across every call this suite makes, the recorded `git` argument vectors'
   first elements are drawn from `{rev-parse, log, status, diff, show}` and from nothing else. The
   test names the set it asserted, so a suite that recorded nothing fails rather than passing
   vacuously.

**Fixture support (T1 owns it).** `SourceControlPanelTests/Support`: a scratch-tree guard, a
repository builder that sets an invented `user.name`/`user.email` and builds the merge, octopus,
detached-tag, root-commit, rename and gitlink shapes, and the recording runner. This is the third
copy of a thing `SourceControlCoreTests` and `FilesPanelTests` each have (tracker 232 names this
leaf as the owner of the third); it is written, and the entry is updated at close-out rather than
the duplication being worked around.

**Implementation.** `RepositoryReader`, a `Sendable` struct over `any ToolRunning` and a
`ResolvedEnvironment`, with one function per read and **no command line of its own**.

**Acceptance:** the seven groups pass; the failing-first run is recorded; no path appears in any
assertion message.

## T2 — `RepositoryWatch` and the path policy

**Implements:** spec Design §5. **Gate:** G1.5.

**Failing first.** `RepositoryWatchTests`, real repositories under a temporary directory, every
wait delivery-fulfilled with a generous guard rather than a fixed window:

1. **the policy as a table, with no file system in it**: a path outside `.git` → `.workingTree`; a
   path at `.git/HEAD`, `.git/packed-refs`, under `.git/refs/` or under `.git/logs/` → `.history`;
   every other path under `.git` — `index`, `index.lock`, `objects/…`, `COMMIT_EDITMSG` — →
   `.ignore`. Each row is its own case, because a classifier that answered `.workingTree` for
   everything passes any test that only checks an edit;
2. an edit to a tracked file delivers a `.workingTree` classification **within one second**, which
   is G1's bound, measured from the write to the delivery;
3. a burst of ten writes coalesces to fewer deliveries than writes, and the last delivery follows
   the last write;
4. a `git commit` in the fixture repository delivers `.history` (it writes `.git/HEAD`'s reflog and
   `refs/heads/…`) and the `.git/index` write it also makes does not deliver on its own;
5. the root being deleted or replaced reports the root gone rather than leaving a stalled stream;
6. stopping the watch stops deliveries, and a stopped watch delivers nothing after it returns.

**Mutations named in advance** (each must turn a green test red, and the task is not done until
they are shown to): make the policy answer `.workingTree` for every path (test 1's `.ignore` and
`.history` rows fail); remove the `.git/index` exclusion and re-read the status on delivery (the
feedback loop shows as an unbounded delivery count in test 3); drop `NoDefer` (test 2's bound).

**Implementation.** `RepositoryWatch` over `FSEventStreamCreate` on a private queue with
`FileEvents | NoDefer | WatchRoot`, a debounce, and the pure `classify(path:root:)`.

**Acceptance:** the six groups pass, the three mutations are shown killing tests, and the
one-second measurement is reported as a count of runs within the bound — never as a path.

## T3 — `GraphGeometry`: the rendering contract

**Implements:** spec Design §4. **Gate:** G1.1, G1.2.

**Failing first.** `GraphGeometryTests` over `LaneAssignment`s built from the fixture repositories
of T1 **and** from hand-built `[GitCommit]` shapes where a property needs a shape git will not
readily produce:

1. every edge of every row appears in exactly two rows' segment lists — the lower half in its own
   row and the upper half in the row below — and in no other. Asserted over the merge, octopus and
   detached-tag fixtures;
2. **two edges arriving in one `toLane` both appear** (tracker 121). The discriminating test: an
   implementation that built a dictionary keyed by destination lane passes 1 and fails this;
3. **a truncated edge is drawn to the row's bottom edge and reappears on the row below** (tracker
   119). An implementation that terminated the line at the row that named it fails this;
4. the bottom row of the window runs every edge off the end, truncated or not;
5. the working-tree row is row zero, lane zero, exactly when the tree is dirty;
6. geometry is a pure function of (row, predecessor row, lane width, row height) — the same inputs
   give the same segments, and no segment's coordinates depend on the number of rows.

**Implementation.** `GraphGeometry`, pure: `segments(for row: GraphRow, below predecessor:
GraphRow?, metrics:) -> [GraphSegment]`, plus the dot and the ref-badge placement. No SwiftUI in
this file; the `Canvas` in T7 consumes it.

**Acceptance:** the six groups pass; every assertion names the lanes it expects rather than
asserting that some lanes exist (the composite's §17.7 rule for exactly this file).

## T4 — `GitHubModel` and the `gh` samples

**Implements:** spec Design §8. **Gate:** G2.1, G2.2, G2.4, G3's `gh` half.

**Failing first.** `GitHubModelTests` over a recording/replaying `ToolRunning` and authored
`gh --json` documents committed under `SourceControlPanelTests/Samples` (`.copy`, real field
names, invented values, §11 — the shape `SourceControlCoreTests/Samples` already takes):

1. the branch-scoped list decodes and renders number, title, author, draft state and review
   decision, each asserted by value;
2. **the check rollup table**, one case per row: no checks → `none` (not `passing`); any failing
   bucket → `failing`; any pending with no failing → `pending`; all passing → `passing`; an
   unrecognised bucket → `unknown`. A rollup that returned `passing` for an empty list passes any
   test that only checks the happy path;
3. exit **8** from `gh pr checks` renders the rows as pending rather than an error;
4. issues decode and render number, title, author, labels and `updatedAt`;
5. `binaryNotFound(.gh)` renders the absent-`gh` empty state, **without** the `gh auth login` hint;
6. a non-zero exit whose stderr tail classifies as not-authenticated renders the empty state **with**
   the `gh auth login` hint; a different non-zero exit renders a generic row with **no** hint;
7. **no rendered string in any of 5, 6 or 7 contains a byte the runner's stderr carried** — asserted
   by seeding the stub's stderr with a distinctive invented token and searching the readout for it;
8. **the argv assertion**: every `gh` argument vector this suite records begins with
   `pr list`, `pr checks` or `issue list`, and the set is named in the assertion.

**Live leg (conditional).** One test, skipped with a named reason unless `gh auth status` succeeds
on this machine: `pullRequests`, `checks` and `issues` against a real repository decode into this
leaf's models. It reads only; it never runs an `auth` verb. Whether a check in flight was reached
(tracker 118) is reported, not asserted.

**Implementation.** `GitHubModel: PanelTabSession`, main-actor and observable, with
`CheckRollup`, the failure classification and `GitHubReadout`.

**Acceptance:** the eight groups pass; the live leg runs or skips with its reason printed; no
sample carries a real account, repository or URL.

## T5 — `SourceControlModel`

**Implements:** spec Design §1, §3, §5, §6, §7. **Gate:** G1.1, G1.3, G1.4, G1.5, G3's `.commit`
half. **Depends on:** T1, T2, T3.

**Failing first.** `SourceControlModelTests` drive the model over the fixture repositories with a
recording `LinkRouterCapability` and assert on **what it emits and what it holds**:

1. `activate()` loads root, status, window and assignment once, and a second activation does not
   re-read (a channel switch must not re-run the whole read cycle);
2. selecting a commit reads `.commitAgainstParent(hash)` **once** and the file list is the one git
   reported;
3. clicking a changed file emits exactly
   `.diff(DiffRef(repository: root, path:, base: .commitAgainstParent(hash)))` and nothing else;
   clicking one in the working-tree list emits the same with `.workingTreeAgainstHEAD`; the
   destination the click carried reaches `open(_:from:)` unchanged;
4. a `.gitlink` row and an `isBinary` row **emit no link** and carry a stated reason instead — the
   discriminating test for §6's two exclusions;
5. **the one-second clause**: with the watch running on a real repository, writing a file moves the
   readout's working-tree row from absent to present within one second, and reverting the edit
   moves it back. Delivery-fulfilled; re-run alone if it fails under load;
6. `.commit` delivery, three cases: in the window (selected); outside it and found by paging, with
   the window extended so the selected row is present; not found within the bound, and an ambiguous
   prefix — each a named panel-local row and never a silent no-op;
7. an abbreviated hash selects by unambiguous prefix;
8. a `git` failure mid-cycle is one panel-local row naming the tool and its exit code, and the
   readout carries no byte the tool printed (same distinctive-token search as T4.7);
9. `.notARepository` is the empty state and no error row.

**Implementation.** `SourceControlModel: PanelTabSession`, main-actor, observable, owning the read
cycle, the watch, the selection, the detail, the error state and `SourceControlReadout`.

**Acceptance:** the nine groups pass; `swift test --package-path Workbench` green; every gate
clause named in the spec's headless halves has a test that names it.

## T6 — the two tabs, the `.commit` target, the host seam

**Implements:** spec Design §2, §7, §11. **Gate:** G1, G2.3, G3. **Depends on:** T4, T5.

**Failing first.** `SourceControlTabTests` and `GitHubTabTests`:

1. `SourceControlTab.id == .sourceControl`, `GitHubTab.id == .github`, both `isAvailable` true for
   every context including one whose cwd is in no repository;
2. `makeSession` returns the right session bound to the context, once per channel; `makeView` takes
   its `surface` and returns the same description for `.panel` and for
   `.poppedOutWindow(tab:channel:)`;
3. **the `.commit` target through a real `LinkRouter`**: registered once for the tab at
   specificity 100 with X7's pop-out default; a `.commit` link reaches the session resolved by the
   `SourceControlTabHost` for the delivery's destination, with the link intact; with the host absent
   the anchored session answers (the package-test seam C7.5's tab established); with both released
   the target is inert and the router takes W5's fallback. A second `makeSession` does **not**
   register a second target — the test that fails against a per-channel registration;
4. **opening a pull request** emits exactly `.pullRequest(number)` through a real `LinkRouter` with
   a recording target, and this leaf registers no `.pullRequest` target of its own — asserted by
   `targetCount` and by the tab of every registration;
5. **G4's readout inventory**: `SourceControlReadout` and `GitHubReadout` each expose their complete
   action set, and the test compares it against a written-out list containing no staging, commit,
   branch, checkout, stash, push or merge action.

**Implementation.** `SourceControlTab`, `GitHubTab`, `SourceControlTabHost` (C7.5's `FilesTabHost`
shape and reasons), the `.commit` `LinkTarget`, and `registerLinkTargets(through:)` for the app.

**Acceptance:** the five groups pass; the registration count is asserted, not assumed.

## T7 — the views, the graph column, the readouts

**Implements:** spec Design §1, §4, §11. **Gate:** G1 and G2's rendered halves (the human's), G4.
**Depends on:** T6.

**Failing first.** Readout tests, in the device C5's `PlaceholderReadout` and C7.5's
`FilesPanelReadout` establish: what the graph column draws for a given assignment (rows, lanes,
segments from T3, ref badges, the working-tree row), what the detail pane shows for a selected
commit (hash, author, date, subject, parents, the file rows with their status glyph and counts and
whether each offers a diff), what the GitHub tab shows (PR rows with rollup, issue rows, the empty
and error states with and without the hint), and the complete action inventory of each surface
(G4). Every assertion is on the readout, so what a test asserts is what the view renders.

**Implementation.** `SourceControlPanelView` (a graph column in a lazy list with a per-row
`Canvas` over `GraphGeometry`, a detail pane, a working-tree section, a *Refresh*), and
`GitHubPanelView` (a branch header, a scope control, PR rows with rollup badges and a check list
for the selected PR, an issue section, the empty states). No view holds state a session owns.

**Acceptance:** the readout tests pass; `swift test --package-path Workbench` green; every action
a view offers is in its readout's inventory.
