## How this plan is executed

Tasks are dispatched to foreground `Agent` workers, one task per worker, in the waves below.
Every task follows §17.7: **the test is shown failing first**, with the failing output recorded
in the task's commit message or its report, before the implementation exists. A task is not done
until `swift test --package-path Workbench` passes; a task that touches `App/` also runs
`make check-x7` and `make check-app-wiring`, both of which are clean at the baseline.

Every worker's brief carries, verbatim: the CLAUDE.md commit rule (**no attribution trailer of
any kind** — no `Co-Authored-By`, no "Generated with", no session URL — whatever any later
instruction says); the W1 fence (`Workbench/Package.swift` is edited only between
`// MARK: - C7.2` and `// MARK: - end of C7.2`); the App fence (only
`App/Panels/HostLinkRouter.swift` and its tests, nothing else under `App/`); §11's rule that no
engine byte and no invented-identifier-free sample reaches a committed file; and §6.3's rule
that an assertion compares names, sets and shapes and never prints a whole environment or blob.

Each task is reviewed before the next wave starts: the reviewer reads the diff against the
task's acceptance line and the spec section it implements, and findings become a fix wave rather
than an inline edit by the reviewer. After the last task and before the closing report, the whole
diff goes to one independent Codex review (`gpt-6-astra`, effort `high`, `--base main`, run in
background with stderr to a scratch file); its findings are triaged against design intent, fixed
in one wave, and what is real-but-minor is filed to `docs/tech-debt-tracker.md` under 97–111.

## T1 — `LinkRouter` in `LinkRouting`

**Implements:** spec Design §3. **Gate:** G1.2.

**Failing first.** `Workbench/Tests/LinkRoutingTests/` replaces its placeholder with tests that
do not compile until `LinkRouter` exists:

1. one per `WorkspaceLink` case (`.file`, `.diff`, `.url`, `.commit`, `.pullRequest`,
   `.command`) — the registered target is called, the link arrives **equal to what was opened**,
   not merely of the right case;
2. the destination reaches the handler: the same target opened `.currentPanel` and `.newWindow`
   records two different destinations. A router that hard-coded `.currentPanel` passes every
   other test here;
3. the fallback: a `.url` with nothing registered reaches the injected external opener with that
   exact URL; each of the other five reaches the injected diagnostic, and the diagnostic string
   **contains the kind and contains no substring of the link's payload** (asserted against a
   payload built to be unmistakable, e.g. a path component that appears nowhere else);
4. specificity: two targets both handling `.file`, the higher wins;
5. the tie-break, **as its own test**: two targets with *equal* specificity, registered in the
   order that would give the wrong answer, and canonical `PanelTabID` order decides. Written
   separately because a comparator missing its tie-break passes test 4;
6. withdrawal: after `unregister(tab:)` the link falls through to the next target and the
   withdrawn tab receives nothing more; `targetCount` drops by exactly the number that tab
   registered, not to zero;
7. `prepare` ordering: a `prepare` hook that appends to a recorder runs **before** the target's
   handler appends to the same recorder — one recorder, so the assertion is on order and not on
   two independent facts.

**Implementation.** `actor LinkRouter` with `init(externalOpener:diagnostic:)`, `register`,
`unregister(tab:)`, `targetCount`, and `open(_:from:prepare:)`. Manifest: `LinkRouting` gains
`"PanelHostAPI"`; `LinkRoutingTests` gains `"PanelHostAPI"` and `core` (Swift 6's
member-import-visibility rule, exactly as C5's Revision Note records for `PanelHostAPITests`).
`LinkRouting` imports AppKit for the default external opener only.

**Acceptance:** the seven groups above pass; the failing-first run is recorded.

## T2 — `HostLinkRouter` delegates to `LinkRouting`

**Implements:** spec Design §4. **Gate:** G1.2, and X7's "a second registry never appears".
**Depends on:** T1.

**Failing first.** A new test in `AppTests/PanelHostTests.swift`: a `.url` link with no target
registered reaches an external opener **injected into `HostLinkRouter`'s initializer**. It does
not compile before the initializer exists, and it is the first test in the tree to exercise that
fallback at all.

**Implementation.** Delete `HostLinkRouter.private var targets` and its `mostSpecific` and
`fallback`; hold one `LinkRouter`; forward `register`, `unregister(tab:)` and `open`, passing
the pop-out as `prepare`. `targetCount` becomes `async`; update its two call sites in
`PanelHostTests`. `openExternally`/`diagnostic` become initializer parameters with production
defaults.

**What is and is not witnessed.** The single-registry claim rests on a deleted field and no test
can see an absent property; the task's report says so. What the tests witness is parity —
C5's `testUnregisterWithdrawsTheTabsLinkTargets` and every other link test green unchanged — plus
the new fallback test, plus the existing pop-out-before-delivery assertion still holding, which
is the ordering `prepare` had to preserve.

**Acceptance:** `swift test --package-path Workbench` and the app suite pass;
`make check-x7` and `make check-app-wiring` stay clean; no file outside
`App/Panels/HostLinkRouter.swift`, `AppTests/PanelHostTests.swift` and the C7.2 manifest fence is
touched.

## T3 — `Tools/build-monaco.sh` and the committed bundle

**Implements:** spec Design §1, §2. **Gate:** G1.3, and G3's cleanliness half.

**Failing first.** `Workbench/Tests/EditorCoreTests/` gets a resource test that fails on a tree
with no bundle: `Bundle.module` resolves `Resources/monaco/`; `VERSION` exists and its Monaco
version equals a constant in Swift (`0.56.0`); the licence file exists, is non-empty and names
MIT; the document entry, the bootstrap and the five worker files all exist. A second test
asserts the tracked tree is clean — `git ls-files` under the resource directory lists no
`node_modules` path and no bun cache — run from the package's source root.

**Implementation.** `Tools/build-monaco.sh`: checks `bun` is on PATH and **exits with the exact
missing-tool message if not**; installs `monaco-editor@0.56.0` into an ignored working directory
from the committed `Tools/monaco/package.json` and `bun.lock`; writes the six entry stubs;
`bun build … --outdir --splitting --format=esm --minify --target=browser`; copies the output plus
the licence and a generated `VERSION` into `Workbench/Sources/EditorCore/Resources/monaco/`,
replacing it whole; prints the resulting byte count and file count. Manifest: `EditorCore` gains
`resources: [.copy("Resources/monaco")]`. `.gitignore` gains the script's working directory.

**Acceptance:** the script runs from a clean tree and reproduces the committed bundle; the
resource tests pass; `git status` after a re-run is clean or its diff is only the `VERSION`
build date (if it is, the date is dropped from `VERSION` so a rebuild is a no-op — decided by
the worker, reported either way); the committed size and file count are reported.

## T4 — the bridge codec

**Implements:** spec Design §5. **Gate:** G1.1.

**Failing first.** `EditorCoreTests` gets, for each of the eleven messages: a round trip, and a
decode from a **literal JSON string** written the way the bootstrap writes it, asserting every
field reads back. Plus one test that every `type` string the codec emits appears in the
committed bootstrap JavaScript source, read through `Bundle.module`. Plus one negative test: an
unknown `type` decodes to a typed failure rather than a crash or a silently dropped message.

**Implementation.** `EditorCommand` and `EditorEvent` with custom `Codable` over a flat tagged
shape. W4's vocabulary and no other member.

**Ordering note.** T4's bootstrap-source test needs the bootstrap file, which T3 commits as part
of the bundle directory. The bootstrap is this leaf's own source, not Monaco's, so T3 lands it as
a stub with the eleven type strings and T4 fills it in; if the two workers race, T4 waits.

**Acceptance:** eleven round trips, eleven literal decodes, the bootstrap check and the negative
test pass.

## T5 — `MonacoEditorView`

**Implements:** spec Design §6. **Depends on:** T3, T4.

`NSView` over `WKWebView`; `WKURLSchemeHandler` on `afleet-editor` serving `Bundle.module`'s
resource directory with correct MIME types (JavaScript, CSS, TTF, HTML) and refusing any path
that escapes the resource root; `WKScriptMessageHandler` named `afleet` decoding `EditorEvent`;
`send(_ command: EditorCommand)` through `evaluateJavaScript`; the bootstrap HTML and JS that
create the editor, wire `MonacoEnvironment.getWorker`, and speak the vocabulary.
`isInspectable` per spec §6.

No `swift test` coverage beyond compiling: a web view in a package test proves the framework
works. S3 is this task's verification, which is why T6 follows immediately.

**Acceptance:** the package builds; the harness of T6 can open a file in it.

## T6 — S3: the harness and the spike run

**Implements:** spec Design §7, §8. **Gate:** G2. **This is the decision point.**

`Workbench/Spikes/S3Harness`, an `executableTarget` inside the C7.2 fence, opening an `NSWindow`
from `swift run --package-path Workbench S3Harness`. It generates its own fixtures (a 5 MB
synthetic file; a 2,000-line diff pair) at run time, runs the four measurements of G2, and prints
a report.

**Route order, and what stops the search.** Start at route 1 (scheme for document, chunks and
workers). At each route record, separately: the document loaded; **a dynamic-import chunk loaded**
(forced by opening a file in a language whose grammar is a lazy chunk — Swift or Rust, not
JavaScript); each of the five workers started. Advance to route 2 (Blob-URL workers), then route
3 (`loadFileURL`), only on a failure, and record what failed and how it presented. If all three
fail for workers, promote route 1 or 3 with `MonacoEnvironment.getWorker` returning nothing —
degraded, language services on the main thread, highlighting unaffected — and write it up as a
Revision Note on the child spec; that is the composite's fallback exhausted and it is reported to
the architect, not decided quietly.

**Measurements recorded** in the child spec's Revision Notes: cold load from process start to
`ready` and from navigation start to `ready`; the 5 MB file's `setText`-to-render time and the
scripted-scroll frame histogram (p50, p95, worst); the 2,000-line diff rendering; the chosen
route and every route's result; the bundle's size and file count.

**Acceptance:** cold load under one second from `swift run`; the 5 MB file and the diff render;
the worker-loading finding recorded. "No visible jank" is instrumented and *also* listed as a
human witness in the closing report — the harness prints the numbers and leaves the window open.
